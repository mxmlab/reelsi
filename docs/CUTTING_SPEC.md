# Архитектура нарезки — полная спека (2026-08-10)

> Движок 1 «Нарезка»: из сырых камер — Premiere XML с вырезанной тишиной/дублями,
> сведённым мультикамом, черновиком mp4. Две ветки нарезки: **GigaAM-ветка**
> (`core/gigaam_cut/`, основная, пословные паузы и анализ) и **VAD-ветка**
> (`reelsi.py`, рез по громкости звука). Вход у обеих веток общий — через
> `core/omni_cut.py` и единый реестр ступеней `core/cutstages.py`. Кнопка «ИИ-нарезка»
> запускает стандартный GigaAM-пайплайн, модалка «Кастом» позволяет гибко
> включать/выключать ступени. Старый путь Omni/VAD (`omni_cut.py --mode old`)
> сохранён как CLI-only. Финал общий: `xmlbuild.build()` + сайдкары + (опц.) draft.
> Субтитры нарезка не делает ни в одной ветке (их строит шаг «Разметить всё» по готовому XML).

## Вход / выход

**Вход:** 1–4 файла камер (`.mp4/.mov/.mxf`), камера 1 — главная (звук всегда с неё).
**Выход** (в `outdir`, на каждый клип):
- `NN_stem.xml` — Premiere FCP7 xmeml (60fps таймлайн);
- `NN_stem.project.json` — как пересобрать XML (камеры, offsets, keep, память правок,
  `speaker`);
- `NN_stem.cuts.json` — что и почему вырезано (решения ИИ, ничего молча);
- `NN_stem.omni.json` — дословный Omni-транскрипт по интервалам (кэш, старый CLI-путь);
- `NN_stem.breaths.json` — спорные вздохи/«кхе» (P_MARK, см. GigaAM-путь);
- `NN_stem.draft.mp4` — черновой рендер 720p (вкл по умолчанию);
- `NN_stem.review.json` — замечания Omni-ревью (ЭКСПЕРИМЕНТ, выкл);
- `<outdir>/_tmp/` — временные файлы (прокси-карта, чистятся кнопкой 🧹 и перед новой нарезкой).

## Ступени нарезки — `core/cutstages.py` (единственный источник правды)

Архитектура нарезки управляется набором ступеней, определённых в `core/cutstages.py`
(`STAGES`). Фронтенд получает их список через роут `GET /api/cutstages` и динамически
строит панель модалки «Кастом» (своей копии списка фронт не держит).

### Таблица ступеней (`cutstages.STAGES`)

| Ключ (`key`) | Название (`label`) | Описание / `hint` | Дефолт (`default`) | Зависимости (`needs`) | Ветки (`branches`) | Панель кастома (`panel`) |
|---|---|---|---|---|---|---|
| `pauses` | Паузы | Вырезать паузы: по словам (`speech`), по энергии звука (`loud`) или отключить (`off`) | `"speech"` | `[]` | `gigaam`, `vad` | `True` |
| `asr` | Распознавание речи | Распознавание слов через ASR. Включается автоматически при необходимости | `True` | `[]` | `gigaam`, `vad` | `True` (только чтение/индикатор) |
| `sense` | Смысл (ИИ) | ИИ-разметка смысловых кусков и удаление неудачных дублей через LLM | `True` | `["asr"]` | `gigaam` | `True` |
| `dedupe` | Чистка дублей | Автоматическое удаление повторов и оговорок кодом | `True` | `["asr"]` | `gigaam`, `vad` | `True` |
| `refine` | Подгон резов | Точная подгонка точек реза по огибающей звука и границам слов | `True` | `[]` | `gigaam` | `True` |
| `breath` | Вздохи | Детекция и вырезание вздохов перед фразами | `True` | `["asr"]` | `gigaam` | `True` |
| `draft` | Черновик mp4 | Рендер быстрого чернового видео `.draft.mp4` для предпросмотра | `False` | `[]` | `gigaam`, `vad` | `False` (галка `chk_draft` в карточке) |

### Нормализация и правила выбора ветки (`cutstages.normalize`)

- **Ветка выбирается положением ступени «Паузы» (`pauses`):**
  - `pauses == "loud"` → ветка **`vad`** (`reelsi.py`, рез по громкости звука);
  - `pauses == "speech"` или `"off"` → ветка **`gigaam`** (`core/gigaam_cut/`, пословный анализ).
- **Ступень `asr` вычисляется автоматически:**
  - Включается (`asr = True`), если `pauses == "speech"` или включена любая активная ступень, требующая слов (`needs: ["asr"]` — `sense`, `dedupe`, `breath`).
  - Руками в интерфейсе не задаётся.
- **Ступени, недоступные в выбранной ветке**, автоматически гасятся при нормализации.
- Для ветки `vad` функция `cutstages.to_reelsi_opts(stages, thresholds)` формирует словарь опций `opts` для `reelsi.py` на основе `DEFAULT_THRESHOLDS` (`model`, `scale`, `vad_thresh`, `min_silence`, `pad`, `cam_return`), жёстко устанавливая `subs: False` и `srt: False`. Whisper в `reelsi.py` загружается только при `dedupe: True`.

## Общие ступени (все пути)

### 1. Аудио + синхрон камер — `core/sync.py`
- `extract_audio`: ffmpeg → mono 16 кГц pcm wav (без декода видео, быстро).
  Wav-темпы — в `mkdtemp`, удаляются по завершении (reelsi: try/finally; omni_cut: atexit;
  при «Стоп» каталог чистит `_kill_curproc` по маркеру `WORK_DIR`).
- `find_offset(wavA, wavB)`: RMS-огибающие (~100 Гц) → кросс-корреляция (FFT) →
  лаг в секундах + уверенность 0..1 (острота пика против медианы).
  `offsets[k]` = на сколько камера k отстаёт от камеры 1; время камеры k = t_cam1 − offset_k.
- `video_envelope` — огибающая ВИДЕО (яркость) для `/api/cammatch` (см. «Пост-нарезка»).

### 2. Детект речи — `core/vad.py` (только ветка VAD и старый CLI-путь)
Энергетический VAD: RMS по кадрам 25мс/шаг 10мс → dB; шумовой пол = 20-й перцентиль;
речь = пол + `thresh_db` (деф. 18). Затем: слияние пауз < `min_silence` (0.30с),
отброс кусков < `min_speech` (0.20с), паддинг `pad` (0.08с) с пере-слиянием перекрытий.
**Границы интервалов = тишина** — резы по ним почти не режут слова.
GigaAM-ветка VAD не использует: тишина режется по пословным таймингам CTC (см. ниже).

## Ветка 1: GigaAM whole-file — `core/gigaam_cut/` (основная, пословная)

Пакет (распилен из монолита 2026-08-06): `tune` — пороги; `takes` — дубли и пост-проход;
`asr` — транскрипция/выравнивание; `decide` — промпты решения; `pipeline` — оркестратор
`run()`. Выбирается по умолчанию и при `pauses: "speech"` или `pauses: "off"`. Движок ASR
берётся из `active_cut_asr` (дефолт `gigaam`, только движки с флагом `cut: True`).

Порядок шагов `gigaam_cut.pipeline.run()` с учётом ступеней (`stages`):

1. **ASR (GigaAM/CTC) целиком по файлу** (`asr.transcribe_words_for_cut`, отдельный процесс,
   ~7.5 ГБ VRAM, выходит — память свободна): слова с РОДНЫМИ пословными таймингами
   (`word_timestamps=True` — текст и тайминги из одной модели, wav2vec2/forced-align
   НЕ используется). Слушаем окнами ~18с (`win=18, search=6`) со швом в самой тихой
   точке последних секунд окна.
2. **Паузы / тишина** (`tune.SILENCE_SEC` = 0.8с): если ступень `pauses != "off"`, паузы
   между словами дольше порога — жёсткие границы реза, вырезаются ВСЕГДА автоматически
   (аналог VAD), `silence_bounds`. При `pauses: "off"` тишина не вырезается (`silence_bounds = []`).
3. **27b решает ДОСЛОВНО** (`decide.decide_markup`, LM Studio; режим **`markup`**):
   - Если ступень **`sense: True`** (включена): модель получает ВЕСЬ пословный текст и расставляет
     скобки `[ ]` вокруг того, что выкинуть. Выравнивание скобок на наши слова — difflib;
     что модель переписала/пропустила — ОСТАЁТСЯ (молча резать нельзя), покрытие в логе.
   - Если ступень **`sense: False`** (выключена): шаг решения пропускается, все слова считаются оставленными (`kept = set(range(len(words)))`, `drop = set()`).
4. **Пост-проход кодом** (`takes.postprocess`):
   - Если ступень **`dedupe: True`** (по умолчанию): чистка фальстартов (`find_takes` — начало сегмента повторяет недавнее, окно `TAKE_WIN` = 12с; перечисления не трогаем — `align.is_enumeration`), выбор последнего чистого захода (`force_takes`), защита уникальной связной речи (`veto_unique_drops`), склейка коротких осколков (`heal_fragments`), чистка остатков (`dedupe_repeats`/`dedupe_fragments`/`drop_truncated`), отброс микро-островков (`drop_micro_keeps`), возврат первых половин перечислений (`keep_parallel_runs`).
   - Если ступень **`dedupe: False`**: механическая чистка дублей отключается.
5. **Сборка keep** + условный санитарный гард:
   - Если ступень **`sense: True`**, проверяется гард: если осталось <25% исходной речи или keep пуст — `SystemExit` «ИИ вырезал почти весь ролик», прошлый XML не перезаписывается.
   - При выключенном `sense` гард пропускается.
6. **Раскладка камер ДО подгона**: `align.assign_cameras(keep, N)` по СМЫСЛОВЫМ кускам (см. ниже).
7. **Подгон резов по звуку** (`tune.refine_keep`, по самому wav):
   - Если ступень **`refine: True`**: точные границы по огибающей звука (`EDGE_IN_MAX`=0.15 / `EDGE_OUT_MAX`=0.35, тихая атака `ATTACK_MAX`=0.15, дыры без речи `HOLE_MIN`=0.15 режутся). Наследует камеры через `parents`.
   - Если ступень **`refine: False`**: подгон пропускается.
8. **Вздохи и «кхе»** (`core/breath.py`):
   - Если ступень **`breath: True`**: Silero VAD + CED-tiny + акустика → градиентный бустинг (`data/breath_model.json`). `P_CUT`=0.95 — режем сами (в `cutlog`, source «вздох»), `P_MARK`=0.5 — метим в `<stem>.breaths.json`. Порог у спикера свой (`breath_p_cut` в профиле).
   - Если ступень **`breath: False`**: детекция вздохов пропускается.
   - **Условный зеркальный санитарный гард:** речь > 30с одним куском — отказ. Проверяется ТОЛЬКО если включён `refine` или `breath` (признак того, что подгон по звуку не разделил слитную речь).
9. **XML** — `xmlbuild.build` + сайдкары `.project.json` и `.cuts.json`. Пишутся ВНУТРИ пайплайна, сразу после XML и ДО чернового рендера. **Субтитры нарезка не делает** (их строит шаг «Разметить всё» по роуту `/api/gen_subs`).
10. **Черновик** — если ступень **`draft: True`**: `draftrender.render_draft(out)`. При `draft: False` рендер черновика пропускается. В конце — `draftrender.clean_tmp(outdir)`.

## Ветка 2: VAD-нарезка — `reelsi.py` (рез по громкости звука)

Выбирается положением ступени **`pauses: "loud"`**. Запускает классический движок `reelsi.py`,
опции которого формируются функцией `cutstages.to_reelsi_opts(stages, thresholds)`:
`subs: False` и `srt: False` выставляются всегда, `dedup` берётся из ступени `dedupe`.

Порядок шагов:
1. `core/sync.py` — извлечение аудио и синхронизация камер.
2. `core/vad.py` — энергетический VAD: вырезка тишины по RMS-порогу (`vad_thresh` = 18 дБ, `min_silence` = 0.30с, `pad` = 0.08с). При `pauses: "off"` нарезка не выполняется (`no_cut: True`).
3. **Whisper** (`core/transcribe.py`): поднимается **только при `dedupe: True`** (для поиска повторов фраз). Если `dedupe: False` и `subs: False`, Whisper не импортируется вовсе, и нарезка проходит мгновенно на CPU без использования VRAM.
4. **Дедуп**: `align.find_repeat_ranges` (точные повторы фраз, keep=last).
5. **Сборка XML**: `xmlbuild.build` + раскладка камер + сайдкары.

## Старый CLI-путь: Omni/VAD — `omni_cut.py --mode old` (legacy)

Сохранён для истории и доступен только из консоли (`omni_cut.py --mode old`).
Порядок шагов:
1. `sync + VAD` → `intervals` — кандидаты-интервалы речи.
2. `core/omni_asr.py` в сабпроцессе (~7.5 ГБ VRAM): поинтервальная транскрипция через Qwen/GigaAM.
3. `core/ssm.py` (CPU): акустический поиск повторов внутри интервалов.
4. Чтение памяти правок (`user_overrides` из `.project.json`).
5. `decide()` через LLM (LM Studio) с prompt-подсказками и пост-гардами.
6. `keep = intervals − drop` + SSM-резка внутри оставленного.
7. Self-check стыков (`selfcheck.check_and_fix`).
8. Раскладка камер, сборка XML, сайдкары и опциональный черновик.

## ASR-реестр — `core/asr_backends.py` (кто слушает звук)

Единый реестр движков: `engines()` (id, язык, даёт ли вероятность, флаги применимости `subs`, `selfcheck`, `cut`) + `transcribe_words(wav, engine=…)`. Отдаётся в UI через `/api/asr_engines`.

### Флаг `cut` (годность под нарезку)

Для нарезки (`active_cut_asr` в `ai_config.json`, вкладка ⚙ → «Нарезка») требуются движки, отдающие **точные акустические границы звучания каждого слова**:
- **`cut: True`** (годен под рез):
  - `gigaam` (GigaAM-v3 CTC, русский язык) — родные границы CTC;
  - `gigaam:multilingual_large_ctc` (GigaAM multilingual CTC, 70+ языков);
  - пользовательские CTC-модели из `data/asr_engines.json` (`kind: "ctc"`).
- **`cut: False`** (не допущен к нарезке):
  - `gigaam:v3_rnnt` и `gigaam:v3_e2e_rnnt` — RNN-T-головы выдают кадр эмиссии токена, а не физические границы звучания слова;
  - `whisper:*` и `whisper.cpp:*` — границы слов приближённые/грубые;
  - `omni` — тайминги слов строятся интерполяцией фразы.

GigaAM/Omni/CTC бегают ОТДЕЛЬНЫМИ процессами (сабпроцесс `core/gigaam_subs.py` и т.п.) —
CUDA OOM / нативный краш не убивает Flask, VRAM изолируется.

## Раскладка камер — `align.assign_cameras(keep, N, return_every=2, big_chunk_sec=6)`

- Камера 1 — база: монтаж начинается с неё; **большой кусок ≥6с — всегда камера 1**
  (единственное исключение из чередования, может идти кам1→кам1).
- Прочие каты: наименее использованная камера 2..N, не равная предыдущей;
  после `return_every` не-кам1 катов — возврат на кам1.
- **Жёсткий инвариант: соседние сегменты — разные камеры** (кроме big-chunk-исключения).
  На 2 камерах это даёт строгое 1-2-1-2.
- Перед большим куском камера «уступает» кам1, только если есть куда шагнуть (N≥3).
- В GigaAM-пути assign считается ДО `refine_keep` (по смысловым кускам) и наследуется
  подкусками через `parents` — иначе камера прыгала бы на вдохе посреди фразы.
- Редактор может сохранить ручную раскладку (`project.json["assign"]`); правка блоков
  в редакторе сбрасывает её (`assign` удаляется — пересчёт).
- **Автоподбор по звуку** (`/api/cammatch`): `/api/cammatch` матчит дубли-файлы камер
  2..N по огибающим (`sync.video_envelope`, порог `sync.MATCH_MIN`) — кнопки «Подбор по
  звуку» / «Подбор всех по звуку» на шаге 1.

## Сборка XML — `xmlbuild.build(cams, segments, offsets, out, assign, …)`

- Таймлайн 60fps; кадры = `round(sec*60)`; `pproTicks = frame*4233600000`.
- На КАЖДЫЙ keep-сегмент — clipitem на КАЖДОЙ видеодорожке камер (V1=кам1 снизу…):
  кам1 всегда `enabled=TRUE` (база), камера k>0 — TRUE только где `assign==k`
  (верхняя включённая дорожка побеждает при показе).
- Время источника камеры k: `in_k = round((s − offsets[k]) * 60)`.
- Аудио: по дорожке на камеру (все клипы, гейн статический); звук в AE потом
  берётся только с кам1. Опц. музыка двумя моно-дорожками L/R с гейном из dB.
- Субтитры-графика (только классика/gen_subs): трек 3, FlatBuffer-блобы из эталона
  (`subs.SubtitleBuilder`, шаблон `data/sub_template.xml`/`data/refblobs.json`), автоскейл длинных
  слов (`SUB_FIT_CHARS=14`), цензура (`core/censor.py`: звёздочка средней буквы по
  `data/badwords.txt`/`data/okwords.txt`; списки правятся в ⚙ → «Слова», своя копия ложится
  в `*.user.txt`).
- Имена файлов экранируются (`saxutils.escape`); ffprobe мемоизирован по (path, mtime).

## Черновой рендер — `core/draftrender.py`

`render_draft(xml, …)` через **карту 720p-прокси камер** (не рендер сегментов из
исходников): прокси `pv_*.mp4` строятся один раз на камеру (NVDEC + `scale_cuda`,
кэш в `<outdir>/_tmp/` — `build_preview_proxy`, тот же путь, что у предпросмотра;
4K-исходник декодируется 3.8с вместо 60с), затем сегменты режутся уже из прокси.
- Кодеки по платформе (`hw_encoder`): Windows/Linux — `h264_nvenc` → фолбэк `h264_amf`
  (AMD) → `h264_qsv` (Intel) → CPU x264; macOS — `h264_videotoolbox`. NVENC может не
  влезть рядом с LLM — автофолбэк по платформе, `--cpu`/`--no-proxy` принудительно.
- Слова — `.ass` (cwd=_tmp, чтобы не экранировать пути Windows); аудио — атrim + afade.
- Ручной перерендер: `/api/draft_render` (фоновый JOB). Кнопки в интерфейсе нет —
  черновик включается галкой при нарезке; роут остался для ручного вызова.
- `clean_tmp(outdir)` — уборка `_tmp` (прокси сохраняются по умолчанию).

## Пост-нарезка: редактор и предпросмотр (webui, без пере-прогона ИИ)

- **Предпросмотр (PV)**: `/api/aicut_preview` → virtual_edl → браузер играет ПРЯМО из
  исходников камер (`<video>` + Range-стриминг), переключая слои по сегментам; звук —
  всегда видео кам1; субтитры оверлеем. Рендера не требует. (В редакторе нарезки
  превью — только камера 1: перебивки 2-й камеры нужны лишь в предпросмотрах шага 2.)
- **Редактор нарезки (ED)**: волна всего исходника (`/api/waveform` → кэш
  `*.peaks<pps>.json`), keep-блоки (зелёное) + вырезанное (серое) + cut-log маркерами +
  оранжевые полоски вздохов из `.breaths.json` (клик вырезает); ручки краёв, undo.
  Сохранение → `/api/editor_save`: пересборка XML из блоков + **запись памяти правок**:
  restored/deleted диапазоны (>0.3с, с текстом из транскрипта) → `user_overrides`
  (до 50, дедуп) — их прочитает следующий прогон старого пути (шаги 4-5 пути B;
  GigaAM-путь пока не читает).
- **Смена/раскладка камер**: `/api/cams_load`/`cams_save` (assign по сегментам),
  `/api/swap_cam` (пересинхрон при замене файла камеры).
- **Субтитры с нуля**: `/api/gen_subs` — склейка keep-аудио → движок из `/api/asr_engines`
  → субтитры-графика в готовый XML (это шаг «Разметки», но использует тот же project.json).

## Память правок (полный цикл)

| Что правит юзер | Где копится | Кто читает |
|---|---|---|
| вернул/удалил куски в редакторе | `.project.json → user_overrides` (restored/deleted, t0/t1/text) | старый Omni-путь при пере-нарезке: LLM-промпт «не выкидывай похожее» + жёсткая защита restored от drop (GigaAM-путь пока не читает) |
| удалил ИИ-карточку вставки | `clip.ins_rejected` в localStorage (до 30) | все вызовы `/api/ai_inserts` → `cmd_inserts(rejected=…)`: промпт + жёсткий фильтр похожих (тип, старт ±2с, слова query ≥60%) |
| правки нарезки руками | разница `project.json` новее `cuts.json` | `tools/train_breath.py` — обучает детектор вздохов на этой разметке |

## Профили спикеров (`core/speakers.py`, `speakers/*.json`)

Пороги `gigaam_cut.tune` — не универсальные константы, а калибровка по спикеру A
(у него речь 39.5 дБ над шумом комнаты, у спикера C — 28.8 дБ, разброс 14 дБ;
жёсткий `ONSET_DB=20` проходит ВЫШЕ медианы его речи — отсюда профили).
Профиль = JSON в `speakers/` (gitignored): папка результата, пресет AE, оверрайды
порогов, поправка к промпту (`hint`). Селектор «Спикер» на шаге 1 → `--speaker` →
`apply_speaker` пишет пороги в globals `tune` (потому пороги читают через модуль
`gigaam_cut.tune.X`, не `from .tune import X` — связанное по имени значение
проигнорировало бы профиль молча).

## Хореография VRAM (16 ГБ, одна тяжёлая модель за раз)

```
LM Studio (27b) ──unload_ours─▶ GigaAM v3-CTC (subprocess ~7.5ГБ, вышел=освободил)
      ▲                               │
      └── decide (27b снова) ◀────────┘
             │ unload_ours
             ▼
      Whisper/CTC (self-check, путь B) ── release_model
             ▼
      NVENC draft (~1ГБ; фолбэк AMF/QSV/x264)
             ▼ (опц., выкл)
      Omni-ревью (7.5ГБ, subprocess)
```
Правило: каждый новый GPU-шаг — через существующий своп-паттерн
(`aicut.unload_ours` / `transcribe.release_model` / subprocess как gigaam_subs).
Breath/SSM — CPU, VRAM не трогают. Roto/модели шага 3 — по тем же правилам.

## Управление и отмена

- UI: webui шаг 1; очередь пар (`QUEUE`), папки камер, per-clip ncams; кнопка «ИИ-нарезка» (GigaAM по умолчанию), кнопка «Кастом» (модалка ступеней `/api/cutstages`), чекбокс «черновик mp4» (`chk_draft`, вкл по умолчанию).
- Параметры нарезки: активный ASR-движок нарезки `active_cut_asr` (вкладка ⚙ → «Нарезка», только движки с `cut: True`), «Спикер» (`speakers/*.json`), ступени нарезки `stages` (`core/cutstages.py`).
- Джоб: `/api/omnicut_run` (ИИ-нарезка) и `/api/run` (кастомная нарезка по ступеням) → глобальный JOB/LOCK (один слот). Лог стримится инкрементально (`/api/status?since=N`, кэп 4000 строк).
- «Стоп»: `/api/cancel` — `taskkill /F /T` дерева subprocess (omni_asr/gigaam не
  сиротеют; каталог `gigaamcut_*` чистится по маркеру `WORK_DIR`), `aicut.CANCEL` рвёт
  ретраи, LM Studio выгружается; выполняется всегда (и для разметки без JOB).
- Таймауты: ffmpeg — `FFMPEG_TIMEOUT` в draftrender; Omni/GigaAM-сабпроцессы — свои
  (GigaAM-субтитры 30 мин), висящий стрим провайдера обрывается сам.
- Атомарная запись сайдкаров — `core/fileio.py` (правки не теряются при Стоп).
- Параметры VAD/пороги: `DEFAULT_THRESHOLDS` в `core/cutstages.py` (`model`, `scale`, `vad_thresh`, `min_silence`, `pad`, `cam_return`).

## Известные ограничения / точки роста

- Классический путь не гоняет self-check/draft автоматически (только ИИ-пути; вручную — 🎞).
- GigaAM-путь: самопроверка выключена (родные тайминги CTC точны; петля переслушивания
  выпилена 2026-08-10 — на практике делала хуже); `user_overrides` (память правок
  редактора) пока читает только старый путь.
- `--refine` (forced-align wav2vec2 внутри фраз, путь B) выключен — режет окончания
  на ослышках ASR. В GigaAM-пути подгон по звуку — `refine_keep` (шаг 7 пути A).
- Старый путь: тайминги решений — интервалы VAD; рез внутри слитной речи без паузы
  невозможен (SSM частично закрывает).
- Кэш `.omni.json` валидируется только числом интервалов — смена `vad_thresh`/`pad`
  с тем же числом интервалов реюзнет старые тексты (редко, но возможно).
- RNN-T-головы GigaAM в самопроверку не пускаем (эмиссия токена, а не граница звука);
  для субтитров их слова раздвигаются `_widen` (короткие по 0.04с — вспышка).
