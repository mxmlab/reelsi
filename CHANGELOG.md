## Unreleased

### Fixed
- **The Windows CI suite is green again: 8.3 short paths, the ffmpeg filter-graph option and a bare message template**: three failures on a Windows runner, none of them visible on the owner's machine. (1) `tempfile.gettempdir()` returns the short 8.3 form there (`C:\Users\RUNNER~1\AppData\Local\Temp`) while a test's own directory arrives in the long one (`C:\Users\runneradmin\…`), and `os.path.commonpath` over that pair answers `C:\Users` — so the guard that swaps real VST3 folders for empty temporary ones discarded the test's own folder and the plugin list came out empty. Every path comparison now goes through one helper, `core.paths.real` (realpath + abspath), on **both** sides: the guard in `tests/conftest.py` and `tests/test_voicefx_proc.py`, and a regression test creates a directory, takes its 8.3 form with `GetShortPathNameW` and checks that its plugin survives. (2) The audio mix passed the filter graph as `-filter_complex_script`, an option ffmpeg 7.1 renamed to `-/filter_complex`: the name is now chosen from `ffmpeg -version` (cached per process, `encoders.filter_graph_args`), the new one from 7.1 up and the old one below, `None` (an unknown version) keeping the old, most compatible form — used by the mix and by the draft renderer alike. (3) `UMsg.__str__` and `ReelsiError.text` returned the **template** (`«Звук не собрался (код {code}): {err}»`), so every log line, CLI message and HTTP answer showed placeholders instead of the reason; the Russian text is now substituted at creation (`core.umsg.format_text`, which falls back to the template when a variable is missing or the template is malformed), while `msg`/`vars`/`code` stay as they were for the front end's translation and `umsg_err` submits the substituted text.

- **The dependency audit is green again, and what it found is excluded by name instead of switched off**: `pip-audit` in CI's `scan` job failed on `transformers` 4.57.6 — eleven advisories, six unique IDs, all of them about loading **untrusted** models, configs and code. Moving to 5.x is not possible yet: at import transformers 5.x calls `torch.accelerator` in its own device-type probe, which appeared only in torch 2.6, while `install.ps1`, `install.sh` and both READMEs install torch 2.5.1 — with it every `Auto*` import dies, so `core/breath.py`, `core/falign.py`, `core/ctc_asr.py` and `core/omni_asr.py` break at once; the torch floor is a separate change and stays out of this one, so `requirements.txt` keeps `transformers>=4.46,<5` with the reason written next to it. Each ID is excluded one by one with its own comment in `.github/workflows/ci.yml`, naming the code path that runs it and why this tree never reaches it: X-CLIP checkpoint conversion (no release converts checkpoints), `Trainer._load_rng_state` (no `Trainer`; the breath detector trains with sklearn), `AutoModelForCausalLM.from_pretrained` with a crafted `config.json` (never called; model ids are fixed), the LightGlue `trust_remote_code` override (no LightGlue and no `AutoModel.from_pretrained`), the `save_pretrained` chat-template path traversal (`save_pretrained` is never called) and `load_custom_generate` (no `custom_generate` is ever passed to `generate()`). **`tools/slice_check.py` now runs the same audit** — the arguments, exceptions included, are read from the `scan` job's line in `ci.yml` rather than copied, so a green slice can no longer hide a red CI; no `pip-audit` installed or no network gives a loud `НЕ ПРОГОНЯЛСЯ` with the reason. `tests/test_ci_scan.py` keeps the exception list closed and pins it to the slice step.

## 0.3.1-beta — 2026-10-07

### Highlights
- **Preview sound is the camera's own track, and the processed voice keeps up with the picture**: with plug-ins on, the voice no longer lags behind the frame on narrow cuts and no longer plays the previous clip's voice, while the camera plays its own audio; Firefox now says in the player why the source audio is silent, and a Chromium-based browser is recommended for the preview.
- **A processed voice is never lost between the preview and the project**: the final voice of a clip is a versioned file named by its sidecar, so a build can no longer ship the camera audio because the file was held open, and a failed take is visible instead of one log line.
- **Work on a clip is kept on disk, and a deleted clip goes to a recycle bin**: speaker, camera setup, inserts, style and intro of every clip are stored next to its XML and come back on load or rescan, while a deleted clip is moved to `_reelsi_trash/` with a full restore.
- **Step 2 "Markup all" is a pipeline**: subtitles run one after another on the GPU, while the cloud steps (yellow highlights and inserts) start per clip as soon as its own subtitles are ready, and the local models run phase by phase.
- **Inserts that share one file keep their identity, and every insert edit can be undone in steps**: each card has a stable id, and the insert state of a clip keeps 100 undo and redo steps on `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y`.
- **The preview shadows are After Effects shadows, taken from a measurement**: one Drop Shadow translation (Opacity, Direction, Distance, Softness) is shared by the built project and the preview for subtitles, photo inserts, the subtitle background and the intro precomp.
- **A fresh installation no longer breaks subtitles, and what the build downloads is safer**: camera audio is read through ffmpeg instead of the fallback librosa has dropped, and stock ids, download addresses, custom profile headers and the XML export route are hardened.
- **Every operation takes the speaker from the CLIP, not from the step-1 selector, and a two-speaker test keeps it that way**: the insert quota, the stock, insert-library, image and video requests, the markup pipeline, the `.jsx` and render folders, the LUT, the camera frame and the voice profile all read the tag through one door (`clipSpeaker(c)`), so a clip of speaker B no longer gets speaker A's quota; `tests/test_two_speakers.py` walks every speaker-dependent feature.
- **The work state lives on the server, and an out-of-date tab cannot overwrite it**: `ui_state.json` carries a revision, a save whose `base_rev` disagrees writes nothing and answers `stale_state`, and the stale tab shows a permanent banner with a Refresh button instead of rolling back clips work.

### New
- **The disclaimer shows in the preview exactly as in After Effects, with scale and position knobs**: the disclaimer used to exist only in the built `.jsx` — the browser preview drew no layer at all, so it could not be seen or adjusted, and its position was hard-coded (`int(H·0.764)`). Three style keys now live in the **Disclaimer → Transform** group: **Scale, %** (a multiplier of the size already fitted to the frame width, so a narrow font does not inflate it), **Position by height, % of frame** (the baseline of the first line, exactly like the Position of a text layer in AE; 76.4 % is the old number) and **Horizontal shift, px** (from the centre of the frame). `plan_decor` computes the numbers once, and both the `.jsx` substitutions (`DISC_SIZE`/`DISC_Y`/`DISC_X`) and the preview layer `#ipvdisc` take them from there: the same lines, font, size, line step, position and the same opacity fade (100 until the end of the show minus 0.35 s, then linear to zero), plus the glow as a white text-shadow of the same radius. The tail copy gets its own window from the plan. Defaults keep the built `.jsx` byte-for-byte as before (`DISC_X` is not declared at all when the shift is zero).
- **Music lives in the style, with a per-clip override, a visible random track and an "Another track" button**: a clip's music used to come from three shared step-3 fields (`musicmode`/`aemusic`/`aemusicdir`), so every clip of every speaker played from the same folder, and a random track was picked at build time and never shown. The style now carries `music_mode` (`off`/`random`/`file`/`url`, default `random` — the previous behaviour), `music_dir` (empty = the `music` folder next to the project) and `music_src`; a clip may override them with `music_override`, and the picked random track is pinned in `music_pick`. The clip block on step 3 shows the chosen track by file name, **Another track** re-picks it through a new seed with the previous track excluded (`exclude` in `/api/music_random`), and **Download** fetches a YouTube link up front through the new `/api/music_fetch` instead of the build downloading it silently. The preview and the build both play `music_pick` as a file — `plan_audio` never calls `random_track` when a track arrived — so there is no second independent pick. The previous state is migrated once into the live style.
- **Persistent clip state and recycle bin**: clip state (speaker, camera setup, inserts, style and intro) is preserved alongside XML files in `<stem>.clip.json` on disk, allowing complete restoration when loading or scanning directories. Clip deletion moves files safely to `_reelsi_trash/` with full restore capability.
- **Pipelined markup for step 2 ("Markup all")**: subtitle generation runs sequentially on the GPU, while downstream cloud AI steps (yellow highlights, inserts) start immediately per clip as subtitles complete rather than waiting for the entire batch. Local models run phase-by-phase with model switches deduplicated to avoid VRAM exhaustion. Yellow highlights and inserts can run concurrently per clip.
- **Multi-step undo and redo for any insert edit**: the insert state of a clip (`inserts`, `ins_rejected`, `insTarget`, `job_ins`) is recorded through a single door (`insHistTouch`, called from `saveState`), with undo and redo stacks of 100 states per clip; `Ctrl+Z`, `Ctrl+Shift+Z` and `Ctrl+Y` work while the inserts window or the step-3 preview is open (not inside a text field), and the panel gains "Undo" and "Redo" buttons next to the generation ones. Applying a snapshot does not record itself as a step, and opening the window on another clip resets the history. The previous one-level undo, which only covered deletion, is gone.
- **Intro edge margins and scale per camera**: the intro width share used to be one value for both cameras (`intro_fit_w`, and the constant `INTRO_FIT_W = 0.92` for the attached intro), so the intro on a cutaway came out larger than on camera 1. Each camera now has "Edge margin, %" (`intro_margin` / `intro_margin2`, distance from each frame edge, width share = `1 − 2·margin/100`) and "Intro scale cap, %" (`intro_fit_max` / `intro_fit_max2`); one width rule covers both modes — a detached intro is fitted both ways up to its camera's cap, an attached one is only shrunk by its camera's share. Old styles migrate at read time: `intro_margin = (100 − intro_fit_w)/2`, `intro_margin2 = intro_margin`, `intro_fit_max2 = intro_fit_max`, so already-built clips look the same.

### Fixed
- **The work state lives on the server now, and an out-of-date tab can no longer overwrite it**: the UI state was restored from `localStorage` first, so a stale copy of the browser — a second tab, an old browser profile, another browser — overwrote the server state on load and re-wrote it 2.5 s later, rolling back clips work. The server keeps a revision inside the state file itself (a top-level `_rev` in `ui_state.json`, so it survives a restart), `GET /api/ui_state` returns `{ok, state, rev}`, and `POST` accepts `base_rev`: when it disagrees with the current revision **nothing** is written — neither the state nor the `<stem>.clip.json` snapshots — and the answer is the `stale_state` code (translated in `en.json`), while a request without `base_rev` (an older client) is accepted as before. Check and write share one lock, so two simultaneous posts of the same revision cannot both pass. The front end keeps the revision in `SRVST_REV`, carries it in every save and in the `beforeunload` beacon, and after a `stale_state` answer stops writing to the server and shows a permanent banner with a **Refresh** button (F5, which takes the server state); nothing is overwritten. Booting pulls the state from the server first, and falls back to `localStorage` — with a toast saying so — only when the server did not answer. Covered in `api/files.py`, `static/app/99-boot.js` and `tests/test_ui_state_rev.py`.
- **Operations over a clip use the CLIP's speaker, not the step-1 selector**: every request that runs over a specific clip — AI inserts and "top up" inserts (`/api/ai_inserts`), the insert target ("how many inserts"), the stock, insert-library, image and video generation and the "mark up all" pipeline — sent `speaker: val('speaker')`, the shared "Speaker" select of step 1, which describes a *new cut*. A clip tagged speaker B with no quota of its own (default 10 + 3 = 13) was therefore told it was speaker A (5 + 2 = 7) and got 7 AI inserts, exactly as the owner saw. All clip operations now read the tag through one function, `clipSpeaker(c)` (`static/app/40-queue.js`), with no fallback to the shared select: a clip with "no speaker" gets the defaults (quota 13, no profile). `spkInsTarget(c)` takes the clip. The shared select is left only where it belongs — the cut queue, the cut summary, the boot state and the speaker-profile panel (each with a comment saying so). Covered in `tests/test_clip_speaker.py`: node stands over the live `markupAllRun`, `markupClip` and `aiInsertsRun` check the `speaker` in the request body and the target number, plus a guard that `val('speaker')` now appears only inside the cutting/profile functions.
- **Every clip-speaker read goes through the one door, and a two-speaker test keeps it that way**: the door `clipSpeaker(c)` was there, but several features still read the clip's tag directly (`c.job.speaker`, `(c.job || {}).speaker`) — the `.jsx` and render folders, the LUT, the camera frame, the voice profile and the voice panel (`VOICEFXSPK`), the stock format, the style-panel note, the clip list's speaker column and the "mixed speakers" checks of the build and render buttons — so the same "wrong speaker" bug could come back silently in any of them. All reads now go through `clipSpeaker(c)`; writing the tag stays where it was. The style-panel note describes the OPEN clip's speaker on step 3 and only falls back to the shared selector on step 1, where there is no clip. `tests/test_two_speakers.py` sets two clips of different speakers next to a shared selector standing on a THIRD speaker and walks every speaker-dependent feature: the insert quota, the target and the `/api/ai_inserts` bodies (window and markup), the style on a speaker switch and in the build, the `.jsx`/render folder ladder, the music folder, the LUT and the camera frame, the voice profile of the panel and of the bake, the `speaker`/`format` of the stock, image, video and insert-library request bodies, the style-panel note and the sub-style patch, plus a guard that no direct read is left. `docs/ARCHITECTURE.md` and its English mirror record the rule: a new speaker-dependent feature adds its check to that test.
- **The processed voice of one clip can no longer be heard in the next one**: after a clip was opened, played and closed, opening another clip left the voice track's double on the *previous* clip's baked file — `vtSpareOf` handed back the already created `st.vsp` without ever comparing its source with the live track, so the double was primed and rolled against the new clip's seams and, when it took over, the speaker heard the first clip's audio ("a couple of seconds in I hear the audio track of the first video"). The only invariant is now held in code: a double plays the very same file as the live track. `vtSpareOf` notices a changed source, forgets the run-up through the same door that a source change uses (`vtSpareIdle` — an armed `at` would otherwise keep the old track ready for the next seam) and takes the source from the live element one to one, as `voicePrime` does, and `vtSpareTake` refuses the swap if the sources diverged between the run-up and the seam. Camera doubles keep their own version of the invariant, checked the same way: a fresh clip rebuilds them on its own file (`bufMake`), so the next clip's seam cannot bring the previous clip's frame. Covered in `static/app/60-preview.js` (`vtSpareOf`, `vtSpareTake`) and `tests/test_editor_seam_narrow.py`.
- **The processed voice no longer changes over before the picture on a narrow cut**: on a seam whose cut is narrower than the voice track's swap window (`VT_SWAP_HI`, 0.25 s) the baked voice track was replaced by its double earlier than the jump the picture makes at the same seam, and the sound ran ~107–176 ms ahead of the frame (the owner's "the sound does not match the picture, and then it drifts"). The window in `vtSpareCtl` was measured from the track's *aim* point (`vspAt`, the start of the next edit block in the editor), while the picture jumps at the *end* of the current block; the cut width sits between the two, so the window opened before the jump. The window is now measured from the jump point: the editor's seam is taken by `edJump`, which jumps and calls `vtSpareTake` itself, so the early swap is not done for it, while players that follow the EDL keep it (their aim point is the seam itself). Covered in `static/app/60-preview.js` (`vtSpareCtl`) and `tests/test_editor_seam_narrow.py`.
- **GigaAM weights no longer depend on the working home folder**: the `gigaam` package downloads its weights (421 MB, `v3_ctc.ckpt`) into `~/.cache/gigaam` unless `load_model` is given a `download_root`, and Reelsi never passed one — so the weights landed outside every other application cache (invisible to the user and impossible to move), and on a machine with a missing or read-only home folder (a container, a service account, CI) the cut died with the package's own `PermissionError: '/home/reelsi'` — all 34 clips, one and the same reason. The folder is now chosen in exactly one place (`core/gigaam_cache.gigaam_dir()`) and every `gigaam.load_model(...)` call passes `download_root=` it, in this order: `REELSI_GIGAAM_CACHE` when it is set (a person's explicit choice beats both a ready-made home cache and the home folder itself, or the weights land where they were not put), an existing `~/.cache/gigaam` (an old installation never re-downloads a gigabyte), `~/.cache/gigaam` again when the home folder can be written to, and the fallback `_model_cache/gigaam` **inside the application folder** (`paths.root`, kept out of git) when the home folder is missing or read-only. When nothing can be written to, the error names the folders and the way out instead of surfacing a foreign `PermissionError` — `gigaam_no_dir` for the fallback, and `gigaam_env_no_dir` for a folder named by `REELSI_GIGAAM_CACHE` that cannot be written to, both with an English translation. `docs/PLATFORMS.md` records where the weights go and a test walks `core/` and `api/` by AST to fail on any `gigaam.load_model(` call without `download_root`.
- **The preview shadows now match After Effects: one Drop Shadow → CSS translation, taken from a measurement**: the preview drew shadows of its own — two hard-coded `text-shadow`s for the subtitles, `drop-shadow(0 6px 18px rgba(0,0,0,.6))` for photo inserts, nothing at all for the shape behind the subtitles, and `soft/2` for the intro precomp — while the built `.jsx` used AE's Drop Shadow numbers (`Opacity 68 / Direction 181 / Distance 5 / Softness 44` for the subtitles, `49 / 135 / 15 / 70` for inserts, `173.4 / 181 / 5 / 44` for the subtitle background). A render of AE 2026 measured the translation (a white square in a precomp, black shadow, Opacity 255, Distance 0: Softness 50/150/287 gave a Gaussian sigma of 9.5/28.0/53.5 px by an erf edge fit, rmse < 0.004, so `σ = 0.187·Softness`; CSS blurs a `drop-shadow` with `σ = r/2`, hence `r = 0.374·Softness`, and AE's 0..255 Opacity becomes the CSS alpha as it is). The numbers of all three shadows now live in one place in Python (`core.xml2ae.plan_decor.shadows_plan` — the same constants that feed the `.jsx` substitutions) and reach the preview as `plan["shadows"]`; the front end translates them in one function, `aeShadowCss(sh, k)` with `k` being preview pixels per frame pixel, and every place that draws an AE shadow calls it — subtitles, photo inserts, the subtitle background and the intro precomp. The subtitle shadow is a filter on the word container (the Drop Shadow of the subtitle precomp layer, so it covers the word background too), the subtitle background gets its own, and the insert filter is composed with the entry blur in AE's order. No shadow numbers are left in the preview JS, and the built `.jsx` for a default style is byte-for-byte the old one.
- **The intro precomp shadow opacity knob is percent now**: the two "Transparency" knobs of the intro precomp shadow (`intro_comp_shadow_op` / `intro_comp_shadow2_op`) were labelled with a `%` sign while actually holding AE's raw Drop Shadow Opacity, which runs 0..255: a person picked 50 % and got 20 %, and the default 68 that the template used to apply looked like "68 %" while being 27 %. The keys are renamed to `intro_comp_shadow_opacity` / `intro_comp_shadow2_opacity` and mean percent (0..100, 100 % is the shadow at full strength), the panel range is 0..100, and the percentages are converted to 0..255 in exactly one place (`core.xml2ae.plan_style`, `opacity*255/100`) that both the `.jsx` and the preview read. Old styles migrate as `op/255*100` (68 → 26.7, 31 → 12.2, 255 → 100), so already-built clips keep their shadow; the built `.jsx` for a default style is byte-for-byte the old one.
- **Every speaker gets their own `.jsx` folder**: the folder of a tagged clip was looked up in the speaker profile's `jsxdir` only, and a profile without it (an empty `jsxdir`) fell back to the shared `AEGLOBAL` field — which **every** speaker selection rewrites. Clips of one speaker therefore went into the folder of the last speaker selected. The lookup is one ladder now — profile `jsxdir`, then the profile's cut folder (`outdir`), then the clip's own XML folder — and the shared field is used by untagged clips only. The render output folder follows the same ladder without the XML rung (the shared field, the server's `exp` default), and the caption under each field names the rung it came from.
- **Subtitle generation no longer fails on a fresh installation**: the subtitle step read the camera's source MP4/MOV with `librosa.load`, and librosa 1.0 dropped its `audioread` fallback while libsndfile cannot read video, so the step died with `LibsndfileError` on any footage. The camera audio now goes through ffmpeg (`core.sync.extract_audio`, `-vn`) into a temporary WAV first, with the file removed in a `finally`. The same run also passed a *path* to faster-whisper, which decodes paths with PyAV, and PyAV 19 removed the `metadata_errors` argument that faster-whisper 1.2 still passes — every transcription raised `TypeError`; `core.transcribe` and `core.selfcheck` now read the WAV themselves and hand the model a float32 16 kHz array, so PyAV is not involved. `requirements.txt` finally has upper bounds (`librosa<1.0`, `faster-whisper<2`, `transformers<5`, `numpy<3`, `soundfile<1`) and declares PyAV explicitly as `av>=12,<19`.
- **The "Mind" level follows the model change**: picking another model profile for a step left the reasoning-effort select showing the levels of the *previous* model — and disabled when that model had none — until the settings were closed and reopened. The profile select now redraws the levels next to itself, exactly as the level select next to it already did.
- **XML paths are never glued together in the front end**: `/api/status` returns **full** paths in `results` (the server writes those files, it knows the folder) and the client stopped prefixing the output folder with a hard-coded backslash. On Linux that produced one file name with a backslash inside, so the preview, the statuses, the markup and the build silently failed for every clip cut in that same run. `clipByXml` compares paths the way `normInsPath` does — separators and case — so the same file is never added as a second clip with its own markup, and a path already saved in that broken shape is repaired when the UI state is loaded.
- **"Already running" names the task that holds the shared lock, and where its progress is**: the lock owner is recorded when the lock is taken, so the refusal no longer says "another task" for the cut, the draft and the preview proxy build — the proxy one names itself and its progress (which camera of how many, how many per cent, and that the progress is in the preview window and in the Logs). The proxy's own log lines now reach the common Logs panel that the message points at; it used to be empty there, because the builder wrote only to its own job.
- **The cutting progress line names the ASR engine that actually cuts**: it always said "Omni", even when the engine taken from `active_cut_asr` was GigaAM — the one string by which a user tells what is cutting his footage.
- **doctor stops raising a false alarm about the Python version, and shows the failure type**: 3.10 and 3.12–3.14 are the versions CI itself builds and smoke-tests, so they are no longer WARN (only versions outside that set are); the set lives in a single constant and a test compares it with `ci.yml`, so the two cannot drift apart. An optional module that fails to import is now reported as "нет (RuntimeError) — отключится: …": the exception type is what separates "the package is not installed" from "the package is installed but broken" (rembg with a failing numba sent people to install what they already had).
- **The processed voice no longer disappears between the preview and the project**: the clip's final voice was one file `<stem>.voice.wav` replaced in place, and on Windows that replacement fails while the file is held open (the step-3 preview plays exactly that file, `/api/media` serves it, an open AE/Premiere project holds it) — the new take never appeared and the failure was one log line, so the build shipped the camera audio. The voice now goes to a versioned name (`<stem>.voice.<key8>.wav`), the version name lives in the `<stem>.voice.json` sidecar (`"file"`), and every reader resolves it through `final_voice_path`; the preview plays the immutable cache copy, a per-clip lock guarantees one bake per clip, and a failed bake is visible — a toast and a "voice without processing" line in the preview, a warning with the reason in the build result.
- **Inserts that share one file no longer get confused**: every step-2 card gets a stable `uid` (and every step-3 insert carries `cid = card.uid`), so a timing edit, a frame drag, the "playing" highlight and the manual AE tweaks (`style` / `scale` / `sin` / `noexit`) land on the very card they belong to. Three inserts using the same photo used to look up "their" card by file path, that is by the first match: editing the second one moved the first, and after a rebuild the insert was gone from its own place. The path stays a fallback key for legacy inserts without `cid`, and then each card is claimed by one insert only.
- **A small card no longer gets a cut width it cannot hold**: the parallel AI cut took the clip count from the settings (1..16) without ever looking at video memory, while every clip process holds a CUDA context of its own — 568 MiB each, measured on a 4096 MiB card (four processes = 2307 of 4096 MiB, peak 696 MiB under work). Ten clips therefore meant `OutOfMemoryError` inside a subprocess and a bare "code 1" in the UI with no reason given. `cut_parallel_width` now caps the width at `free_vram // 600 MiB` (`core/device.py` measures free memory the way `doctor.py` does — torch, then `nvidia-smi`) and writes the reason into the job log (`карта 4.0 ГиБ, каждый ролик держит ~600 МиБ — одновременно не больше 6 (просили 10)`); a machine without CUDA has no cap.
- **Subtitles no longer take the video card behind the cut's back, and a Whisper model that does not fit has a way down**: `POST /api/gen_subs` raised ASR in the server process and took no `gpu_lock`, so subtitles on top of a running cut were two models on one card (Whisper and GigaAM) — recognition now runs inside `gpu_lock("субтитры")`. A model that does not fit used to die with a raw `CUDA failed with error out of memory` and no advice: the attempt is repeated with `compute_type="int8_float16"` and then one step down the ladder (large-v3 → medium → small), every step reports the card size and what was taken instead, and when nothing fits the answer carries the `whisper_gpu_fallback` code with its English translation. Out-of-memory is recognised by exception type or text in one place (`core.device.is_oom_error`).
- **A "big on the left" intro group no longer stands below its neighbours**: the precomp scale anchor (`intro_scale_anchor`) mode `first` took the *first row of the list* as "the top of the block", and in a group with a big word that first row IS the big word, whose baseline `intro_big_layout` puts at the BOTTOM of the block (on the baseline of the last stack row). Auto-fit then shrank such a group around the bottom of the big digits: on the clip the measurement was taken from, an ordinary group anchored at 960 (its top row, `ys` 960/1120) while a "big on the left" group anchored at 1112.14 (`ys` 1112.14/984.14/1112.14), the Position compensation (ay − H/2)·96.8 % gave them 0 and +147.27 px, and the block stood ~177 px of frame lower than a neighbour at ds 73 against 100. Mode `first` now means the Y of the TOPMOST row of the block (the minimum of the non-empty `ys`) and `block` the middle between the topmost and the bottommost row (min/max). An ordinary group lists its rows top to bottom, so its `ys`, `y` and `anchor_y` are unchanged to the hundredth and the built `.jsx` stays byte-for-byte the old one; the anchor still reaches the `.jsx` (INTRO_ANCHOR_Y) and the preview (`plan.intro[].anchor_y`), and no second copy of the number is made. Covered in `core/xml2ae/plan_intro.py` and `tests/test_intro_big_anchor.py`.
- **A "big on the left" intro group stands where the style puts it, like any other group**: such a group had a fix-up of its own — the top of its block was levelled with the top the same group would have had in the ordinary layout (`intro_big_top_shift`). The big word is sized to the height of the stack and `intro_big_over` lifts it above the block's top, so the fix-up dragged the WHOLE stack off the base the style anchor puts it on, and `y` went with it (the precomp scale anchor is taken from the topmost row of the block). On the clip the measurement came from, the top row of the stack read `ys` 984.14 against 960 for an ordinary group at the same group scale and camera, the block's `y` was 328.58 against 305.21, and the owner lifted such groups by hand (−228.7 px of frame). The fix-up is gone: the top row of the stack sits on the base of the style's anchor (960, and the block's `y` is 305.21, on the same clip) exactly like the top row of an ordinary group; the block's top in the frame moved from 1208.35 to 1167.90 px and is level with the neighbours (median 1162.53 px). `intro_big_over` still lifts the big word alone — that is its own business and does not touch the block anchor. Groups without a big line are untouched (the built `.jsx` for a default style stays byte-for-byte the old one and the golden reference is not regenerated), and the layout inside the block (`intro_big_layout`: the big word on the left, the stack on the right, its size) is unchanged. Covered in `core/xml2ae/plan_intro.py` and `tests/test_intro_big_anchor.py`.
- **Preview audio is the camera's own track, and Firefox says why it is silent**: the audio proxy built for unreadable source audio played *on top of* the camera sound in Chromium, where the source track is decoded fine — the owner heard two voices at once. It is gone, front and back: no `<audio>` proxy, no `media.probe_audio_codec`, no `_audio_proxy_plan`/`build_audio_proxy` and no `audio` field in `/api/preview_proxy`, which is back to the plain video-proxy route. Firefox genuinely cannot decode PCM inside MP4 (measured 2026-10-07: Chrome 152 on Windows and Linux read it, Firefox 156 does not), so the player now says so in its own progress row when the source camera has played for at least 1.5 s and `<video>.mozHasAudio === false` — a property only Firefox has, so in Chromium the row never appears. The row goes away with the switch to the preview proxy, whose audio track is aac. The READMEs recommend a Chromium-based browser (Chrome, Edge, Brave) for the preview.
- **The step-1 preview no longer depends on the `AudioContext` being awake**: `createMediaElementSource` is irreversible — after it an element sounds only through the graph, and a suspended context (the browser keeps it suspended until a real gesture) mutes it silently. Every play start now wakes the graph through ONE door, `audioWake()` (`edPlay`, `ipvPlay`, `cpvPlay`), instead of the step-3 player waking it by accident through the music sync, and the camera `<video>` is attached to the graph **lazily**: only when a processed voice track or the live plug-in host actually needs it. A speaker without processing plays the camera audio directly, whatever the context state.
- **`pedalboard` is declared**: it was not listed anywhere — not in `requirements*.txt`, not in `pyproject.toml`, not in the installers, not in `doctor.py` — so the only way to learn about it was to turn the plug-ins on. It now lives in `requirements-optional.txt` and in the doctor's optional list ("live monitoring through VST3 plugins and the output device list"). The output device list is no longer tied to it: without the package `/api/voicefx_devices` answers with the devices listed by the sound system (Windows registry, `core.voicefx.system_output_devices`) and a `reason` naming what is unavailable, instead of failing with "no pedalboard" — and enabling the plug-ins still shows the reason without muting the camera.
- **The built-in render (no After Effects) picks its ANGLE back-end by platform**: `--use-angle=d3d11` was hard-coded in the frame catcher, and Direct3D 11 does not exist outside Windows — on Linux Chrome fell back to the software SwiftShader and a 1080x1920 frame cost 400-550 ms with the GPU idle (225 ms is the measured Windows figure). `core.webrender` now names the back-end by platform (`d3d11` on Windows, `vulkan` on Linux, `metal` on macOS, `REELSI_ANGLE` overrides it) and hands it to the catcher as `--angle`; `docs/PLATFORMS.md` carries the Vulkan ICD recipe a Linux container needs, without which Vulkan has zero devices and the flag alone does not help.
- **A hanging frame catcher is an error, not silence**: when the render page stopped answering the DevTools call, the catcher wrote `Runtime.evaluate: the browser did not respond within 120 s`, the error sat in the log and the job stayed `running` at 0 % forever — there was nothing left to wait for and no way to see it. The catcher now writes a `#timeout` mark, and `webrender.render` reacts to it by killing its own processes (by PID, the same path as Stop, Chrome included) and raising a `ReelsiError` that names the reason.
- **"Stop" stops the built-in render too**: `render_kill` only knew the AfterFX/aerender process, so cancelling a render without AE killed nothing at all — its children (the node catcher with its Chrome, the segment ffmpeg, the concat) are now registered in `RJOB` and killed by the same `kill_tree`, while the render itself leaves the wait loop on the cancel flag.
- **The clip progress no longer jumps**: the per-chunk counter the catcher prints and the whole-clip counter printed by `core.webrender._Progress` had the same shape (`кадр N/M`), and `core/render_job._FRAME_RE` matched both, so a lagging chunk pulled the bar back (19 % → 5 %). The chunk line is now `кусок N: кадр a/b` and only the summed line moves the percent.
- **A missing camera frame outside the chunk no longer sends the chunk to `<video>` seeking**: the per-camera miss counter counted every failed image, including that of a camera the chunk does not show at all, and after three misses in a row the camera was declared dead for the whole chunk (a live run spent 149 frames seeking at 94 ms instead of 22). Misses are counted for the cameras the chunk actually shows, and the log line names the first missing address instead of only the status.
- **The catcher kills its own Chrome on a normal finish, children and all**: `google-chrome` is a wrapper script, so a `SIGKILL` to the parent left the browser and its children running (155 Chrome processes, 112 of them zombies, after a single Linux render). On a normal finish and on Stop alike the catcher now kills the process tree by PID — `taskkill /F /T` on Windows, its own process group on POSIX.

### Security
- **A stock item's id can no longer write outside the library**: the file name of a downloaded stock item was built from `cand["id"]` straight out of the provider's answer, so `id="../../../../tmp/OWNED"` landed the file outside the library (the same `file://`-style path also let a hostile answer make the server read a local file). The name is sanitised now (letters, digits, `.` `_` `-` only; no separators, no `..`) and the finished path is checked with `realpath` to stay inside its folder — and every download address that comes from an external answer goes through the same SSRF guard (`unsafe_url_reason`): plain `http`/`https` to a public host only, never `file://`, loopback, link-local or a private range. Covered in `core/stock.py`, `core/aicut/images.py` and `/api/video_probe`; the guard sits in one place (`core/_pathguard.py` for names, `core/app_meta.unsafe_url_reason` for addresses).
- **Custom profile headers are masked like API keys**: a header value is a supported secret channel (`apply_profile_headers` — `Authorization`, `x-api-key`, provider tokens), and `GET /api/ai_config` handed those values to the browser in clear text (localStorage, devtools, and the "Custom headers" field itself). Headers now go out as `•••xxxx`, exactly like the API key, a value that is still a mask is never written to the config (it is replaced by the stored one, same rule as the key), and a live call (`Check`, model list) resolves the mask back to the stored value instead of sending `•••xxxx` to the provider. `env:VAR` stays unmasked: it is a variable name, not a secret.
- **The GPU lock no longer spins forever on a broken lock file**: any failure (read-only folder, missing permission, `msvcrt` failure) was treated as "the GPU is busy" — `while True` with a 0.5 s sleep and a "waiting for the GPU" message, with nothing to wait for. Being busy is now only a refusal to lock an already-open file (some other clip holds it, and waiting for that is honest), while a lock file that cannot be created or opened raises `ReelsiError` with the reason at once.
- **`Host` is checked with its port, and the built-in renderer no longer trusts `request.host`**: `127.0.0.1:5999` is a local name but a foreign door, so a `Host` that names a port must name this server's port. The address for a render without After Effects is built from the server's own port instead of the `Host` header, which anything can set.
- **`/api/export_xml` is a `POST` now**: it rewrites the XML (`sync_xml_voice`), so as a `GET` a hostile page could trigger it with an `<img src>` tag. The front end (clip download button, step-2 download, the XML format of the download dialog) posts the path in the body.

### Install
- **The style carries the music and the intro fit now, and old styles migrate once on load**: `music_mode`/`music_dir`/`music_src` replace the shared step-3 fields and the picked random track is pinned in `music_pick`, while `intro_margin = (100 − intro_fit_w)/2`, `intro_margin2 = intro_margin` and `intro_fit_max2 = intro_fit_max` keep the intro size of the saved styles; the style files on disk are not rewritten.
- **The disclaimer is a style block now**: **Disclaimer → Transform** carries **Scale, %**, **Position by height, % of frame** and **Horizontal shift, px**; a style without them builds exactly as before (`DISC_X` is not declared when the shift is zero).
- **Live monitoring through VST3 plugins needs `pedalboard`**, now declared in `requirements-optional.txt` (`pip install pedalboard`) and in the doctor's optional list; without the package the plug-ins are unavailable, the output devices are still listed and the camera sound is not muted.
- **The GigaAM weights folder is chosen by the installation**: `REELSI_GIGAAM_CACHE` when it is set, an existing `~/.cache/gigaam` (never re-downloaded), otherwise a folder inside the application, so a missing or read-only home folder no longer kills the cut.

- **Style panel tests catch real breakage**: the DOM stub only knows the elements the panel created; visibility, field read-back for every control type, the slider row and the roto fraction are checked by behaviour, and each check was confirmed by a deliberate code mutation.
- **Every style knob is checked end to end**: each of the 118 style keys changes the built `.jsx` (caption, intro rows, sound, music, transition and roto included), fractional fields keep their scale, and a full pass through the style panel leaves every value unchanged.

Computed masks stay cached for the next build; turn roto off in the style to build without it.

Each stage was moved with the built `.jsx` and the plan JSON byte-identical on eight real clips.

A guard test fails the run when a copy comes back.

On macOS and Linux Stop now kills the whole process group, so a grandchild holding video memory no longer survives it.

Adding a knob no longer means editing numbers in three test files, while a missing translation or a duplicate key now turns the run red.

Claims about the size of a file in lines were removed from the text — they go stale with every edit.

### Fixed
- **Deleting by a foreign path**: `/api/clip_delete` removed every `<name>.*` next to any path it was given, and `/api/clean_tmp` cleaned any folder. Both now require the target to be a Reelsi cut or output folder; `/api/breaths` checks its target the same way.
- **SSRF in the paid video download**: the result was fetched from any address the provider returned, redirects included. Now only `http`/`https` to public addresses is accepted, each redirect is checked again, and authorization headers are not carried to another host.
- **Broken journals are no longer wiped**: a broken file of learned hallucination phrases, media import log, video generation history or hard-terms dictionary used to be read as empty and then overwritten by the next write. Now the learned phrases are left untouched, and the journals are set aside as `<name>.bad-<time>` before the next write.
- **The hard-terms dictionary was erased silently**: `POST /api/terms` without the `terms` field replaced the dictionary with an empty list, and a string was stored letter by letter. Both are errors now; an explicit empty list still clears it.
- **Linux CI and the public repository were red**: a process stub in the tests did not accept the POSIX process-group argument, and two documentation checks required files that are not published. The checks now follow `.publicignore`.
- **Intro counter on fractional numbers**: the After Effects expression read the slider as an object, so fractional counters ("5,2") failed; Repeat Edge Pixels is now off on every intro blur, not only on subtitle highlights.
- **AI intro answer lands in the right clip**: opening another clip while the model was thinking wrote the answer into the wrong clip.
- **Errors of background jobs reach the log**: a build, render or cut that stopped with a user-facing reason («roto was not computed for 3 of 40 chunks» and the like) lost that text in the job thread — the job just ended and the item was not listed as failed. The reason is now written to the job log and the item is marked failed.
- **Big intro word keeps its size in After Effects**: the entrance animation keyed Scale in absolute 70 → 100 % and overrode the big word's layer scale, so "big on the left" looked normal-sized in After Effects while the preview was right. Entrance scale keys now start from the layer's own scale.
- **Deleted subtitle word leaves no gap**: deleting a word removed its clip from the XML and left an empty gap until the next word (a counter could start more than a second late). The next word now takes the deleted word's start when it followed directly (pause ≤ 0.3 s); its end, the highlight entrance and the counter follow the new start. Gaps left by earlier deletions stay.
- **Preview subtitles follow the style at once**: the subtitle overlay was rebuilt only when the visible words changed, so a new font or height did not show while paused.
- **Style panel scrolls in the preview tab**: with many groups open the panel ran off the bottom.
- **Camera proxy progress is visible**: a block over the player shows the camera, file and percentage while proxies are built; ffmpeg progress is read by a separate thread, because on Windows a timed-out `communicate()` carries no output.
- **Video inserts in the preview**: they no longer blink black on every edit (the `<video>` element is reused), "Scale, %" works at 100 % and above, and scaling grows from the centre as in After Effects instead of from the top-left corner.
- **Preview no longer stalls the interface**: opening the step 3 preview or pressing Save could wait for several seconds. The browser keeps at most six connections per server, and every preview `<video>`/`<audio>` (cameras, their buffers, music, sound effects, video inserts) asked for the whole file, filled its buffer and then held the connection without reading; with six such elements an ordinary request waited 5.3 s. `/api/media` now answers an open or long byte range with a 4 MB piece (after the security checks), so the browser asks for the next piece itself and the connection is released; with eight videos on the page requests take 8–95 ms. Requests without a range and downloads (`dl=1`) still get the whole file.
- **Short highlighted words finish their entrance**: a highlighted subtitle word shown for less than 0.35 s disappeared in the middle of its entrance (rise, fade-in, blur). The entrance now lasts min(0.35 s, 60 % of the time the word is visible), in the one-word mode, with joined words and in the stack of consecutive highlights in rows; the preview uses the same numbers. Videos without short highlighted words build byte-for-byte as before.
- **Head follow after Stop**: stopping the build during head tracking saved a partial track as complete, and following froze with an old offset for the rest of the video. Cancelling now stops the build without writing the cache, and a cached track is used only if it covers the camera-1 ranges of the current edit.
- **Subtitle rows with an intro**: word timings from `.words.json` were not re-indexed after the intro words were removed, so rows broke in the wrong places.
- **Background-removal cache**: two images with the same name and different extensions shared one cut-out; the cache is now `<name>.<ext>.nobg.png`. The cut-out no longer shows up in the insert library as a separate image.
- **Preview of yellow words in rows**: the rise, fade-in and blur-in of highlighted words are now visible in the preview in multi-word rows, with the numbers from the scene plan.
- **Photo on a plate squashed in the preview**: background removal trims empty margins and changes the aspect ratio (e.g. 1408×768 → 176×451), but the preview plan sized the photo frame from the original file. The switch to the `.nobg.png` file now happens in the scene plan, so the preview and the `.jsx` use the same sizes.
- **Fonts falling back to Times New Roman in After Effects**: when After Effects lists several fonts under one PostScript name (a font reinstalled over an older copy), setting the font by name picked a broken copy and the text silently became Times New Roman. The build now tries every copy once per name on a probe layer, uses the one that sticks, and logs when none does.
- **Tritone washing out bright highlight colours**: the intro yellow-line Tritone is skipped when the midtone colour is bright (Rec.709 luminance above 0.7), because the glow pushes letters to white and Tritone keeps them white; darker colours keep it.
- **Preview**: camera-2 inserts no longer move with camera 1; panning, head follow and horizon no longer show stripes or smeared edges — the whole source is drawn through one camera matrix, the same model as in After Effects.
- **Background removal without rembg**: an insert on a plate falls back to the original file with a log line instead of failing the whole build.
- **CI**: a subtitle-rows test no longer depends on fonts installed on the machine.

- **A normal stop is not reported as a crash**: stopping the server with SIGTERM (SIGBREAK on Windows) removes its run marker, so the next start no longer warns about an abnormal end; the warning now says "crashed or was killed".
- **Style panel controls have accessible names**: sliders, hidden number inputs, colour swatches, file and reset buttons and tree rows are labelled; the layer order list is labelled by its caption.

The older VAD path checks the model's decision before long intervals are restored.

The previous cut stays untouched.

- **Language model calls**: a 400 error about `max_completion_tokens` or `stream_options` no longer loops the retry; the reasoning level on a retry is lowered from the previous attempt.
- **Local API**: state-changing requests from other sites are rejected by `Sec-Fetch-Site` and `Origin` checks.
- **Jobs**: render takes the shared job lock, so a cut can no longer start on top of a render.
- **Saved files**: JSON files and word lists are written atomically, so a stop or crash mid-save no longer leaves an empty file; concurrent `ai_config.json` saves no longer overwrite each other.
- **Premiere subtitle XML**: the subtitle track goes inside the sequence's video block, and the frame rate comes from the source XML.
- **Multicam**: until a late camera starts, its segment is taken from camera 1.
- **After Effects build**: an empty riser start time no longer breaks the script; a clip that fails in a batch build is reported as failed.
- **Editor and inserts**: the intro line colour input no longer throws a syntax error; insert sound preview follows the chosen file; the right insert is picked when the plan list is filtered; malformed entries in the model's insert answer are skipped; long words can be renamed in subtitle graphics; draft render accepts clip names with commas, brackets and quotes.
- **Build verification tools**: a one-`.jsx` build is checked against the selected timeline; empty middle intro groups are handled.
