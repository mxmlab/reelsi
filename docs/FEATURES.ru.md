# Все возможности по шагам

Reelsi — локальный помощник монтажа говорящей головы. Этот документ проходит по мастеру
из трёх шагов и перечисляет все возможности: что делает каждая, где живёт в интерфейсе,
как ей пользоваться и что стоит денег.

English version: [docs/FEATURES.md](FEATURES.md).

## Как устроено

Интерфейс — один мастер из трёх шагов: **Нарезка** → **Разметка** → **After Effects**,
плюс окно настроек и отдельная вкладка «Видео». Всё тяжёлое считается на вашей машине:
распознавание речи, синхронизация камер, детектор вздохов, ротоскоп и черновой рендер.

Через API уходит только текст: текстовая LLM решает, что вырезать, какие слова
подсветить, где стоят вставки и что говорит интро. Эта же LLM умеет работать локально
в LM Studio или Ollama. Генерация картинок и видео всегда идёт через API провайдера.

## Перед началом

### Раскладка рабочей папки

Держите репозиторий в одной папке рядом с материалом. Результаты Reelsi пишет рядом с
материалом, поэтому мастеру достаточно знать, где лежат папки камер.

```
моя_папка/
├── reelsi/            ← этот репозиторий
├── камера1/           ← видео с камер
├── камера2/
├── music/             ← скачанные треки (необязательно)
└── Reelsi_out/        ← нарезки и сайдкары
```

**Где:** шаг 1 › **Папка проекта (где камеры)**
**Как:** 1. Положите репозиторий рядом с материалом. 2. Задайте папку проекта.
3. Нажмите **Пересканировать папки** — Reelsi покажет найденные папки камер.
**Настройки:** **Папка результата** — куда падают нарезанные XML и их сайдкары. Папка
для собранных `.jsx` задаётся на шаге 3.
**Code:** `templates/index.html:52`, `api/files.py:30`, `webui.py:81`

### Профили спикеров

Профиль спикера — это «кто в кадре» как набор настроек: свои папки, свои пороги нарезки,
свой стиль AE по умолчанию и свои подсказки ИИ.

**Где:** шаг 1 › **Спикер** (карандаш — правка, плюс — новый), и то же окно из строки
клипа на шаге 3.
**Как:** 1. Нажмите плюс рядом с селектором **Спикер**. 2. Заполните имя, папку
результата, папку для `.jsx` и папку вывода рендера. 3. Выберите стиль AE по умолчанию
и напишите подсказку ИИ, если она нужна. 4. Сохраните.
**Настройки:** пороги нарезки (тишина, голос, запас вокруг слова, дыра без речи и
остальные) лежат на свёрнутой панели **Калибровка — правит ассистент**; у детектора вздохов свои пороги
реза и метки. Приписки к промптам генерации картинок и видео — в том же окне, там же два
слота подложки — **Подложка: приписка к промпту 1/2**: их берут вставки с галкой **на
подложке** вместо обычных слотов.
**Ограничения / цена:** профиль — обычный JSON в `speakers/`, папка в гит не попадает.
Стиль в профиле — значение по умолчанию: на шаге 3 стиль всегда можно поменять.
**Code:** `core/speakers.py:29`, `core/speakers.py:68`, `api/presets.py:85`,
`templates/index.html:570`

### Профили ИИ-провайдеров

Профиль — это один провайдер плюс одна модель плюс ключ. Шаги мастера выбирают, какой
профиль на каком шаге работает.

**Где:** ⚙ в шапке › **Подключения**.
**Как:** 1. Откройте ⚙ и выберите или заведите профиль. 2. Выберите провайдера и
модель. 3. Вставьте API-ключ и нажмите **Проверить**. 4. Нажмите **Сохранить**.
**Настройки:** поддерживаются LM Studio и Ollama (локально), CommandCode, Anthropic,
OpenRouter, DeepSeek, Groq и любой OpenAI-совместимый адрес со своим Base URL. Ключ можно
написать как `env:ИМЯ_ПЕРЕМЕННОЙ` — тогда он не попадает в `ai_config.json`. Для шлюзов
есть дополнительные заголовки. Возможности модели (уровни размышлений, temperature,
кэширование) берутся из открытого каталога models.dev, кэш на диске обновляется раз в
сутки.
**Ограничения / цена:** ключ хранится только на сервере и отдаётся в браузер маской.
Текстовые вызовы стоят копейки; картинки и видео провайдер считает по выбранной модели.
Локальные провайдеры бесплатны.
**Code:** `core/aicut/config.py:41`, `core/aicut/config_actions.py:41`, `core/aicut/catalog.py:1`,
`templates/index.html:890`

### Каталог моделей и статистика вызовов

**Где:** ⚙ › **Подключения** › **Диагностика вызовов ИИ**; список моделей — в поле
**Модель** на той же вкладке.
**Как:** 1. Нажмите **Обновить список**, чтобы спросить у провайдера его модели.
2. Откройте диагностику, чтобы увидеть, во что обошлись прошлые вызовы.
**Настройки:** панель группирует вызовы по модели, шагу и уровню «ума» и показывает
медианы токенов, доли размышлений и времени. Ошибки считаются отдельно.
**Code:** `api/ai.py:245`, `api/ai.py:524`, `core/aicut/config.py:38`,
`core/aicut/catalog.py:22`

### Генерация картинок и видео: что встроено

Локальные генераторы картинок и видео в код не встроены. Генерация идёт в image-модель
или видео-модель через API провайдера. Проект открытый, поэтому подключить свой
локальный бэкенд может любой: точки расширения — `core/aicut/images.py` и
`core/aicut/video.py`.

## Шаг 1 — нарезка

**Как:** 1. Вставьте ссылку в поле **Ссылка**. 2. Задайте **Папку загрузки**.

**Настройки:** `rclone` настраивается один раз командой `rclone config`, вход в аккаунт

**Ограничения / цена:** качает `rclone`, поэтому крупные файлы ему по силам; прогресс
разбирается из его статистики.
**Code:** `api/gdrive.py:244`, `core/rclone.py:46`, `templates/index.html:32`

### Проект, число камер и очередь

**Где:** шаг 1 › **Проект**.
**Как:** 1. Задайте папку проекта. 2. Выберите число камер (от 1 до 4). 3. Выберите
файл каждой камеры. 4. Нажмите **В очередь** — или **Авто-пары по имени**, или

**Настройки:** **Подбор по звуку** ищет в папках камер 2..N файл того же дубля по
корреляции огибающих; порог снят с реальной съёмки, поэтому «похожего не нашлось» так и
означает «похожего нет». **Подбор всех по звуку** делает то же для всей папки камеры 1, а галка
**только новые** пропускает дубли, на которые в папке результата уже есть XML.
**Code:** `templates/index.html:49`, `api/files.py:57`, `core/sync.py:113`,
`core/sync.py:26`

### Синхронизация по звуку

### ИИ-нарезка

**Где:** шаг 1 › **Нарезка** › **ИИ-нарезка** (основная кнопка).
**Как:** 1. Заполните очередь. 2. Задайте папку результата. 3. Нажмите **ИИ-нарезка**.
**Настройки:** CTC-модель слушает файл целиком и отдаёт каждое слово с родными
таймингами. Дальше текстовая модель получает полную расшифровку и возвращает тот же
текст, заключив в квадратные скобки то, что надо выкинуть; код выравнивает этот ответ на
наши слова. Тишина дольше 0.8 с режется всегда. Модель и уровень «ума» задаются в ⚙ ›
**Нарезка**. Черновик mp4 собирается в конце каждой нарезки.
**Ограничения / цена:** провайдеру уходит только текст. В видеопамяти живёт одна тяжёлая
модель за раз, поэтому GigaAM выгружается до обращения к LLM.
**Code:** `core/gigaam_cut/asr.py:49`, `core/gigaam_cut/decide.py:26`,
`core/gigaam_cut/decide.py:169`, `core/gigaam_cut/pipeline.py:61`

### Кастомная нарезка и её ступени

**Где:** шаг 1 › **Нарезка** › **Кастом**; сами ступени — в ⚙ › **Нарезка** ›
**Ступени нарезки**.
**Как:** 1. Нажмите **Кастом**. 2. Отметьте нужные ступени в ⚙. 3. Запустите.
**Настройки:** ступени — один список, общий для бэкенда и интерфейса:

| Ступень | Что делает |
|---|---|
| **Паузы** | Вырезать паузы: по словам (речь), по энергии звука (громкость) или выключить |
| **Распознавание речи** | Пословные тайминги ASR; включается сам, если он нужен другой ступени |
| **Смысл (ИИ)** | LLM размечает смысловые куски и убирает неудачные дубли |
| **Правка нарезки кодом** | Код поверх ответа ИИ: повторы, оговорки, микро-островки; слабым моделям помогает, умным портит |
| **Подгон резов** | Точная подгонка точек реза по огибающей звука и границам слов |
| **Вздохи** | Детекция и вырезание вздохов перед фразами |
| **Черновик mp4** | Быстрый `.draft.mp4` для предпросмотра нарезки |

Выбор **Паузы → по громкости** переводит нарезку на классическую ветку: VAD плюс Whisper
вместо родных таймингов CTC. Пороги VAD (порог тишины, минимальная пауза, паддинг)
появляются на той же вкладке настроек.
**Ограничения / цена:** у ступени «Черновик mp4» отдельной галки в интерфейсе нет: она
включается вместе с Omni-ревью.
**Code:** `core/cutstages.py:16`, `core/cutstages.py:87`, `core/cutstages.py:149`,
`templates/index.html:801`, `static/app/10-settings.js:243`

### Детектор вздохов и полоска спорных вздохов

**Где:** шаг 1 › **Нарезка** (работает внутри нарезки), и полоска в редакторе нарезки.
**Как:** 1. Запустите нарезку. 2. Откройте редактор. 3. Клик по оранжевой полоске
вырезает этот вздох.
**Настройки:** профиль спикера может задать свои порог реза и порог метки; дефолты —
0.95 — вырезать, 0.50 — отметить. Участок с вероятностью речи выше 0.25 не режется

**Ограничения / цена:** решают три источника: Silero VAD, CED-tiny в изоляции и
акустика. Если нет `silero-vad`, `transformers` или файла модели, детектор молча
выключается, а нарезка идёт как раньше.
**Code:** `core/breath.py:40`, `core/breath.py:229`, `core/breath.py:254`,
`api/editor.py:135`

### Редактор нарезки

**Где:** шаг 1 › список клипов › **Правка** (окно предпросмотра, левая половина).
**Как:** 1. Откройте клип. 2. Клик ставит курсор, края блоков тянутся, двойной клик по
серому возвращает вырезанное. 3. Нажмите **Сохранить в XML**.
**Настройки:** колесо — зум, Shift+колесо или линейка — прокрутка, пробел — играть,
стрелки — покадрово. **Резать** (C), **Удалить** (D) и **Отмена** (Ctrl+Z) работают по
блокам. Галка **слушать вырезанное** играет и вырезанный звук. Плеер здесь **один** —
редактор: блока «Монтаж» со вторым плеером больше нет, а громкость и строка
«камера — склеек — длина» переехали в его строку управления. Клик далеко по таймлайну во
время игры теперь ставит плейхед ровно туда, куда кликнули (раньше второй плеер откатывал
его на следующий кусок монтажа).
**Обработанный голос спикера** (шумодав и живые VST-плагины) звучит в этом же плеере: и
когда слушаете монтаж, и когда играете исходник. Время звука — исходное время камеры 1 под
плейхедом, поэтому на вырезанных местах звук прыгает вместе с картинкой, а громкость
слушают ползунком строки плеера (см. «Голос» на шаге 1).
**Ограничения / цена:** сохранение переписывает XML и пересчитывает тайминги вставок под
новый монтаж; окно предупреждает, если закрывать с несохранённой правкой.
**Code:** `templates/index.html:306`, `static/app/70-editor.js:13`,
`api/editor.py:256`

### Голос спикера

**Где:** шаг 1 › предпросмотр нарезки › панель **Голос** (у спикера в профиле нужна
включённая обработка голоса); на шагах 2–3 — та же панель у превью вставок.
**Как:** 1. Поставьте в профиле спикера **ИИ-шумодав** и/или добавьте VST3-плагины.
2. Откройте превью — дорожка обработанного голоса звучит в плеере. 3. Крутите ручки
шумодава и плагинов на слух, кнопка **Настроить** открывает окно плагина.
**Настройки:** цепочка идёт в порядке «шумодав, потом плагины», как дорожка в DAW. Живой
хост существует только пока открыто окно плагина («крутить и слушать»): закрыли окна — хост
отдаёт состояние ВСЕХ плагинов в профиль спикера, голос перепекается, и все три шага играют
одну эту запечённую дорожку — ту самую, что уйдёт в AE. Пока
шумодав считается (или он выключен), плагины звучат ВЖИВУЮ поверх звука камеры — на кадре
так и написано; досчитался — хост меняет дорожку на очищенную с того же места. Итоговый
голос пишется ВЕРСИОННЫМ файлом (`<stem>.voice.<key8>.wav` и сайдкар `.voice.json`), поэтому
замена не падает на Windows, когда старый файл держит превью, `/api/media` или открытый
проект AE/Premiere; сбой запекания не молчит — в превью тост и строка «голос без обработки»,
в итоге сборки предупреждение с причиной.
Смена плагинов и их ручек никогда не пересчитывает шумодав: он считается один раз и
кэшируется. Незагружаемый плагин пропускается, а его имя и причина видны в панели.
**Дорожка голоса на стыках монтажа** идёт дублёром `<audio>`, повторяя решение видео на
стыке (видео подменено дублёром — голос тоже; видео прыгнуло seek — голос ждёт `seeked`), а
дрейф гасится скоростью (±6 %), не перемоткой. Инвариант: дублёр играет тот же файл, что
живая дорожка, — иначе на очередном стыке зазвучал бы голос предыдущего клипа.
**Ползунки громкости** — **Громкость** в панели (то же `voice_db` стиля клипа, что ползунок
**Голос** на шагах 2–3) и громкость прослушивания в строке плеера. Оба действуют и на
живой звук плагинов: громкость хоста = громкость голоса спикера (дБ) + громкость
прослушивания. Живой хост играет на частоте устройства и при сбое сообщает об этом в
панель, возвращая звук странице; «Настроить» открывает окно уже звучащего хоста, закрытие
окна звук не рвёт, а закрытие превью снимает хост.
**Нарезка** слушает голос после ВСЕЙ цепочки спикера: шумодав (если включён) и включённые
плагины — тем же кодом, что вывод. Сбой плагина — нарезка по дорожке шумодава, затем по
сырому звуку.
**Звук превью, граф и браузер.** Граф Web Audio превью будит ОДНОЙ дверью (`audioWake`) из
обработчика нажатия каждого плеера, а звук камеры уходит в граф только когда есть что
обрабатывать (дорожка обработанного голоса, живой хост плагинов или громкость голоса не 0).
Спикер без обработки поэтому играет звук камеры напрямую и от состояния звука в браузере не
зависит. Firefox не декодирует PCM (`pcm_s16be`) внутри MP4 вовсе, в отличие от Chromium;
пока превью играет исходник, плеер говорит об этом своей строкой — «Firefox не читает звук
этих камер — звук появится с прокси», — и строка эта по ФАКТУ
(`<video>.mozHasAudio === false` после 1,5 с игры), а уходит сама, как только играет
видео-прокси (в нём дорожка aac). Отдельного ЗВУКОВОГО прокси НЕТ: прежний играл поверх
звука камеры в Chromium и убран. Рекомендуемый браузер — на Chromium (Chrome, Edge, Brave).
Поддержку VST3 даёт необязательный пакет `pedalboard`; без него панель голоса работает, но
плагинов нет, звук камеры играет как есть, а список устройств вывода приходит от звуковой
системы с напечатанной причиной.
**Ограничения / цена:** нужны NVIDIA и пакет с моделью шумодава (`RoFormer`); окно плагина
во время звука — поверх остальных окон.
**Code:** `core/voicefx.py`, `core/voicefx_editor.py`, `static/app/60-preview.js`

### Раскладка камер

**Где:** шаг 1 (строка клипа) › окно раскладки камер.
**Как:** 1. Откройте раскладку для клипа. 2. Клик по строке перематывает на этот кусок.
3. Поменяйте камеру у куска. 4. Нажмите **Сохранить раскладку**.
**Настройки:** легенда и полоса показывают, какая камера видна на каждом куске.
**Сбросить на авто** возвращает автоматическую раскладку. Плеер ниже играет монтаж, а

### Камера 1: анимация зума, наезды в тейках и на хайлайтах

**Где:** шаг 3 › стиль › **Кадр** › **Камера 1** › **Анимация зума**.
**Как:** 1. Выберите режим: **наезд с откатом (плавно)**, **резкие скачки 100–140%**,

**Настройки:** «Анимация зума» — три независимых блока: **В начале ролика** (галка + масштаб),
**На склейке** (нет / наезд с откатом / скачок / скачок + дрейф, масштаб от–до одной строкой)

со знаком «+»; диапазон «от > до» меняется местами сам. В **резких скачках** масштаб на
каждом кате прыгает на случайное число между **Возвраты от, %** и **Возвраты до, %**.
**наезд в начале** открывает ролик плавным подъездом от **Первого наезда, %** к первому
скачку, а не случайным числом в кадре 0. **Внутри длинного куска** добавляет наезд в каждом
куске длиннее порога — при ЛЮБОМ типе склейки, не только на скачках: камера подъезжает,
держит **Держать, с** и отъезжает; цикл сжимается под короткий кусок (запас, отступ,
подъезд/отъезд, удержание), а не влезает и сжатый — наезда нет, камера не остаётся
приближенной. **Хайлайт** — наезд на выделенные слова (жёлтые слова ролика и выделенные
цветом слова интро): подряд идущие слова считаются ОДНОЙ фразой, подъезд начинается за 0.1 с
до первого слова, удержание — до конца последнего плюс **Держать, с**. Отъезд ставится,
только если целиком помещается до склейки: иначе камера держит приближение до ката.
**Только сильные жёлтые** — наезд не на каждую фразу, а на самые сильные (см. «Сила
жёлтых»). **Ограничения / цена:** у **Держать, с** в коротком куске удержание короче.

### Интро: несколько слов в строке, привязка к камере, межстрочный интервал

**Где:** шаг 3 › стиль › **Текст** › **Интро**.
**Как:** 1. Задайте **Межстрочный интервал, %** (100 — обычное расстояние). 2. В группе
**Текст › Задний план** задайте **Межстрочный заднего плана сверху, %** и **Межстрочный

**Настройки:** интро работает одинаково и при включённом режиме строк (**слов в строке**), и
без него: его слова вырезаются из субтитров, а кегль берётся тот, что был бы у субтитров без
автоподжатия длинных строк, поэтому в режиме строк интро не выходит мельче. Поля разложены по
трём группам: **Transform** — общие **Масштаб интро, %**, **Межстрочный интервал, %**,
ручки большого слова, **Интро по горизонтали** и галка **интро едет с камерой**; **Камера
1** — **Интро по вертикали** и **Якорь интро, камера 1**; **Камера 2** — **Интро на кам2 Y**
и **Якорь интро, камера 2**. **интро едет с камерой** держит интро на нуле Камеры 1, и оно
наследует зум, сдвиг кадра и слежение за головой; снятая галка оставляет интро и затемнение
под ним стоять в кадре, а группу подгоняет под ширину кадра — и вверх, и вниз, тогда как
привязанное интро она только ужимает; группу с ручным масштабом не трогает ни то, ни другое.

**Отступ от краёв и масштаб — у каждой камеры свои.**
**Отступ от краёв, %** (`intro_margin` / `intro_margin2`, 0…30, по умолчанию 4) — зазор с
КАЖДОЙ стороны кадра, из него выходит доля ширины `1 − 2·margin/100`; **Масштаб интро, %**
(`intro_fit_max` / `intro_fit_max2`, 100…1000, 250) — потолок УВЕЛИЧЕНИЯ, без него одно
короткое слово раздувалось до 667–819 % кадра, а ужатие не режется. Обе ручки видны всегда:
у группы на перебивке берутся ключи `*2`, решает это одно место (`plan_intro`). Раньше
ширина и потолок были одни на обе камеры, а привязанное к камере интро ужималось под
константу — одна фраза выходила на кам1 и кам2 разного размера. После подгонки блок
опускается по своему фактическому верху, вместе с большим словом, и никогда не
поднимается выше безопасной линии кадра (`INTRO_SAFE_TOP`, 285 px из 1920): до правки
опускание считалось до автофита, и верх крупной откреплённой группы забирался до 164 px
при линии 285. **Межстрочный интервал, %** множит расстояние между
строками интро.
**Межстрочный заднего плана сверху, %** (ключ `back_step`, 10–300 %, по умолчанию 65) задаёт
шаг до строки заднего плана и между такими строками; **Межстрочный заднего плана снизу, %**
(`back_step_after`) — шаг от строки заднего плана к обычной строке под ней; оба — долей от
того же межстрочного интервала. Ручек две, потому что видимые зазоры зависят от слов
(строчные буквы, хвосты) и одним числом их не выровнять; стиль без нового ключа берёт
значение «сверху», поэтому сохранённые стили выглядят как раньше. Прежние «Шаг заднего
плана» с минимумом по чернилам букв и «Зазор малых строк» убраны; оставшийся в сохранённом
стиле `back_gap` выкидывается при загрузке стиля.

**Гашение к субтитру.** Блок интро, стоящий на уровне субтитров (по вертикали) и
переживающий следующий субтитр, гаснет ровно к нему: за **Быстрый фейд перед субтитрами, с**
(`intro_sub_fade`, 0.15). Правило включено по умолчанию, выключает его галка **Интро гаснет
к субтитру** (`intro_sub_cut`). Последняя группа ролика не трогается — держится до конца,
как раньше. Появление, которое не успевает доиграть до начала спада, сжимается, но не
короче 0.1 с. **Фейд-аут интро, с** (`intro_fade`) — про другое: он сдвигает начало спада,
а не момент исчезновения.

**Тень прекомпа интро: непрозрачность в процентах.** **Непрозрачность тени, камера 1, %**
(`intro_comp_shadow_opacity`) и **камера 2, %** (`intro_comp_shadow2_opacity`) — 0…100, где
100 % это тень в полную силу. Ручки назывались «Прозрачность» и имели подпись «%», а держали
СЫРОЕ значение AE 0..255: выбранные «50 %» давали 20 %, а дефолт 68 (27 %) выглядел как
«68 %» и читался как «тень ничего не даёт». В проценты переводит одно место
(`core/xml2ae/plan_style.py`, `opacity*255/100`) — из него число берут и `.jsx`, и превью.
Старые стили мигрируют при чтении как `op/255*100` (68 → 26.7, 31 → 12.2, 255 → 100), так
что уже собранные ролики сохраняют свою тень; личные файлы стилей при этом не
переписываются, а при дефолтах собранный `.jsx` побайтово прежний. Цвет тени
(**Заливка тени**, `intro_comp_shadow_fill`), сдвиг и мягкость — рядом, в тех же группах.

**Большое слева.** Галка в строке интро ставит эту строку — одно слово или несколько — слева
крупно, а остальные строки группы собирает стопкой справа, по левому краю. Большое слово
стоит на базовой линии последней строки стопки, а высота считается по стопке: от верха
заглавных первой строки до этой базы, умноженная на **Большое выше стопки, %**
(`intro_big_over`, по умолчанию 110; при 100 верх большого слова вровень с верхом стопки).
Хвосты букв (Ц, Д) свисают ниже базовой линии, как в типографике. Появление не меняет
размер слова: анимация растит его от базы слоя, поэтому большое слово остаётся большим.
**Зазор до большого слова, px** (`intro_big_gap`, 40) — расстояние между большим словом и
стопкой;
**Межстрочный стопки, %** (`intro_big_step`, 80) — шаг строк стопки, от общего межстрочного
он не зависит. Раскладка считается один раз, и превью с After Effects берут одни и те же
числа. **Верх такой группы держится на месте:** раньше при ужатии блок держался за базовую
линию и уезжал ниже соседних групп (владелец видел это как «группа ниже остальных»), теперь
верх блока совпадает с верхом той же группы в ОБЫЧНОЙ раскладке
(`layout.intro_big_top_shift`, по самой верхней строке). Мельче такая группа остаётся по
геометрии — это горизонтальный блок в той же ширине, — а крупнее её делает меньший отступ
от краёв. В группе с несколькими галками большой будет первая; в группе из одной строки
большого слова нет. Ролик без такой строки собирается побайтово как раньше.

### Рендер без открытия After Effects

**Где:** шаг 3 › **Собрать и отрендерить**, плюс поле папки вывода рендера.
**Как:** 1. Отметьте клипы. 2. Нажмите **Собрать и отрендерить**. 3. Следите за прогрессом
и ETA. 4. Кнопка **Остановить** прерывает прогон.
**Настройки:** папка вывода по умолчанию — `exp` рядом с репозиторием, её же можно задать
в профиле спикера. Набор из нескольких клипов всегда становится одним проектом AE с одним
мастер-скриптом и одним запуском `aerender`; одиночный клип идёт прежним путём. **Сколько
копий AE собирают проект** задаётся в ⚙ › **Инструменты** › **After Effects**
(`ae_build_workers`, по умолчанию «авто»): набор собирается несколькими копиями `AfterFX`
параллельно, каждая — свою часть клипов, а потом одна копия сливает части в один проект;
«авто» берёт min(3, число клипов, свободная память / 10 ГБ), «1» возвращает прежний путь.

After Effects забирает почти всю память, Windows уходит в подкачку, а рендер идёт медленнее
(на замере 361 с против 290 с). На этапе
«сборка проекта в AE» при наборе из нескольких клипов видно «N из M», какой ролик собирается
сейчас и ETA, а уже собранные ролики в очереди стоят со стадией «собран, ждёт рендера».
Времена фаз прошлых прогонов запоминаются, и ETA со временем становится точнее.
**Ограничения / цена:** After Effects должен быть закрыт: открытая копия перехватила бы
безголовый прогон, поэтому джоб отказывается стартовать. Есть сторож простоя, а мгновенный
выход AfterFX распознаётся как «ушёл в открытую копию». Ротоскоп считается во время
сборки и это самый долгий её этап.

## Ограничения

- Проверено только на Windows 11 с видеокартой NVIDIA и Adobe After Effects / Premiere
  Pro. Заметки о переносе на другие платформы: [docs/PLATFORMS.md](PLATFORMS.md).
- Цвет (Lumetri) в превью браузера — приближение: настоящие формулы Lumetri закрыты,
  поэтому превью показывает направление правки, а не точный результат.
- Tritone не ставится на яркий цвет жёлтого интро (яркость выше 0.7): на таком цвете он
  выбеливает свечение вместо того, чтобы его докрасить. Тёмные цвета акцентов его
  по-прежнему получают.
- У двух установленных шрифтов может совпасть PostScript-имя. Тогда сборка пробует копии и
  берёт ту, что действительно встала; если не встала ни одна, текст собирается шрифтом по
  умолчанию, а в лог уходит имя отвергнутого шрифта.
- Экспорт в Premiere XML и в `.drp` содержит известные дефекты:
  [docs/KNOWN_ISSUES.md](KNOWN_ISSUES.md).
- Статус бета-версии: структуры настроек и проектов могут меняться между релизами.
