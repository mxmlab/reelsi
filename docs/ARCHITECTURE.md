# Reelsi — архитектура, как что работает, роадмап

## UI-контракт пакетного мастера

UI организован вокруг пакетного прохода из трёх шагов: нарезка, разметка и сборка
After Effects. Открытие отдельного клипа в предпросмотре необязательно и служит
точечной проверке. На шаге AE галочки задают пакет (пустой выбор означает весь
набор), а sticky-панель после #clips3 запускает сборку или рендер одного и того
же состава. Выбор режима JSX и действие «Только текущий» остаются локальными
ускорителями и не меняют пакетную семантику.

Импорт Google Drive — первый, но свёрнутый блок шага 1; его gdrive_* id являются
частью UI-контракта. Спикер хранится в clip.job.speaker и редактируется
компактным раскрывающимся контролом в строке AE-клипа.

## Что это и куда движемся

ИИ редактор, работающий поверх **Adobe Premiere + After Effects**.
Автоматизирует рутину монтажа коротких вертикальных роликов (talking-head, мультикам
1–4 камеры). Всё считается локально на GPU, ничего не грузится в облако.

Ядро — **ИИ-монтаж**, уже прикрученный и работающий:

- **нарезка** — основной движок **GigaAM whole-file** (`core/gigaam_cut/`): одна модель
  слушает ролик целиком и отдаёт слова с таймингами, LLM (27b) решает, что выкинуть,
  а код добивает механику. Один пайплайн совмещает всё, что классика делала
  отдельными модулями: тишина, дубли-пересъёмки, вздохи, кашель и «кхе» — плюс
  подгон резов по звуку и раскладка камер;
- **разметка** — `core/aicut/`: жёлтые слова, вставки (семантический подбор по базе либо
  ИИ-генерация картинки/видео), интро;
- **сборка** — `xml2ae + styles + roto (RVM)` → `.jsx` для After Effects.

Стратегия прежняя: **каждый день убираем по кусочку ручного труда**. Ручным
остался только творческий конец — доводка в Premiere; от камер до рендера AE
(включая безголовый рендер без открытия After Effects, задание BD) всё
автоматизировано.

Важно: сам каталог проекта (папка уровнем выше `reelsi/`) — **не git-репозиторий**.
Репозиторий — это
папка **`reelsi/`** (свой `.git`, ветка `main`). Правки кода и коммиты — здесь.

## Пайплайн (сверху вниз)

Синим — Python-инструменты (авто), жёлтым — ручная работа, серым — файлы:

1. **Камеры 1–4** (`.mp4/.mov`, папки `камера1`, `Камера2`, …) — вход.
2. **Reelsi · вкладка «Нарезка»** → основной движок `core/gigaam_cut/`:
   `sync → GigaAM whole-file → 27b решает → пост-проход → подгон по звуку →
   вздохи/кашель → assign → xmlbuild` (+ черновик `.draft.mp4`).
3. **XML для Premiere** — за один прогон вырезано всё: тишина, дубли,
   кашель и вздохи; мультикам сведён (субтитры-графика строятся на шаге 2
   «Разметка» по готовому XML).
4. **Reelsi · вкладка «Разметка»** → `core/aicut/` (LLM): жёлтые слова, вставки
   (по базе или ИИ-генерацией картинки/видео), интро.
5. **Premiere — финальная доводка** (руками, по желанию; правки редактора
   запоминаются в `user_overrides` и учитываются при пере-нарезке).
6. **Reelsi · вкладка «After Effects»** → сначала **план сцены** (`/api/scene`,
   вся арифметика сборки без `.jsx` и рото), предпросмотр шага 3 рисует его в
   браузере и принимает правки перетаскиванием; затем
   `xml2ae + styles + roto (RVM)` → `.jsx` из одобренного плана.
7. **Рендер** — безголовый: кнопка «Рендер» собирает проект и гонит `aerender`
   (только Windows, см. `api/render.py`); вручную AE для этого открывать не нужно.

Ручным остался этап 5 (и то опционально) — творческий конец. Захода в After Effects
в пайплайне больше нет: там осталась только отдача рендера.

## Два движка нарезки

### Движок 1 — GigaAM whole-file (основной, пакет `core/gigaam_cut/`)
Запуск через кнопку «ИИ-нарезка» на стр. 1 либо кастомный запуск со ступенями
через модалку «Кастом». Вход через `core/omni_cut.py` (по умолчанию `gigaam`). Движок ASR
выбирается в настройках (`active_cut_asr`, только движки с флагом `cut: true`).
Один пайплайн совмещает всё, что классика делала отдельными модулями, — подробно ниже.

### Движок 2 — классика (legacy: VAD + Whisper, `reelsi.process_pair`)
Осталась для совместимости и доступна через ветку VAD (ступень «Паузы» = `loud`):
`sync` (аудио+синхрон) → `vad` (вырезка пауз по уровню громкости) →
опционально `transcribe` (Whisper large-v3, кэш `<src>.words.<md5>.json`, загружается
только при включённой чистке дублей) → `align` (удаление повторов-дублей, раскладка мультикама) →
`xmlbuild` (Premiere FCP7 XML). Выход: нумерованные `NN_stem.xml` в `Reelsi_out`.
Субтитры нарезка не делает ни в одной ветке (их строит шаг «Разметить всё» по готовому XML).

### Устройство движка 1 — как GigaAM режет
GigaAM v3-CTC слушает ВЕСЬ файл и сам отдаёт пословные тайминги
(`word_timestamps=True` — текст и тайминги из одной модели, wav2vec2/forced-align
НЕ используется). Слушаем окнами ~18с (`_transcribe_words_manual`, win=18/search=6):
шов кладём в самую тихую точку последних `search` секунд, чтобы рез между окнами
не попал в слово, `torch.cuda.empty_cache()` после каждого окна (на Windows WDDM
иначе — access violation). **pyannote-longform выпилен 2026-08-10**: гейтед-веса
`segmentation-3.0` + виндовые баги pyannote/speechbrain — остался только оконный
фолбэк (он же был запасным и раньше: окна ~24с со швом в самой тихой точке).
Дальше 27b видит весь пословный текст (слова без номеров — позиция задана самим
текстом) и возвращает
drop-диапазоны (дубли заходов, NG-пересъёмки, паразиты); тишина > 0.8с режется
всегда автоматически (как VAD). Пороги — константы в `core/gigaam_cut/tune.py`
(SILENCE_SEC/MIN_KEEP/REPEAT_N/REPEAT_WIN и остальные; `GAP`/`PAD` выпилены).

Пакет с 2026-08-06 (был один файл на 2310 строк): `tune` — пороги и всё, что их
читает; `takes` — дубли и пост-проход кодом; `asr` — транскрипция и выравнивание;
`decide` — промпты решения; `pipeline` — оркестратор `run()` (модуль `seams`
«швы и сверка с черновиком» выпилен 2026-08-10 вместе с петлёй самопроверки).

`tune` собран не по теме, а по ОГРАНИЧЕНИЮ, и это надо знать, прежде чем растаскивать
его дальше: `apply_speaker` пишет пороги прямо в globals ЭТОГО модуля, поэтому
`from .tune import SNAP_DB` в соседнем модуле дал бы значение по умолчанию,
связанное один раз, — профиль спикера перестал бы действовать молча, без ошибки.
Все читатели переписываемых порогов лежат в `tune`; кому порог нужен снаружи, тот
берёт его через модуль (`tune.SILENCE_SEC`), а не по имени. По той же причине
СПИКЕР-МЕНЯЕМЫЕ пороги не переэкспортируются на фасад пакета (фасад отдаёт
остальные константы — см. `core/gigaam_cut/__init__.py`): обращение к профильным —
`gigaam_cut.tune.SNAP_DB`.

**Чем модель отвечает — один режим `markup`.** (Режимы `index`/`quotes` и
`AUTOCUT_DECIDE_MODE` выпилены 2026-08-10 как неиспользуемые.)
Модель видит ВЕСЬ текст ролика и возвращает его целиком, заключив в `[ ]` то,
что выкинуть (`decide_markup` + `parse_markup` + `align_markup`): позиция реза
задана самим текстом, арифметики нет, а решение видно глазами прямо в логе.
Выравнивание на наши слова — difflib; где модель переписала/пропустила слово,
оно ОСТАЁТСЯ (молча резать то, чего модель не показывала, нельзя), покрытие
пишется в лог. Замер на C1353-1356: совпадение 100% на всех клипах. markup не
требует от модели ни арифметики, ни самоцитирования — она просто расставляет
скобки в тексте, который ей дали. Пост-проход остаётся включённым и в нём
(`REELSI_LIGHT_POST=1` — только механические чистки): даже с размышлениями
модель то снесёт все три захода разом («чтобы не дать» ×3 -> осталось
«разрушить луковицу»), то дорежет продолжение. Когда модель права,
`force_takes` принимает то же решение и ничего не меняет.

**Пост-проход кодом (`postprocess`, добавлен 2026-07-22).** Ключевой вывод из
разбора нарезки C1353: 27b — ОДИН вызов на весь ролик, и она НЕ УМЕЕТ считать
индексы. В `notes` пишет всё верно («оставляем последний чистый заход»), а в
`drop` кладёт соседний диапазон: оставляла ранний заход дубля, обрубок слова у
реза («питание воло | волосяных»), островки в 1-2 кадра, а один раз снесла
интро-хук целиком (drop 0-44 вместо 14-20). Промптом это не лечится, поэтому
МЕХАНИЧЕСКАЯ часть решения забрана у модели в код, а ей осталась смысловая
(что мусор, что оффтопик, что NG). После `decide_markup` идут:

- `find_takes` — детект ФАЛЬСТАРТОВ: начало сегмента дословно повторяет начало
  недавнего (>=2 слов, с поправкой `_same`/`_lev1` на обрубки «воло»/«волосяных»
  и опечатки ASR «фолликулы»/«фоликулы»). Ищем повтор НАЧАЛА, а не заходы равной
  длины: спикер переснимает как получится, период непостоянный. Окно `TAKE_WIN`
  = 12с — дальше это уже не пересъёмка, а осмысленный повтор. ПЕРЕЧИСЛЕНИЕ
  фальстартом не считается — см. `align.is_enumeration` ниже;
- `force_takes` — внутри кластера остаётся ПОСЛЕДНИЙ заход, что бы ни решила 27b.
  Если модель выкинула кластер ЦЕЛИКОМ (так делает режим цитат — она честно
  перечисляет все три захода), последний заход ВОЗВРАЩАЕТСЯ: на C1355 иначе
  пропадала вся история «ещё пять лет когда я ездил в штаты выступать». Не
  возвращаем только блоки с мат/NG-маркерами (`NG_MARKERS`) — там модель права.
  Чистовой заход дотягивается `_take_tail` до ПАУЗЫ, а не до границы кластера:
  граница — это лишь место, где кончилось совпадение с брошенным заходом
  («используем его уже» совпало, «очень давно» уже нет);
- `veto_unique_drops` — по краям каждого вырезанного диапазона отматывает слова,
  не входящие ни в один кластер, и возвращает такой хвост, если он длинный
  (>=5 слов и >=1.5с). Настоящий брак заканчивается пересъёмкой, поэтому лежит
  в кластере; уникальная связная речь — не дубль, её резать нельзя;
- `heal_fragments` — 27b оставила начало фразы и дорезала короткое продолжение
  («и список» без «самых опасных», «а с» без «максимальным»): если КОРОТКИЙ
  (< `HEAL_SEG`) оставленный кусок упирается в короткий вырезанный хвост, которого
  нет ни в одном кластере, — возвращаем хвост. Паразиты из `FILLERS` не тащим:
  их модель выкидывает правильно;
- `dedupe_repeats` / `dedupe_fragments` / `drop_truncated` — добивка остатков
  (соседний повтор → РАННЯЯ копия; осколок не вплотную → ПОЗДНЯЯ копия, текст
  не меняется; слово-префикс следующего);
- **гейт перечислений `align.is_enumeration`** (2026-08-04, жалоба «вырезается
  перечисление»): «где он сделал вот это, А где он сделал другое» — начало
  повторяется дословно, и `find_takes`/`dedupe_fragments` видели тут фальстарт,
  снося всё до второго вхождения. Перечисление опознаётся по ДВУМ признакам
  сразу: перед вторым заходом стоит союз-связка (`ENUM_LINKS`) И у первого есть
  СВОЙ содержательный хвост (не паразит и не обрубок слова, которое сейчас
  прозвучит целиком). Кандидат перед проверкой раздвигается ВЛЕВО: детектор
  цепляется за середину повтора («он сделал» вместо «где он сделал»), и союз
  иначе оказывается внутри совпавшего куска. Гейт общий на все пути — тем же
  пользуются `align.find_restarts` и текстовый гейт SSM (`ssm.text_has_repeat`),
  правило продублировано в промптах нарезки;
- `drop_micro_keeps` — ОДНОСЛОВНЫЙ кусок короче `MIN_KEEP` = 0.6с (два слова
  подряд — уже контент: «во вторых» занимает 0.56с) и любой кусок короче
  `MIN_ISLAND` = 0.35с («а с» = 0.20с — мусор при любом числе слов).

`NG_MARKERS` работают ТОЛЬКО в путях возврата: код никогда не воскрешает мат и
NG-реплики, которые модель выкинула, но и не режет мат, который она оставила
(герой матерится по делу — это контент). Резать по словарю пост-проход не умеет
в принципе.

В режиме разметки код НЕ переигрывает решение модели (инвариант 2026-09-08):
пост-проход поверх ответа LLM включается только ступенью «Правка нарезки кодом»
(ключ `dedupe`, по умолчанию выключена); при выключенной ступени `postprocess`
сам переходит в light-режим и делает единственную чистку — `drop_micro_keeps`
(микро-островки в 2-3 кадра). Почему: замер на пяти роликах 2026-09-08 — модель
дала 18 верных вырезов, код добавил 6 своих и все 6 оказались ошибочными
(`force_takes` и `dedupe_repeats` резали перечисления и ролевую речь «это же
укольчик», «да я привык мне нормально на прогресс не влияет»), а
`veto_unique_drops` вернул обратно верно вырезанный оффтопик в конце ролика.

**Подгон резов по звуку (`refine_keep`, 2026-07-22).** Всё выше работает с ТЕКСТОМ,
а жалобы были про звук: «остались места без звука и вздохи» и «обрезаются немного
слова». Замер на C1353/1355/1356 подтвердил обе: внутри оставленных кусков
набегало 6-8с тишины (паузы короче `SILENCE_SEC` порог не проходят), а резов,
попадающих ВНУТРЬ слова, было 28-30 на клип — CTC даёт границу с точностью ~40мс.
Поэтому после сборки интервалов идёт проход по самому wav:

- **границы по звуку, а не по фиксированному отступу**: от края слова идём до
  КОНЦА ВОЛНЫ в пределах `EDGE_IN_MAX`/`EDGE_OUT_MAX`. Замер: звук тянется после
  «конца слова» по CTC у 62-83% слов (медиана 80-120мс, до 400мс), поэтому
  фиксированные 100мс — это одновременно «отступ везде» и обрубленные хвосты.
  Теперь у «выступать» добор 25мс, а у «давно» — 211мс. Конец волны = ЗАТИШЬЕ,
  `QUIET_RUN` тихих кадров подряд (2026-07-28): по первому же тихому кадру рез
  садился в провал ВНУТРИ волны — смычку перед «п/т/к», стык слогов — и слово
  звучало обрубленным. Тем же `QUIET_RUN` меряются хвосты слов в маске речи,
  иначе добранный хвост волны маска считает дырой и вторая ступень вырезает его
  обратно, посреди спада. Затишья может и не быть вовсе (следующее слово
  начинается сразу — вырезанный дубль) — тогда, как и раньше, встаём в САМОЕ
  ТИХОЕ место: иначе рез садится на атаку чужого слова и слышен его огрызок.
  Слово принадлежит куску, только если его СЕРЕДИНА внутри: по касанию
  подтягивалось соседнее слово, которое юзер намеренно вырезал (до 600мс);
- **начало куска — от ВХОДА ВОЛНЫ, а не от CTC-старта** (`_start_edge`, 2026-07-31).
  Жалоба: «начало бывает обрезает не на полной тишине, руками много довожу». Разбор
  C1414 показал корень: CTC-старт слова гуляет относительно звука на ±150мс в ОБЕ
  стороны. У «я» он опоздал на 160мс — окно `EDGE_IN_MAX` упиралось в сплошную волну,
  затишья нет, запасной «самый тихий кадр» садился на атаку слова; у «транболлона»
  опередил на 130мс — в это время шумел вдох, и рез садился на вдох, хотя настоящая
  тишина была ПОЗЖЕ CTC-старта. Поэтому вход слова ищем по звуку: голос — громче
  `ONSET_DB` над полом и не тише пика слова минус `ONSET_FALL` (вдох/шум комнаты на
  реальных клипах 12-18 дБ, речь 30-45), тихую атаку добираем назад до `ATTACK_MAX`,
  отступаем `START_PAD`. Сверка с ручной доводкой юзера (8 клипов, 179 кусков):
  медиана расхождения с его границей 60 -> 20мс, стартов, севших на звук, 19 -> 7,
  и в 6 из 7 оставшихся он и сам режет по звуку (сплошная речь, тишины там нет).
  Число кусков и содержание не меняются — уходит только лишний воздух (~1с на клип).
  МАСКУ РЕЧИ (ниже) на вход волны НЕ переводили: там цена ошибки выше — на тех же
  клипах маска по волне срезала начала тихих слов («клеточная», «поэтому») и они
  уходили в дыру как вдох;
- **дыры без речи**: вдохи, «кхе», чмоканье и стук GigaAM НЕ транскрибирует, и это
  их и выдаёт — звук есть, а слова на нём нет. Маска речи строится по словам с
  запасом `WORD_PAD`, всё вне её длиннее `HOLE_MIN` режется, по краям остаётся
  `HOLE_AIR` воздуха. ВАЖНО: маска расширяется по ЗВУКУ, а не жёстким padding-ом —
  иначе тянущаяся буква («давно» звучит ещё 200мс после конца слова по CTC)
  считается неречью и вырезается, то есть ровно то, что просили не резать. Спектральные пороги (доля энергии >3кГц) пробовали — маска
  слов надёжнее: кашель бывает громче речи и по громкости не ловится.
  **ТИХИЕ кадры маска речью не считает** (2026-07-31): и добор волны, и `WORD_PAD`
  легко уезжают в паузу (CTC-конец слова часто за краем волны), а замаскированная
  пауза переставала быть дырой и оставалась в куске. Разбор ручной доводки юзера
  (6 клипов): из 40 участков, которые он вырезал руками, 22 были именно такой
  тишиной — теперь они уходят сами, ценой 0.22с чужого (и то тишины). Порогу
  тишины при этом верим, только если он ниже медианы голоса на 6 дБ: `floor` —
  20-й перцентиль клипа, и на плотной речи он уезжает в саму речь.
  Слышимые вздохи и «кхм» этим не берутся (громкостью и долей ВЧ от хвоста слова
  они не отличаются — замер: распределения пересекаются полностью, кашель бывает
  громче речи) — для них отдельный модуль `core/breath.py`, см. ниже.

**Пороги сняты с РУЧНОЙ нарезки юзера** (`NGAutoCut_out/0{1,2,3}_C135{4,5,6}`), она
здесь эталон. Что показал разбор его файлов: внутри его кусков нет ни одной дыры
>= 0.20с (максимум 1-2 участка по 0.15-0.19с) -> `HOLE_MIN = 0.15`; границы он
ставит за ~25мс до слова и через ~82-117мс после -> `EDGE_IN_MAX`/`EDGE_OUT_MAX`. Первая
версия искала «самую тихую точку в окне +-150мс» и разжимала его плотную нарезку
на +2с — от неё отказались. Проверка: `refine_keep`, применённый к его же кускам,
не меняет их число и длину (+-0.5с), границы расходятся на 33-41мс (2 кадра при
60fps). А если склеить его куски в смысловые блоки (как их отдаёт ИИ) и прогнать
подгон — получается его же дробность: 18->24 при его 24, 13->19 при его 21,
12->21 при его 23. То есть «много кусков» — это норма: паузы и вдохи внутри фразы
режутся, и один смысловой блок превращается в 1-2 куска.

**Вздохи и «кхе» (`core/breath.py` + `tools/train_breath.py`, 2026-07-31).** Отдельный шаг ПОСЛЕ
подгона резов — потому что тут работают внешние модели, которых может не быть в
окружении, и падать из-за них посреди джоба нельзя (`available()` -> нарезка идёт
как раньше). Три источника, каждый о том, в чём силён:

- **Silero VAD** (~2 МБ, ONNX, CPU) — «речь / не речь» на каждые 32мс, 1с на ролик;
- **CED-tiny** (AudioSet, 5.5M) — участок **в изоляции** (кладём в середину 10с
  тишины). Речь от не-речи отделяет идеально (AUC 1.00), длинные вздохи зовёт
  Gasp/Breathing. ГОТЧА: CED отдаёт УЖЕ вероятности, `sigmoid` поверх схлопывает
  всё в 0.5. Тайлинг участка вместо тишины даёт периодический гул -> «Music»;
  скользящее окно по ролику бесполезно (AUC 0.53) — соседняя речь забивает окно;
- **акустика** — громкость, доля ВЧ, длительность, место в куске, паузы вокруг.

Ни один признак по отдельности вздох от хвоста слова не отличает (лучший AUC 0.84),
поэтому решает **градиентный бустинг**, обученный на РУЧНОЙ ДОВОДКЕ юзера:
`project.json` новее `cuts.json` = ролик правили руками, и разница между
автонарезкой и его версией — готовая разметка (34 ролика, 3787 кандидатов, 240
удалённых им участков). Модель уезжает в прод РАЗОБРАННОЙ в `data/breath_model.json`
(пороги и листья деревьев): sklearn нужен только для обучения. Оценка честная —
пороги подбираются на N-1 роликах и меряются на отложенном: p>=0.9 -> 22% находок
при точности 73%, p>=0.7 -> 41% при 50%.

Отсюда ДВЕ рабочих точки, а не одна: `P_CUT` (0.95) — режем сами, `P_MARK` (0.5) —
пишем в `<stem>.breaths.json`, редактор нарезки рисует оранжевую полоску, клик по
ней вырезает участок (`/api/breaths`, `edBreathAt`/`edCutRange` в `app/70-editor.js`). Плюс
жёсткая страховка `SPEECH_MAX`: вероятность речи выше 0.25 не режем НИКОГДА, какой
бы ни была уверенность модели — ложная метка бесплатна, ложный рез стоит слова.
Разбор ложных срабатываний подтвердил гейт: у них вероятность речи 0.04, то есть
это тоже не речь, юзер просто не стал чистить.

Переобучение: `python tools/train_breath.py` (кэш wav+слов в `_breath_cache/`,
34 ролика ~30с на транскрипцию). Каждая правка нарезки в редакторе добавляет
разметки — модель имеет смысл переобучать по мере накопления роликов.
Цена в нарезке: ~1.6с на ролик (Silero 1.0с + CED 0.5с), плюс разовая загрузка
моделей.

Функция возвращает ещё и `parents` — из какого исходного куска получился каждый
новый. **Раскладка камер при этом не меняется**: `assign_cameras` считается ДО
подгона, по смысловым кускам, а подкуски наследуют камеру родителя. Иначе камера
прыгала бы прямо на вдохе посреди фразы (соседним кускам она всегда даёт разные
камеры). Тесты: `tests/test_refine_keep.py` на синтетическом звуке
«слово · пауза · КХЕ · пауза · слово».

Слова, возвращённые починкой швов, передаются в `protect`, иначе итерации
самопроверки зацикливаются. Тесты: `tests/test_gigaam_postprocess.py` — там же
эталон юзера на реальном куске C1355 (`fixtures/c1355_takes.json`): четыре
захода подряд, ручная разметка «выкинуть 32-58 и 68-91, оставить 59-67 и
92-100», и три теста проверяют, что код приходит к ней из любого стартового
состояния — модель ничего не выкинула / выкинула всё / оставила ранний заход.
Правило «из повторов остаётся ПОСЛЕДНИЙ заход» продублировано и в
`DECIDE_MARKUP_SYS` — оно было в `core/omni_cut.py`/`aicut`, но потерялось при
переносе на пословный путь, из-за чего нарезка и брала первый дубль.

Петля самопроверки (GigaAM переслушивает вырезку/черновик, `max_iter`,
`compare_draft` с restore/drop) выпилена 2026-08-10: на практике делала хуже.
Самопроверка стыков осталась отдельным шагом `core/selfcheck.py` (флаг джоба
`selfcheck`, движок — `--selfcheck-model`). Субтитры тем же путём: `core/gigaam_subs.py` (сабпроцесс,
чтобы OOM не убил Flask) через `core/asr_backends.py` — общий реестр движков
(Whisper любого размера / GigaAM / Omni / CTC-модели других языков из
`data/asr_engines.json`).

### Профили спикеров (`core/speakers.py`, `speakers/*.json`)

> Спикеры здесь и дальше называются буквами: **A**, **B**, **C**, **D**. Это реальные
> люди, и их акустика, манера дышать и число переснятых дублей — данные о них, а
> не о проекте. Цифры сохранены полностью, имена — нет. Соответствие лежит
> локально в `docs/speakers-calibration.md` (в `.gitignore`); в UI селектор
> «Спикер» показывает те имена, которые ты дал файлам в `speakers/`.

Пороги `gigaam_cut.tune` — не универсальные константы, а калибровка по спикеру A.
Замер `_envelope` по реальным клипам: у него речь звучит на **39.5 дБ** над
шумом комнаты (разброс 4 дБ по 7 клипам), у спикера C — на **28.8 дБ** (разброс
14 дБ), а на одном клипе запас всего 21 дБ, то есть жёсткий `ONSET_DB = 20`
(«голос = громче 20 дБ над полом») проходит ВЫШЕ медианы его речи. Следствие
видно в огибающей: непрерывные куски «выше порога голоса» у спикера A медианой
0.39с, у спикера C — 0.12с и 90% короче 0.35с. Речь для кода рассыпается на
осколки, `refine_keep` режет «дыры» между ними, `drop_micro_keeps` добивает
остаток. По ручным правкам это ровно и видно: восстановлений на клип у спикера A
0.74, у спикера B 1.0, у спикера C 2.25, причём 6 из 18 его восстановлений длиной
0.32-0.50с вообще не значатся в `.cuts.json` — их убрал не LLM, а `MIN_KEEP` /
`MIN_ISLAND`.

Профиль = JSON в `speakers/` (gitignored, как и `styles/`): папка результата
(`outdir`), папка для собранных `.jsx` (`jsxdir`), пресет AE, оверрайды порогов
(`speakers.CUT_DEFAULTS` — полный список), поправка к промпту решения (`hint`),
приписки к промптам генерации картинок (`image_prompts` — слоты a и b) и
референсные кадры под будущее автоопределение. Выбирается селектором «Спикер» на
шаге 1; выбор ставит ОБЕ папки и стиль, уезжает в `omni_cut --speaker` и пишется
в `.project.json`. Папку из профиля не подставляем молча поверх ручной: пусто или
папка другого спикера — меняем сразу, своё — спрашиваем (`spkDir` в
`app/95-styles.js`, одно правило на обе папки).

Заводится и правится профиль тут же, окном рядом с селектором (`openSpeaker` /
`saveSpeaker` в `app/95-styles.js` → `/api/savespeaker`, `/api/delspeaker`). Два правила,
которые в этом окне нельзя нарушать, иначе оно молча портит данные:

- **сохраняется КОПИЯ профиля**, а не собранный из полей объект: в файле есть то,
  чего в окне нет (`ref`, `breath_model`), и пересборка это стёрла бы;
- **порог, равный общему, в файл не пишется** — пустое поле показывает дефолт
  плейсхолдером. Иначе «профиль без правок» получил бы шестнадцать «своих»
  порогов, и следующая правка общих констант до него бы не дошла.

**Стиль AE в профиле — значение по умолчанию, а не привязка.** Выбор спикера
ставит его стиль, дальше на шаге сборки стиль меняется свободно и в профиль не
возвращается: у одного человека несколько стилей (одна камера / две / другой
шрифт), и стилей всегда больше, чем спикеров. Чей стиль стоит сейчас, видно на
шаге 1 в сводке нарезки и рядом с селектором стиля (`styleSpeakerNote`).

**Разбор по всем троим (`project.json` → `user_overrides` как эталон, пословные
тайминги сняты GigaAM на 11 клипах) — вывод для каждого РАЗНЫЙ:**

| | восстановлений/клип | из них по порогам | удалений/клип | что удаляет |
|---|---|---|---|---|
| Спикер A (19) | 0.74 | 1 из 14 | 2.68 | вдохи внутри кусков (пик +19.6 дБ) + смысл |
| Спикер B (17) | 1.00 | **0 из 17** | 3.71 | разговоры с оператором, переснятия |
| Спикер C (8) | 2.25 | **6 из 18** | 2.50 | речь (уровень 25.5 дБ при речи 28.0) |
| Спикер D (18) | 1.78 | **17 из 32** | 0.89 | паузы 0.31–0.90с без текста (дыры под `hole_min`) |

- **Спикер C — порог.** Четыре из шести «порожных» восстановлений оказались
  словами («трехста», «сохраняйте», «читайте») длиной речи 0.52-0.60с, то есть
  островками короче `MIN_KEEP=0.6`. Плюс низкий запас речи. Правится цифрами.
- **Спикер B — смысл.** Пороги у него не ошибаются НИ РАЗУ, хотя акустически он
  ближе к спикеру C, чем к спикеру A (запас 25.6 дБ, 85% кусков «выше порога
  голоса» короче 0.35с). Низкий запас сам по себе поломки не даёт — это важно:
  `db_auto` не надо включать всем подряд «за компанию». Его лечит `hint`.
- **Спикер A — вдохи.** Его паузы внутри кусков не тишина, а вдохи: маска речи
  продлевает слово ПО ЗВУКУ, вдох прилипает к слову, и дыры для кода там просто
  нет — опускать `hole_min` бессмысленно. Лечит детектор вздохов, но общий порог
  `P_CUT = 0.95` на нём слишком осторожен.
- **Спикер D — порог `hole_min`.** 17 из 32 его восстановлений — паузы 0.31–0.90с
  с ПУСТЫМ текстом (медиана 0.54с), то есть дыры без речи, а не слова: их вырезал
  код, а не LLM. Оверрайдов в профиле не было (`"cut": {}`), работали дефолты,
  снятые со спикера A. Цена порога по 200 вырезанным дырам в его 18 роликах:

  | `hole_min` | вернётся дыр | лишнего воздуха на ролик |
  |---|---|---|
  | 0.15 (дефолт) | — | — |
  | 0.45 | 17 | 0.23 с |
  | 0.75 | 23 | 0.43 с |
  | **0.95** | **41** | **1.29 с** |
  | 1.20 | 61 | 2.48 с |

  Поставлено `hole_min = 0.95`: при нём переживают все семнадцать возвращённых
  пауз (максимум 0.90с), цена — 1.29с лишнего воздуха на ролик. Вторая половина
  жалобы (14 из 32 режет LLM) — задание CA.

**Метрика «рез посреди слова»** (доля границ кусков после `refine_keep`, попавших
внутрь слова) — по ней и подбирался `hole_min` спикера C: 25.1% у него против 8.1%
у спикера A и 18.1% у спикера B; `hole_min` 0.15→0.22 роняет её до 13.5%, вместе с
`db_auto` — до 11.3%, и при этом ни одной лишней дыры >0.31с не остаётся. На
спикере A ни один перебор порогов ничего не меняет (8.1% при любых) — ещё одно
подтверждение, что дефолты это его калибровка.

**Детектор вздохов: личным должен быть ПОРОГ, а не модель.** Обучил по каждому
отдельно (`train_breath.py --speaker`) и сверил leave-one-clip-out на одних и тех
же 44 клипах: общая модель ловит 25% вздохов при точности 76%, три личные вместе
— 21.8% при 74%. Данных на одного мало (906-2725 примеров против 4914), а
признаки вздоха оказались не такими личными, как звучание голоса. Зато сильно
разъезжается КАЛИБРОВКА вероятностей: при общем `P_CUT = 0.95` детектор берёт у
спикера A 18 вздохов из 151, у спикера B 23 из 91, у спикера C 9 из 75. Порог под
точность 75% на отложенных роликах: спикер A 0.88 (31 из 151), спикер B 0.95 (как
есть), спикер C 0.84 (19 из 75) — вдвое больше пойманного при той же цене
ошибки. Поэтому в профиле живёт `breath_p_cut`, а `breath_model` оставлен на
будущее (когда у спикера накопится сравнимый объём).

Пороги кладутся в МОДУЛЬНЫЕ константы `gigaam_cut.tune` разово в начале `run()`
(`apply_speaker`) — читают их полтора десятка функций по всему файлу. Из-за
этого пороги, которые были дефолтами аргументов (`thr=SILENCE_SEC` и т.п.),
переведены на `None`: дефолт связывается при импорте и профиля не видит.

`db_auto` считает пороги громкости от РЕАЛЬНОГО запаса речи в клипе, а не в
абсолютных дБ: `snap = 0.30 × запас`, `onset = 0.50 × запас`. Доли не выдуманы —
это те же 12/20 дБ, пересчитанные на запас спикера A 39.5 дБ, поэтому на его
материале формула возвращает 12.0/19.9 и ничего не меняет, а у спикера C опускает
пороги до 6-10 / 10-17 дБ по клипу. Включается профилем, по умолчанию выключен.

Дефолты в `speakers.CUT_DEFAULTS` продублированы с констант `gigaam_cut.tune` —
расхождение означало бы, что «спикер без правок» молча меняет нарезку. Сверяет
`tests/test_speakers.py` (он же проверяет, что каждый порог из списка реально
доезжает до константы).

### Движок 3 — «After Effects» (финальный Premiere XML → `.jsx`)
Сборка идёт в ДВА шага, чтобы предпросмотр шага 3 видел ровно те числа, что уйдут
в AE (задания A–E, правило «у любого значения один источник»):

1. **`scene_plan()`** (`core/xml2ae/build.py`) — вся арифметика сборки БЕЗ рото и записи:
   наезд и дрейф камеры, ключи вставок, интро-группы (окна `ts`/`te`, смещения
   `dx`/`dy`, масштаб `ds`), субтитры, визуальная подпись ролика (`caption` из `<stem>.caption.json` по стилю пресета — плашка + текст), рото-разметка, `audio` (громкости + окна
   цензуры). Отдаётся как план через `/api/scene`; превью рисует только его, ничего
   не досчитывая (`scene_plan` живёт ДО рото — предпросмотр не трогает GPU).
2. **`to_ae_full()`** = план + рото (RVM-альфа персонажа, GPU) + подстановка в
   JS-шаблон `AE_FULL` → запись `.jsx`. Отдельно `build_combined()` склеивает
   несколько файлов в один `.jsx` (набор → «один на всё»).

**Безголовый рендер** (`api/render.py`, задание BD). Кнопка «Рендер» на шаге 3
собирает проект (`AfterFX.exe -noui -r …jsx` — с `app.project.save` и без `alert`,
только в этом режиме) и отдаёт очередь рендера в `aerender.exe`; прогресс парсится
из stdout в лог джоба. Только Windows: поиск AE идёт по `%ProgramFiles%\Adobe`
(`_find_ae` — единый источник для `api/render.py` и `doctor.py`), пресеты вывода
привязаны к установленной версии. Отмена джоба убивает процесс `aerender`, чтобы
тот не остался висеть фоном.

**Два пути рендера.** Набор из ОДНОГО ролика — `_run_render_single`: безголовый `.jsx`

Строка интро (`introRowHtml` в `static/app/60-preview.js`, `job.introRows`, `PVW.intro`, `INTRO`) настраивается независимыми селекторами:
- **Цвет (`color`, `fill`):** `white` (белый), `yellow` (в UI — «хайлайт»), `accent` (акцентный цвет стиля), `custom` (произвольный RGB с палитрой `<input type="color">`). В строках интро слова отображаются цветом хайлайта стиля `var(--introhl, var(--subhl, var(--yel)))`;
- **Анимация появления строки (`anim`):** `""` (плавный фейд), `up` (вылет снизу), `left` (слева), `right` (справа), `glitch` (текстовый глитч через посимвольное мерцание непрозрачности букв без подмены символов, повторяя Text Animator AE с `Opacity=0`, `Randomize Order=1`, seed 10), `reveal` (раскрытие: посимвольный каскад скейла от 0 до 100% слева направо с размытием). Опция `count` из селектора `anim` удалена;
- **Эффекты (`fx`):** `""` (нет) или `glow` (эффект свечения `Glo2` со сложением в экране);
- **Шрифтовые роли:** `accent` (акцентный шрифт и регистр из стиля) и `back` (задний план с масштабом 69% и шрифтом `back_font`);
- **Счётчик числа (`is_count`, `cnt_words`):** ставится на КАЖДОЕ слово-число строки независимо (`isNumberWord`), у каждого такого слова — свой чип `123` (`.icnt`). Позиции слов со счётчиком хранит `cnt_words` — список позиций внутри строки (`0..count-1`), `is_count` всегда равен `cnt_words.length>0`. Задания без `cnt_words` читаются как легаси (счётчик на первом числе строки), и первый клик по другому числу материализует список (`[p0]` → `[p0, p]`). Клик трогает ТОЛЬКО свою строку: прежнее правило «один счётчик на интро» отменено. Ручной инпут точности в UI скрыт — число знаков после запятой (`dec`) считается автоматически по тексту числа: для целых чисел (например, 100, 1500) `dec=0` (`Math.round`), для чисел с дробной частью через точку или запятую (например, 2.5 или 2,5) `dec=1` (`.toFixed(1)`), для 3.14 — `dec=2`. В After Effects (`core/xml2ae/build.py`) `Slider Control` (0 → целевое число за `HL_DUR`) и выражение на `Source Text` независимы от строкового `anim`: на слово-число со счётчиком штатно накладываются строковые анимации (`glitch`, `reveal`, `up` и т.д.) и эффекты (`glow`). В пословном режиме план отдаёт `cnts` (`[[позиция, цель, выражение, dec], ...]`), и КАЖДЫЙ слой слова-числа получает свой `Slider Control` и своё выражение — счётчики одной строки не конфликтуют; скаляры `cnt`/`expr`/`dec`/`cnt_idx` равны первому элементу `cnts` и обслуживают строчный режим (один текстовый слой — один счётчик, только первое число строки).
- **Пять дверей синхронизации:** данные строк интро обязаны синхронно и без потерь пробрасываться через все точки входа и выхода: `pvwOpen` (шаг 1), `pvwCommitIntro` (шаг 1), `selectAE` (шаг 3), `captureAE` (шаг 3), `aiIntroAllRun` (пакетный ИИ-интро) и `resolveIntroFor` (резолв в сборку). Поля `count, color, fill, anim, fx, dec, is_count, cnt_words, break, from, gx, gy, gs, accent, back` сохраняются во всех дверях.
- **Покадровый предпросмотр в веб-плеере (`static/app/85-inserts-view.js:ipvIntro`):** точное воспроизведение анимаций и стилей интро без открытия After Effects. Расчёт ведётся покадрово от тайминга плеера `tm` (в `static/app.css` у `.ipvintro span` отключена задержка `transition: opacity` и включён `display: inline-block`). Поддерживаются кривая `ipvEase` (cubic-bezier 35/90), анимации появления `reveal` (побуквенный каскадный скейл 0→100% и comp blur), `up` (вылет снизу), `left`/`right`, `glitch` (посимвольное мерцание прозрачности букв) и `fade`. Точный базовый масштаб прекомпа интро откалиброван коэффициентом `0.968` (`iSc = 96.8 * gDs / 100` в AE). Счётчик `is_count` интерполирует число от 0 до `cntTarget` за 1.5с с сохранением формата, запятой и пробелов. Цвета (`yellow`, `accent`, `custom` с `fill`, `white`) и свечение (`fx: glow`) соответствуют стилю и плану `scene_plan` (`hl_fill3`, `intro_fill`, `intro_hl_fill`), а для строк `back` учитывается уменьшенный кегль `back_scale` и компенсированный межстрочный отступ.
- **Цвета хайлайтов и разделители стопок:** термин «жёлтые» заменён на «хайлайт» / «хайлайты» по всему интерфейсу. Активные чипы (`.chip.on`, `.chip-cnt.on`, `.icnt.on`) и активные разделители стопок (`.brk.on`) красятся в цвет хайлайта стиля `var(--subhl, var(--yel))` с автоматическим расчётом контрастного цвета текста (`var(--subhl-tx)`). Субтитры при склейке слов (`hl_joins`) группируются в единый контейнер `.pvsubw`, исключая наложение слов друг на друга. Звуки SFX (`pop`) обрезаются по `def_out = 0.1s`. Музыка в превью и рендере привязывается к ролику детерминированным сидом от пути клипа.

**Клип хранит ИМЯ стиля, а не его копию.** В задании живёт `job.styleKey` — имя шаблона
из `styles/`; развёрнутая копия `job.style` остаётся ТОЛЬКО у безымянного кастома
(`__custom__`), которому имени взять неоткуда. Стиль резолвится в момент сборки:
`_norm_build_jobs` (`api/build.py`) — единственная дверь для сборки, рендера и
`/api/scene` — зовёт `styles.resolve(job.style)` (принимает и имя, и словарь) и берёт из
результата `roto`, `roto_bottom`, `music_db`. Рото — свойство СТИЛЯ, а не клипа
(решение 2026-08-22): полей `job.roto`/`job.roto_bottom` в задании больше нет, а нужен
уникальный рото на один клип — стиль сохраняется под другим именем («Сохранить как…»).

Почему именно так: копия стиля в задании была источником рассинхрона. Правка шаблона не
доезжала до готовых заданий — два клипа на одном стиле собирались по-разному, один верно,
второй со старым значением (жалобы 2026-08-21 и 2026-08-22). Разносить правки теперь
нечего, поэтому механизмы разноса удалены: `restyleJobs`, `propagateSpeakerStyle`,
`inheritMissingStyleKeys`, флаг `STYLEPROP` и пометка `styleOwn` (с меткой «свой стиль» в
списке клипов) больше не существуют. Старые задания мигрирует `migrateClipStyles()` в
`loadStyles` (`static/app/95-styles.js`): копия → имя по `styleKey`, иначе по содержимому
(`styleKeyFor`); стиль не узнали — клип честно становится кастомом со своей копией,
настройки не теряются. В сравнении «какой это шаблон» участвуют все поля кроме
`STYLE_LOCAL = ['label']` — рото исключать нельзя: два стиля, отличающиеся только рото,
должны считаться разными.

Предпросмотр (`/api/scene`) шлёт стиль СЛОВАРЁМ (`CURSTYLE`) — намеренно: он показывает
НЕСОХРАНЁННЫЕ правки панели. Сборка берёт сохранённый стиль по имени. То есть предпросмотр
показывает то, что в панели, а сборка — то, что сохранено.

Правится шаблон карандашом у селектора (`editStyle`): открывает те же поля «кастома», но с
уже вписанным именем — иначе имя приходилось помнить и вбивать руками, а опечатка молча
рождала второй шаблон. Встроенным `base`/`geologica` имя не подставляется: файла у них нет,
и перезапись развела бы в списке второй «Базовый».

**`webui.py` — единственный интерфейс.** Файл исторически назывался webui2
(пока жил переходный интерфейс на порту 5000; тот заморожен 2026-07-13, без
бэкенда с 2026-07-17, удалён 2026-07-22), с 2026-08-09 снова `webui.py`.
Интерфейс один — на 5001, порт 5000 больше не поднимается.

## Ключевые правила (больные места системы)

Этот раздел — ключевые точки того, как система реально работает: что ломается
чаще всего и что НЕЛЬЗЯ менять без понимания.

**ПРАВИЛО:** картинки/видео вставок живут в папке `Reelsi_out/` (то есть всегда
рядом с XML). Это контракт: `xml2ae` ищет их по относительному пути.

**ПРАВИЛО:** база вставок (`insertlib`) индексирует ВСЁ в `Reelsi_out` (и в
подпапках) — не только вставки. Если файла нет в `Reelsi_out`, в базу он не попадёт.

**ПРАВИЛО:** картинки вставок для AE: можно `.png`, `.webp`. НЕ `.jpg`
(AE не читает? — проверить).

**ПРАВИЛО:** слоты "1"/"2" вставки — это НЕ два разных файла: это ДВЕ ГЕНЕРАЦИИ
ОДНОГО предмета (два кадра одного и того же — с текстом и без); `insertlib`
индексирует оба.

**ПРАВИЛО:** `user_overrides` — только в `.project.json`, не в `ai_config.json`
и не в `ui_state` (это состояние UI, а не проекта).

**ПРАВИЛО:** `insertlib` — отключаем: в конфиге можно поставить `insertlib=off`.

**ПРАВИЛО:** ai_config — это `ai_config.json` (на сервере), а не `ui_state`
(localStorage) — разные вещи: `ai_config` хранит профили/ключи/настройки моделей,
`ui_state` — состояние интерфейса. Не путать.

**ПРАВИЛО:** правки в AE — `.jsx` собирается по клипу; «Собрать всё» просто
перебирает.

**ПРАВИЛО:** камеры на шаге 3 НЕ разбиваются по трекам (см. «Changed» выше).

**ПРАВИЛО:** карточка вставки "1"/"2" — пакетная генерация только через слот `a`.

**ПРАВИЛО:** `core/verify_jsx.py` ловит ошибки структуры, но НЕ ошибки анимации — для
этого нужен рендер в AE.

**ПРАВИЛО:** самое важное: `xml2ae` жёстко зависит от порядка слоёв в шаблоне —
НЕ менять порядок без пересборки.

**ПРАВИЛО:** `xml2ae` ищет файлы по относительным путям от папки XML — всё должно
быть в `Reelsi_out/`.

**ПРАВИЛО:** `tools/harvest_good.py` — пересбор шаблона/субтитр-блобов из эталонного
XML. Без нужды НЕ запускать.

**ПРАВИЛО:** `core/vad.py` — энергетический VAD, кадры 25 мс / шаг 10 мс, порог =
floor + 18 дБ.

**ПРАВИЛО:** `Nano Banana` (`gemini-2.5-flash-image`) — для фонов и вставок; все
ИИ-настройки в модалке `mbAISettings` (⚙).

**ПРАВИЛО:** картинки вставок для AE: `.png`, `.webp`; `.jpg` — НЕТ.

**ПРАВИЛО:** `GigaAM` — пословные тайминги, `transcribe_words_whole`, а не
`transcribe_whole`.

**ПРАВИЛО:** `_cut_breaths` — вздохи/«кхе»: уверенные режем, спорные помечаем.

**ПРАВИЛО:** видеовставки — только `.mp4`, `.webm`; генерация через
`aicut.video.gen_video`.

**ПРАВИЛО:** генерация слотов "1"/"2" — ДВА кадра одного предмета, НЕ два разных.

**ПРАВИЛО:** `core/styles.py` — пресеты стиля клипа: `base` (по умолчанию),
`geologica`, свои — `styles/*.json` (приоритет: пользователь → дефолт).

**ПРАВИЛО:** рото — только с профилем спикера (`speakers/*.json`), без профиля
выключено.

**ПРАВИЛО:** `xml2ae` не меняет камеры без `insertlib`? — проверить.

**ПРАВИЛО:** `xml2ae` ищет вставки по имени в `insertlib` — файл не
проиндексирован, вставка не найдётся.

**ПРАВИЛО:** субтитры НЕ ставятся на вставки (автоматически их обходят).

**ПРАВИЛО:** `xml2ae` — выходной `.jsx` пишется в `Reelsi_out/` (рядом с XML).

**ПРАВИЛО:** `xml2ae` — путь к `.jsx` — `Reelsi_out/`, а не `reelsi/`.

**ПРАВИЛО:** `xml2ae` — `Reelsi_out/` — единственная папка, где живёт `insertlib`.

**ПРАВИЛО:** `xml2ae` — рото-маски: `roto/` в `Reelsi_out/`.

**ПРАВИЛО:** `xml2ae` — файл пресета стиля: `styles/*.json` (см. выше).

**ПРАВИЛО:** у каждого ключа `styles.BASE` обязана быть ручка в UI. Ручка заводится
в ТРЁХ местах: элемент в `templates/index.html` (вкладка `div#stylepart_*`), чтение в
`fillStyleFields()` (`static/app/95-styles.js`), запись в `stEdit()` — плюс точка
«изменено против родителя» в `updateStyleDiffDots()`. Сторож `tests/test_style_keys_in_ui.py`
проверяет обе стороны: каждый ключ BASE пишется из `static/app/*.js` как
`CURSTYLE.<key>=`, и каждый так записываемый ключ есть в BASE; списка исключений нет —
после задания FB он пустой, и пусть таким остаётся. Цена отсутствия сторожа: девять
ключей (`insert_anim`, `insert_c2_x`, `intro_x`, `cam1_zoom_big`, `cam1_zoom_lo/hi`,
`sub_bg_anim`, `sub_bg_padmin`, `audio_fades`) годами правились только руками в
`styles/*.json` — интерфейс их не знал вовсе.

**ПРАВИЛО:** зависимая настройка видна только при включённом хозяине, и включать/
выключать её надо в ОБЕИХ дверях — в обработчике клика (например `rotoSync()`) И в
восстановлении стиля (`fillStyleFields()`). Одна дверь = баг возвращается после F5:
`fillStyleFields` ставит галку по стилю, а обёртка настроек осталась с display из
прошлой сессии. Так сделаны `st_subbg_wrap`, `st_caption_wrap`, `st_topline_wrap`,
`driftwrap`, `rotowrap` («Устройство рото», «Низ маски», «Рото только на Камере 1»
видны только при включённом «Авто-ротоскопе», задание FG).

**ПРАВИЛО:** `xml2ae` — пресет стиля применяется через `styles.resolve`.

**ПРАВИЛО:** ступени нарезки описаны ОДИН раз — `cutstages.STAGES`; интерфейс рисует галки по ответу сервера, своей копии списка не держит.

**ПРАВИЛО:** ветку нарезки задаёт положение «Паузы», а не отдельный переключатель движка.

**ПРАВИЛО:** годность движка ASR под рез — флаг `cut` в `asr_backends`, а не проверка по имени или `kind`.

**ПРАВИЛО:** субтитры делает шаг «Разметить всё» по готовому XML; нарезка их не делает ни в одной ветке.

**Сборка `.jsx`: этапы и «Стоп»** (2026-08-04). `to_ae_full` принимает `cancel` —
колбэк «нажали Стоп?» — и проверяет его между этапами (`_ckpt`, он же пишет в лог
«· разбор XML / музыка / рото: N кусков / сборка скрипта»), а также ВНУТРИ рото:
`roto.alpha_for_ranges(cancel=…)` смотрит флаг перед каждым куском. Прерванная сборка
кидает `xml2ae.Cancelled` — отдельный тип, чтобы `api._run_build_job` написал
«остановлено», а не «ОШИБКА» с трейсбеком, и **не записал .jsx**; посчитанные маски
остаются в кэше и переиспользуются на следующей сборке. `build_combined` («один .jsx на
всё») получил те же `emit`/`cancel`/`progress`: раньше эта ветка молчала весь прогон
(одна строка на старте, одна в конце) и «Стоп» не проверяла вовсе, а флаг `JOB["cancel"]`
смотрели ТОЛЬКО между файлами — то есть весь долгий кусок досчитывался до конца.

**Папки в панели проекта AE.** В корне — только основные композиции. По бинам
раскладываются: `Камеры`, `Вставки`, `Переходы`, `Рото`, `Аудио`, `Интро` (прекомпы
«текст интро» + интро-SFX) и `Субтитры` (прекомп «Субтитры (текст)»). Механизм —
`bin(name)`/`toBin(item,name)` в шаблоне `AE_FULL`: существующая папка с таким именем
переиспользуется, поэтому в режиме «один .jsx на всё» все таймлайны кладут своё в те же
бины.

## Вход / Выход

**Вход** — камеры 1–4 (`.mp4/.mov/.mxf`), камера 1 — главная (аудио всегда с неё).
`assign_cameras` раскладывает остальные: никогда две одинаковые подряд (исключение
2026-07-22: при 3+ камерах длинный кусок ≥6 с — Камера 1, но только когда повторов
нет); исключения «наименее задействованной камеры» работают грубо, рассчитаны на
4 камеры.

**Путь вывода** — `Reelsi_out/` (папка уровнем выше `reelsi/`), имена `NN_stem.xml`,
сайдкары (`.project.json`, `.cuts.json`, `.omni.json`...).

**Запуск** — `python reelsi/omni_cut.py --out Reelsi_out/NN.xml -cam1 ... --cam2 ...`
**Запуск (webui)** — вкладка «Нарезка» → `python -m webui` — нет, `webui.py`.

**XML-контракты** — Premiere FCP7 xmeml; особенности: таймлайн 60fps; `<clip>` со
`speed:100%`, `alpha: ignore` для субтитров; «технический хвост» в картинках
снимается.

**Память правок пайплайна** — `user_overrides` в `.project.json`: дерево
`{ clip: { restored: [..], deleted: [..] } }` — «возвращено/удалено» в редакторе;
повторный omni_cut жёстко защищает возвращённое и сообщает об этом LLM.

**Забракованные вставки** — `ins_rejected` на клипе → `rejected` в `cmd_inserts`:
промпт + жёсткий фильтр похожих.

**Preflight перед рендером** — внутри `/api/render_run`, до старта AE: проверки
файлов (пропавшие файлы, `.webp`/`.avif`, CMYK, AV1, перехлёсты) и синтаксический
проход `verify_jsx`. Старого отдельного роута `check_before_build` больше нет; при
провале preflight джоб рендера отказывается стартовать.

**Права камер с 2026-07-23** — на шаге 3 нет «главной» камеры: все камеры в наборе,
какая из них «база» для AE, НЕ определяется (упрощение — шаг 3 работает со сборкой,
а не с камерами).

**Сборка `.jsx`** — `xml2ae.to_ae_full()`: `parse_full` (разбор таймлайна) →
`styles.resolve` (пресет стиля) → `roto` (альфа персонажа RVM, GPU) → подстановка в
JS-шаблон `AE_FULL` → запись `.jsx`. Отдельно `build_combined()` сливает несколько
файлов в один `.jsx` (набор → «один за всех»).

**Проверка шага 3** — `core/verify_jsx.py` (без AE), `tools/verify_ae.py` + `tools/ae_inspect.jsx`
(по дампу).

**ПРОВЕРКА AE** — `tools/verify_ae.py` сверяет дамп проекта с контрактами `.jsx`: для
каждого слоя — что он есть в дампе; слои со `speed!=100` или scale 404 — ошибки.

**ГЕНЕРАЦИЯ ВИДЕО** — `core/aicut/video.py`: `VIDEO_MODELS` + живой
`OPENROUTER_VIDEO_MODELS`, валидация запроса (промпт, длительность), генерация:
`gen_video` → API-вызов облачной модели. Этот же путь использует и карточка
видео-вставки; отдельного провайдера или каталога для неё нет.

**ГЕНЕРАЦИЯ КАРТИНОК** — `core/aicut/images.py`: профили генерации картинок (из
`images_profiles.json`), валидация запроса, генерация: `gen_image` → API-вызов.

**САМОПРОВЕРКА** — `core/selfcheck.py`: Whisper по склеенному keep-аудио — высокая
уверенность слова на стыке = норма, низкая = плохой стык; ошибки — в лог, в
`.cuts.json`.

**ЧЕРНОВОЙ РЕНДЕР** — `core/draftrender.py`: 720p без звука, предпросмотр до Premiere.

**ПРОФИЛИ СПИКЕРОВ** — `core/speakers.py` + `speakers/*.json` — пороги нарезки, стиль,
папка под конкретную студию/голос. `.cut` — калибровочные пороги спикера A.

**АУДИО-ФЕЙДЫ** — `audio_fades` (стиль) — фейды ~10 мс на стыках камер, чтобы не
щёлкало.

**СВОДКА ПРАВИЛ** — главные правила собраны в начале документа (см. «Ключевые
правила»), остальные — по разделам. `core/verify_jsx.py` не ловит ошибки анимации — нужен
рендер в AE.

## Контракты данных (важно при правках `core/xml2ae/`)

**Разбор XML (`parse_full`)** — треки видео снизу вверх (`non_sub`). Субтитровый трек
определяется по `effectid == "GraphicAndType"`. Из НЕ-субтитровых: первые, что **похожи
на камеру**, — камеры; остальные (сверху) — вставки (тип по файлу: картинка=фото,
иначе видео). `ncams` — **верхняя граница** числа камер, а не жёсткое число (см. подводные камни).
«Похож на камеру» = не трек картинок И (один файл нарезан на ≥ `CAM_MIN_CLIPS=5` клипов
ИЛИ покрывает ≥40% таймлайна).

**JS-структуры в шаблоне `AE_FULL`** (генерятся Python-ом, читаются JSX в AE):
- `CAM = [{path, name, clips:[[start,end,in,out,enabled,scale],…]}]` — кадры.
- `SUBS = [[start,end,"WORD",hl,row,gend],…]` — hl=1 жёлтое, row=ряд стопки, gend=общий конец связки.
- `ROTO = [{ci,ts,te,cs,scale,mf,mask},…]` — рото-персонаж (luma-матте);
  `ci`=камера, `mf`=во сколько раз маска МЕЛЬЧЕ исходника (4K → маска 1080p, mf=2;
  слой маски в AE масштабируется на `scale*mf`).
- `INTRO_GROUPS = [[{words,color,times},…], …]` — интро по прекомпам (кросс-фейд между группами).
- `INTRO_ON2 = [0|1, …]` — по группе: появляется ли она на перебивке (камера в момент
  ПЕРВОГО слова группы, `_active_cam_at`). Такие прекомпы вешаются на отдельный нул
  «интро на кам2» (устроен как «интро», плюс сдвиг `intro_y2`) — на кам2 кадр другой,
  и текст за спиной ставят ниже, не трогая интро на Камере 1.
- `INSERTS = [{t:"photo"|"video",style:"cam1"|"cam2",media,start,end,scale,sc,mosaic,x,y,mw,mh,sin,noexit,oncam2},…]`;
  `x`/`y` — сдвиг точки покоя в px (у полноэкранного видео — панорама кадра, зажата запасом
  заполнения; у ужатого — свободный сдвиг, как у фото), `sc` — ручной масштаб в % от авто
  (фото: × авторасчёт карточки, видео: × заполнение кадра, 100 = во весь экран),
  `mw`/`mh` — форма маски-карточки фото в % от авторасчёта (100 = как считает JSX сам; у видео
  маски нет), `sin` — с какой секунды файла играть кусок (видео),
  `oncam2` — стиль «Кам 1», но в кадре перебивка (см. `docs/INSERTS_SPEC.md`).
- `CAM1_SCALE = [[frame,percent],…]` — зум Null Камеры 1.
- Стиль: `font, hl_font, hl_bold, hl_fill, sub_fill, sub_case ('upper' | 'lower' |
  'sentence'), intro_font, intro_hl_font, transition,
  transition_sfx, pop, music_db, roto, roto_bottom, roto_device, roto_video,
  insert_style, intro_mode, cam1_zoom ('pulse' | 'jump' | 'drift' | 'none'),
  cam1_zoom_start (bool, дефолт True), caption (bool), caption_font, caption_size,
  caption_fill, caption_x, caption_y, caption_bg (bool), caption_bg_fill,
  caption_bg_op, caption_bg_round, caption_kx, caption_ky, caption_case ('upper' | 'as-is')`
  (см. `core/styles.py`, `resolve()` наследует от `base`; `None` у шрифтов = «как база/как субтитры»).
  `caption` задаёт одиночную визуальную подпись ролика с настраиваемой плашкой-подложкой
  на весь таймлайн (текст берётся из `<stem>.caption.json`). `sub_fill` — цвет базовых субтитров
  `[r,g,b] 0..1` (дефолт `[1,1,1]`, жёлтые берут `hl_fill`), `sub_case` — регистр
  субтитров в сборке AE (в XML и Premiere субтитры остаются капсом).
- Ключи стиля из заданий FE/FC/FF (у всех дефолт = прежнее поведение, `.jsx` не меняется
  ни на байт — это ловит golden-тест): `sub_scale` (масштаб СЛОЯ прекомпа субтитров, %;
  раскладка внутри прекомпа — перенос строк, автоподжатие, шаг стопки — не пересчитывается;
  при ≠100 якорь/позиция слоя переносятся в точку строки `[W/2, POSY]`, иначе `sub_y`
  начнёт врать); `insert_anim` (`'zoom'` | `'rise'` | `'none'`; `none` работает при ЛЮБОМ
  `insert_style` и снимает `wiggle` — дрожание гасится подстановкой `ins_wiggle` в шаблоне,
  а не полем плана); `insert_fx` (`'card'` | `'white'` | `'none'`; `none` снимает и
  тень, и маску-скругление, поэтому поля «Маска Ш/В» в карточке вставки показываются
  только при `card`); `insert_above_subs` (bool; фото-вставки поднимаются над субтитрами
  И над рото — фото поверх всего, включая человека; при стиле «Кам 1» вылет из-за спины
  теряет смысл, это осознанный выбор).

**План сцены (`/api/scene`, задание C).** Тот же счёт, что у сборки, но БЕЗ рото и
записи — то, что рисует предпросмотр шага 3 и из чего потом собирается `.jsx`
(превью ничего не досчитывает, правило одного источника). Черновик контракта:
`{fps, w, h, dur, name, cams:[{ci, path, proxy, segs:[{ts,te,src}]}], zoom:{keys,
ease, fit, hold}, intro:[{group, ts, te, on2, lines:[{words, times}], color, dx, dy,
ds}], inserts:[{ts, te, media, kind, style, oncam2, scale, pos, enter, exit, slack,
anim}], subs:[{s, e, w, color, row, gend}], roto:[{ts, te, ci}], caption:{text, font,
size, fill, x, y, case, bg, bg_fill, bg_op, bg_round, kx, ky}, audio:{voice_src,
voice_db, music_path, music_db, censor:[{ts,te}]}}`. Ключи вставок и интро приезжают
готовыми (`anim`, `ts`/`te`) — превью только интерполирует между ними по паре
влияний `(in, out)` из плана.

**Экранирование:** любую строку в JS кладём через `_js()` — он экранирует `\ " \r \n \t`.
Пути Windows → двойные бэкслэши. Многострочный текст (дисклеймер) — `_js_multiline` (`\n`→`\r`).

## Подводные камни (gotchas — из реальных багов)

- **Тесты JSX обязаны мокать resolver ассетов (2026-08-28):** `core/xml2ae/build.py` резолвит
  переходы и SFX через `assets.resolver()`, который при отсутствии файла возвращает пустую
  строку (отключая слой). Тесты JSX, ожидающие медиа-зависимый слой (например, переходы
  в стеке слоёв), обязаны сами задавать/мокать resolver средствами pytest (`monkeypatch`):
  личные `assets` не являются fixture, и без изоляции тест случайно проходил локально за счёт
  файлов разработчика, но падал на чистом CI.
- **Слой прекомпа и shape-слой масштабируются по-разному (задание FE, 2026-08-25).**
  Формула AE: `экран = Position + (P_local − Anchor) * Scale`. У слоя ПРЕКОМПА локальные
  координаты совпадают с пикселями композиции, поэтому якорь `[W/2, POSY]` ставит центр
  масштабирования ровно в строку субтитров. У SHAPE-слоя (плашка субтитров, `bgLayer`)
  содержимое нарисовано вокруг локального `(0,0)`, и тот же якорь уносит плашку в
  `(162, 343)` — левый верхний угол кадра. Для shape-слоя якорь считается как
  `[0, POSY − bg_y]` (`bg_y` — исходная `Position.y` плашки), а позиция — `[W/2, POSY]`.
  Проверять надо РЕЗУЛЬТАТ по формуле экрана (где окажется центр), а не факт вызова
  `setValue`: тест, проверявший факт вызова, дефект пропустил. Там же: предпросмотр и
  AE обязаны совпадать — плашка в превью лежит ВНУТРИ `#ipvsub` и едет от общего
  `transform: scale()`, поэтому неверный якорь в `.jsx` давал расхождение «в проге одно,
  в AE другое».
- **Кипэлайв провайдера обезвреживает таймаут (2026-08-10).** Симптом: пакетная
  разметка интро «стоит на третьем файле», в логе последняя строка «… 16с · пишет
  ответ: 505 симв.», а вызов идёт двенадцатую минуту. Апстрим OpenRouter замолчал
  посреди ответа, но сам OpenRouter продолжил слать `: OPENROUTER PROCESSING`.
  Единственным предохранителем был `urlopen(timeout=600)`, а он меряет тишину
  **в сокете** — каждый кипэлайв её обнулял, и вызов не отвалился бы никогда.
  Хуже: тик прогресса стоял ПОСЛЕ `continue` для не-`data` строк, поэтому индикатор
  «модель жива» замирал ровно тогда, когда он и нужен. Лечится сторожем по РОСТУ
  ответа (`STALL_MID`/`STALL_FIRST` в `core/aicut/llm.py`), а не по байтам. Общее правило:
  **у стрима таймаут транспорта не считается таймаутом задачи.**
- **Имя `t` в `static/app/` занято функцией перевода (2026-08-10).** i18n-проход
  обернул строки в `t('…')` внутри `ipvUI(t)`/`ipvOverlay(t)`, где `t` — время
  плейхеда: `t('ФОТО')` звало число. Падало молча и в неожиданных местах —
  не таскался плейхед, не работал ползунок, из двух наехавших вставок рисовалась
  одна, кнопка генерации не доходила до `fetch`. Время теперь везде `tm`, элемент —
  `el`; запрет самого имени стережёт `test_nothing_shadows_the_translator_t`.
- **Таймкод исходника: `probe()` спрашивал его только у `v:0` (2026-08-06).** Симптом:
  XML открывается в Premiere идеально, а в DaVinci Resolve нарезка разложена не туда —
  «паузы не вырезаны, вообще не то». Камеры Sony (XAVC) кладут таймкод в служебную
  дорожку `tmcd`/`rtmd`, а не в теги видеопотока, поэтому `ffprobe -select_streams v:0`
  не находил ничего и в XML уезжали нули. Premiere этого не замечает — он берёт медиа по
  `pathurl` и опирается на `pproTicks`; **Resolve позиционирует клипы ПО ТАЙМКОДУ**, и от
  нулей вся нарезка ехала на часы (`C1412.MP4` начинается с `01;57;31;11`).
  Читать таймкод надо из ЛЮБОГО потока или из `format_tags` — `xmlbuild.pick_timecode()`.
  **Точка с запятой + `DF` — правильно, не «чинить»:** сверено с экспортом самого Premiere
  того же таймлайна, там `01;57;31;11` при `ffprobe` `01:57:31:11`.
  Метод, который надо было применить сразу вместо перебора гипотез: **открыть наш XML в
  Premiere и переэкспортировать его же в FCP7 XML** — получается эталон в премьеровском
  диалекте для того же таймлайна, дальше обычный диff. Он показал, что все 299 клипов
  (`start/end/in/out/pproTicks`) и все объявления `<file>` совпадают ПОБАЙТОВО, и
  единственное расхождение во всём документе — таймкод. Тем же диффом снялись ложные
  версии: `in/out` в кадрах 60 при `<file>` 29.97 — это и есть премьеровский диалект,
  Resolve его понимает; `file://localhost/C%3a/…` со строчным hex и кириллицей —
  тоже как у Premiere, менять не надо.
  Старые нарезки чинятся на лету при скачивании: `xmlbuild.fix_timecodes()` +
  `/api/export_xml` (файл на диске не трогаем — его читают редактор, субтитры и `xml2ae`).
  Остаётся два отличия Resolve, которые **не баги** и одинаковы для экспорта из Premiere:
  субтитр-графика (`GraphicAndType`) там всегда офлайн (у неё нет `<pathurl>`; рядом лежит
  `.srt`), а `Basic Motion scale` требует Project Settings → Image Scaling → Mismatched
  Resolution Files → «Center crop with no resizing», иначе Resolve сначала впишет 4K в
  кадр сам и применит наши 50.4% поверх.

- **Предпросмотр играет ПРОКСИ камер, а не исходники (2026-08-06).** Симптом был:
  «на стыке встаёт на треть секунды», причём только на новом материале — старые клипы с
  плотной нарезкой летали. Причина не в коде: H.264 **High 4:2:2, 10 бит** (Sony/Canon;
  файлы `камера1 джаггер` — 3840x2160 rotation=90) браузер НЕ берёт на аппаратный
  декодер. Проверяется одной строкой, гадать не нужно:
  `navigator.mediaCapabilities.decodingInfo({type:'file',video:{contentType:'video/mp4; codecs="avc1.7A0033"',…}})`
  → `powerEfficient:false` (у 4:2:0 8 бит `avc1.640033` — `true`). Софтовый декод 4K даёт
  seek 365 мс медиана / 640 мс максимум; тот же материал в 720p 4:2:0 8 бит — 124/375 мс.
  Лечится `draftrender.build_preview_proxy` + `/api/preview_proxy`: прокси собирается **от
  ИСХОДНИКА**, один раз на файл камеры (26 с и 28 МБ вместо 2.38 ГБ), кэшируется в
  `<outdir>/_tmp/pv_*.mp4` по mtime/size. Правки нарезки его НЕ трогают — этим он
  принципиально отличается от черновика (`render_draft`), который надо пересобирать после
  каждой правки. Три отличия от чернового прокси обязательны: **со звуком** (камера 1 —
  источник звука превью), **fps исходника** (по этому же `<video>` ходит плейхед
  редактора), **гарантированный yuv420p 8 бит**.
  Четвёртое отличие (2026-08-07): **короткий GOP — ключевой кадр раз в ~1 секунду**
  (`-g <fps>`, а не дефолтные 250 кадров = 10 сек при 25 fps). Иначе каждый seek браузера
  (перемотка в редакторе, разбег дублёра перед стыком) гоняет декодер от ближайшего
  ключевого кадра — до 10 секунд видео вперёд — и предпросмотр заикается даже на готовых
  прокси. В ключ кэша добавлена метка формата `:g` (`preview_path`), чтобы до-фиксовые
  прокси гарантированно пересобрались.
- **Размер прокси считается по ДИСПЛЕЙНОМУ кадру, не по закодированному.** Вертикаль
  часто лежит как 3840x2160 с матрицей поворота 90°. По закодированному вышло бы 1280x720
  — вертикаль, размазанная в горизонталь. См. `draftrender._display_dims` (результат
  кэшируется по mtime/size: план прокси считается на каждое открытие предпросмотра и на
  каждый опрос прогресса сборки).
- **Повёрнутый исходник через NVDEC не гоняем ВОВСЕ** — `draftrender._decode_tries`, один
  список заходов на оба прокси (черновой и превью). С `-hwaccel_output_format cuda`
  автоповорот ffmpeg не применяется: `scale_cuda` получает ещё не развёрнутый кадр
  3840x2160, жмёт ландшафт в портрет, а матрица поворота 90° уезжает в выход как есть —
  прокси выходит и искажённым, и лежащим на боку. Коварство в том, что заход при этом
  **успешен** (на 4:2:0 NVDEC работает), поэтому в кэш попадал битый файл, а на CPU-заходе
  тот же исходник давал верный кадр: что осядет в `_tmp`, зависело от того, какой заход
  сработал. Замер на `камера1/C1387-008.MP4` (3840x2160, rotation=90, 4:2:0): GPU-заход
  давал 720x1280 **с сохранённым rotation=90** (то есть показывалось 1280x720, искажённо),
  CPU-заход — 720x1280 без поворота, верно. CPU только ДЕКОД, энкод остаётся на NVENC.
  В ключ кэша повёрнутым добавляется `|rot` (`_rot_key`), иначе до-фиксовый битый прокси
  переиспользовался бы молча; у неповёрнутых ключ не меняется и они зря не пересобираются.
- **Стык в плеере проходится подменой `<video>`, а не seek'ом.** `currentTime=` в момент
  склейки — честный seek декодера (флаш → ключевой кадр → декод вперёд), и звук встаёт
  вместе с картинкой (он с того же элемента). Рядом с камерами живёт **дублёр**
  (`P.spare`, ВНЕ `P.vids` — иначе `camVisual` покажет его отдельной камерой): заранее
  уводится на разбег `PV_PREROLL` перед нужным кадром, за него же до стыка пускается
  вживую немым, на стыке элементы меняются местами. Живой — ВСЕГДА `P.vids[0]`, поэтому
  редактор, звук и `camVisual` о подмене не знают. Не успел — откат на прежний seek, хуже
  прежнего не станет.
  Машина (`bufMake/bufDrop/bufIdle/bufArm/bufRoll/bufTake` + обвязка
  `sparePrime/spareRollAt/spareSwap/spareIdle/spareStop`) **общая на все плееры**:
  подключены монтаж `PV`, редактор `ED`, вставки `IPV`, раскладка камер `CPV`. Держится
  это на том, что цель — абсолютное исходное время (`b.at`), а не индекс в чьём-то списке
  сегментов; поэтому редактор пользуется дублёром монтажного плеера, не заводя своего.
  **Дублёров у плеера может быть несколько — `P.bufs`, по одному на НЕПРЕРЫВНУЮ дорожку.**
  У всех есть слот 0 (ведущая камера, она же таймбаза). В `CPV` при звуке с К2/К3
  добавляется второй, на звуковую камеру: без него её на каждой склейке дёргал
  `cpvSyncAudioCam` (допуск 0.25 с), то есть звук вставал ровно там, где раньше вставала
  картинка. У этого дублёра свой файл (пересоздаётся при смене К1/К2/К3, `cpvAudioBuf`) и
  свой постоянный оффсет `b.off` = `CPV.delta[k]`; после удачной подмены расхождение
  нулевое и синхронизатор молчит сам.
- **Вторичная камера — ВТОРАЯ НЕПРЕРЫВНАЯ ДОРОЖКА, а не спящий кадр (`camApply`,
  2026-08-08, третий заход).** Это та самая жалоба «в предпросмотре с 2 камерами при
  переключении моргание, не точное переключение», и два первых захода лечили симптом:
  держали скрытые камеры на паузе и будили на стыке (не успел декодер → на экране лишние
  кадры ПРЕЖНЕЙ камеры — «мелькает прежняя») либо держали играющими, но правили дрейф
  seek'ом (сама сидка роняет кадр и даёт тот же откат ракурса).
  Верная модель: клип снят одним дублём, синхрон один на весь ролик, значит исходное время
  камеры k = исходное время ведущей + **постоянный оффсет** `P.delta[k]` (`camDeltas`, тот
  же расчёт, что раньше был только у звуковой камеры в раскладке). Отсюда:
  камера играет ВСЕГДА; дрейф гасится СКОРОСТЬЮ (`camTrack`, ±6 % при расхождении >0.04 с;
  seek — только от 0.5 с, то есть при промотке и срыве подмены); склейку она проходит
  СВОИМ дублёром (`camBufs` заводит его каждой камере — обобщение того, что было у
  звуковой). Показ ракурса становится чистой сменой z-index: кадр уже нужный.
  **Прежний ракурс не показывается НИКОГДА** — `camApply` берёт `ci=s.ci` как есть.
  Любое «подождём готовности входящей» — это показ ДРУГОЙ камеры, а цикл идёт 60 раз в
  секунду: «подержим пару кадров» и есть видимая вспышка чужого ракурса. Так и было:
  сперва до 500 мс, потом до 100 мс — жалоба не уходила. Худшее, что допустимо теперь, —
  пара кадров ТОГО ЖЕ ракурса, ещё доигрывающего seek. Одна машина на все плееры: копий
  было три, правки расходились.
- **ГЛАВНОЕ про моргание: дрожат ЧАСЫ, а не показ.** Время монтажа считается от
  `currentTime` ВЕДУЩЕЙ камеры, а на склейке её подменяет дублёр, которому позволено стоять
  в окне `PV_SWAP_LO..HI` (до 0.12 с недобега). Сразу после подмены `t` считается уже от
  него — и на кадр-другой ОТКАТЫВАЕТСЯ за границу куска. `pvSegAt` честно отдаёт предыдущий
  кусок, а в нём прежняя камера: показ прыгал «новая → прежняя → новая». Три правки логики
  показа это пережило, потому что показ работал верно — врал вход.
  Ловится счётчиком, не глазами: на ОДНОЙ смене ракурса «кам» набирал 4 вместо 1 (замер
  пользователя на C1432). Воспроизведение синтетикой — последовательность t
  `−0.30, −0.10, +0.02, −0.06, +0.04, −0.05, +0.10, +0.30` от границы куска давала показ
  `0,0,1,0,1,0,1,1` (5 смен), с запретом хода назад — `0,0,1,1,1,1,1,1` (1 смена).
  Лечение (`camApply`): во время игры по кускам EDL назад не ходим. Назад — это перемотка,
  а она всегда идёт через `*SeekTo`, где `P.vidx` сбрасывается в −1 и запрет снимается.
  В `#ipvstat` для этого есть счётчик «откат»: сколько раз часы пытались уехать назад.
- **Ракурс переключается ПОРЯДКОМ СЛОЁВ, а не прозрачностью (`camVisual`).** Слой
  `<video>` с `opacity:0` композитор вправе не рисовать вовсе, и на возврате в `1` первый
  кадр приходит с запозданием — на экране в этот момент остаётся то, что было под ним,
  то есть ПРЕЖНЯЯ камера. В логах плеера этого не видно вообще (кадры видео тут ни при
  чём), ловится только глазами — и это причина, по которой «моргание» пережило две правки
  логики. Теперь все камеры непрозрачны и всегда отрисованы, меняется только `z-index`:
  видимая — 2, прочие — 1, дублёры — 0 (они играют с опережением и всплыть не должны).
  Держится на том, что камера кроет кадр целиком (`.pvstage video`: `inset:0` +
  `object-fit:cover` + чёрный фон) — стережётся тестом.
  Счётчики честности показа видны прямо в предпросмотре (`#ipvstat`):
  «стык · своп · сидк» — про склейку, «кам · замер» — переключений ракурса и кадров, на
  которых входящая камера ещё доигрывала seek. Замер на шаге 2 (23 сегмента, прокси):
  385 вызовов показа, 13 переключений, **0 показов чужого ракурса**, 13 склеек из 13
  подменой, «замер» 2 кадра.
- **Кадр камеры в предпросмотре AE рисует `<canvas>`, а не CSS-масштаб `<video>`
  (`ipvCamPaint`, 2026-09-08).** `transform: scale()` на `<video>` при плавно меняющемся
  зуме давал горизонтальное дрожание кадра, тем заметнее, чем крупнее наезд. Замерами
  доказано, что данные ни при чём: время монтажа монотонно (0 откатов на 375 сэмплах),
  кривая зума монотонна (0 разворотов на 309 сэмплах), дропов кадров 0, прокси дрожания
  не добавляет (межкадровый сдвиг 0.0156 px против 0.0165 px у исходника). Стенд из трёх
  способов вывода (CSS-scale на видео / canvas / scale обёртки) выбрал canvas.
  Теперь `<video>` остаются ИСТОЧНИКАМИ (звук, дублёры, `camVisual` с его `z-index`) и
  прячутся `visibility:hidden` — НЕ `display:none`: иначе браузер перестаёт декодировать
  кадры. Поверх них `#ipvcam` (`z-index:3` — ниже рото-маски 4 и субтитров 5,
  `pointer-events:none`, иначе ломается выбор точки наезда кликом по кадру).
  Вырезка: `f = max(W/vw, H/vh) · s`, `sw = W/f`, `sh = H/f`, `sx = cx·(vw−sw)`,
  `sy = cy·(vh−sh)` — точка наезда неподвижна (137.35 px и при `s=1`, и при `s=1.35`).
  Два следствия, на которых уже попались: рисовать надо и при `s === 1` (ранний выход
  убран), и по событиям `loadeddata`/`seeked` КАЖДОГО элемента, включая дублёров, —
  иначе после перемотки холст пуст, а раньше `<video>` показывал себя сам. Значение зума

- **Рото v2 — потоковый конвейер (2026-07-14):** v1 (сегмент-файл libx264 → RVM fp32
  seq=2 → 4K PNG-секвенция → libx264) выдавал ~2 fps: GPU простаивал (10–20%), всё время
  съедали PNG на CPU и двойной 4K-энкод; 6-мин ролик ≈ час. v2 в `core/roto.py`: один ffmpeg
  NVDEC-декод (`-ss` ДО `-i`) → pipe → RVM fp16 seq=8 → pipe → ffmpeg NVENC; без
  промежуточных файлов и PNG. Маска в ПОЛОВИННОМ разрешении для 4K (luma-матте хватает),
  фактор в поле `f`/`mf` (см. контракт ROTO). ~25 fps на 4K-вертикали (RTX 4070 Ti S) —
  ~10x. Вертикальные исходники: rotation=±90 в side data → `_probe` меняет w/h местами
  (ffmpeg авто-поворачивает при декоде; без свапа кадр сплющит). Кэш-ключ масок включает
  делитель разрешения — старые v1-маски не реюзятся. env: `REELSI_ROTO_FULLRES=1`
  (полное разрешение маски), `REELSI_ROTO_DEVICE=cuda|cpu`.
- **Черновик через карту — прокси, а не GPU-фильтры (2026-07-21).** Проба `_nvenc_ok()`
  в `core/roto.py` гоняла кадр 64x64, а NVENC такие отвергает («Frame Dimension less than the
  minimum supported value»): проба падала ВСЕГДА и рото молча кодировало 4K в libx264 на
  процессоре. Кадр пробы 256x256. В `draftrender` кодек и раньше был NVENC — грузил проц
  ДЕКОД: `trim` стоит после декодера, поэтому каждый черновик прогонял через него весь
  4K-исходник целиком, а черновик пересобирается на КАЖДОЙ итерации самопроверки и после
  правок. Наивный перенос фильтров на GPU (`-hwaccel cuda` + `scale_cuda`) не помогает:
  `concat` не принимает cuda-кадры, `hwdownload` приходится ставить в каждую ветку, и на
  60 сегментах это МЕДЛЕННЕЕ CPU (замер 5.0 с против 3.8 с). Работает другое — 720p-прокси
  камер (`_build_proxy`: NVDEC + `scale_cuda` + NVENC, кэш `_tmp/proxy_<hash>.mp4`, ключ =
  путь+mtime+размер+геометрия): тяжёлый декод один раз, дальше сборка идёт по 720p
  (3.8 с → 0.8 с при 60 сегментах; на реальном 4K разрыв больше). Фолбэки на каждом шаге:
  NVDEC → CPU-декод (4:2:2 10 бит Sony/Canon NVDEC до Blackwell не умеет), прокси не
  собрался → работаем по исходнику. Отключить: `use_proxy=False` / `--no-proxy`.
- **Переходы — поверх рото и фронт-видео (2026-07-14):** слои «Переход»/«Whoosh» создаются в
  цикле вставок, а рото-бутерброд и подъём фронт-видео (`moveToBeginning`) — ПОЗЖЕ, поэтому
  вспышка перехода горела ПОЗАДИ персонажа и полноэкранной видеовставки («видеоклип выше
  переходов, но под рото»). Фикс: `transLayers[]` собирает переходы, после рото и frontVideos
  они поднимаются наверх. Порядок сверху вниз: дисклеймер → субтитры → НУЛЫ → переходы →
  фронт-видео → рото → интро/фото-вставки → камеры.
- **ВСЕ нулы — в шапке компа (2026-08-11):** подъём нулов был написан поимённым списком
  (камеры → «вставки кам1» → «вставки кам2» → «интро»), и каждый заведённый позже нул в
  него забывали дописать: «вставки кам1 на кам2» и «интро на кам2» оставались закопаны
  между клипами камер, а достать их можно было только прокруткой таймлайна. Теперь после
  явного порядка идёт **добор любого оставшегося нула** композиции (`layer.nullLayer`) —
  новый нул попадёт в шапку сам. Порядок нулов на картинку не влияет: они выключены и
  служат только родителями. В сверке нул опознаётся по флагу `isNull` из дампа
  `tools/ae_inspect.jsx`, а не по имени, и «нул» — свой ярус в `ORDER_PAIRS`.
- **Вставка, срезанная катом, — без анимации выхода (2026-07-14):** ИИ округляет тайминги до
  0.1 c, поэтому конец вставки мог лечь в 1 кадре от смены камеры — строгая проверка «смена
  внутри окна» это не ловила, и фото играло полный вылет поверх сменившегося плана. Фикс в
  `_clip_end`: конец в пределах `SNAP_TOL=0.12 c` от точки смены (фото И видео) → конец
  прижимается к кату, `noexit=true` (у видео это же убирает выходной переход+whoosh).
- **ExtendScript (ES3, старый движок AE):** длинные однострочные массивы норм; ломают
  только управляющие символы в строках. `setTrackMatte` — AE 23+, есть фолбэк на
  `trackMatteType`. Стиль/шрифт задаётся через `Text Document`, `fauxBold` для искусств. жирного.
- **Правило раскладки камер (`align.assign_cameras`, переписано 2026-07-22).** Одна
  функция на все пути (нарезка, редактор нарезки, окно раскладки). Общее для любого
  числа камер: **первый и последний куски — камера 1** (ролик открывается и
  закрывается основным планом). Дальше раскладка РАЗНАЯ по числу камер — это важно,
  правила не путать:
  - **2 камеры** (`_assign_two`) — строгое чередование 1-2-1-2, никаких исключений:
    выбирать не из чего, любое отступление читается как сбой ритма. Чётность:
    чередование от кам1 приходит обратно в кам1 только при НЕЧЁТНОМ числе кусков; при
    чётном ровно в одном месте камера держится два куска подряд (с индекса `p` фаза
    сдвигается, дальше снова чередование, конец опять на кам1). Место сдвойки — пара
    САМЫХ КОРОТКИХ соседей (задержку на коротышах глазом не поймать), первый кусок в
    пару не берём (начало обязано открыться чистой сменой), при равных парах — ближе к
    концу и лучше на кам1 (два коротких подряд со ВТОРОГО ракурса — тот самый паттерн
    кам2-кам2 из аудита). Большие куски здесь НЕ выделяются.
  - **3+ камеры** (`_assign_many`) — прежняя раскладка целиком: БОЛЬШОЙ кусок
    (>= `big_chunk_sec` = 6с) идёт на кам1 (единственный случай, когда камера
    повторяется подряд), возврат на кам1 каждые `return_every` не-первых кусков,
    остальные — наименее занятому ракурсу (2..N делятся поровну). Чередовать здесь
    нечего: ракурсов много, «строго через один» убило бы и большие куски, и
    балансировку. Добавлен только хвост: если последний кусок вышел не на кам1, он
    ставится на кам1, а сдвоившийся предпоследний уводится на свободный ракурс (если
    он не большой — большой на кам1 по праву).

  Тесты: `tests/test_assign_cameras.py`. После ручной правки нарезки раскладка
  пересчитывается сама — `editor_save` зовёт `assign_cameras` и сбрасывает ручной
  `assign` из project.json (блоки-то другие).
- **Раскладка камер НЕ трогает разметку (2026-07-22).** `/api/cams_save` меняет только
  то, чья картинка видна на куске: `keep`-интервалы, их длины и звук (всегда камера 1) —
  те же, значит слова, тайминги и индексы жёлтых не сдвигаются ни на кадр. Раньше
  пересборка шла без `sub_words`, и сохранение раскладки стирало субтитры и жёлтые
  (плюс страшный `confirm`). Теперь читаем их `parse_full`/`auto_highlights` ДО сборки и
  вписываем обратно — как давно делает `swap_cam`. Не путать с `editor_save` (редактор
  нарезки): там `keep` реально меняется, и сброс разметки честен.
- **After Effects не читает webp и avif (2026-07-22).** Импорта таких файлов у него нет
  вовсе — .jsx собирается, а слоя в композиции не появляется. В диалоге выбора файла они
  теперь показываются (их полно в «Скаченном»), а `insertlib.to_ae_image()` на сборке
  перекодирует их в PNG рядом с исходником (альфа сохраняется) — вызов стоит в
  `api._adopt_inserts`, то есть на всех трёх путях сборки, и подменённые пути уезжают
  фронту тем же маппингом `insmoved`, что и переезд файлов в базу.
- **CMYK-JPEG роняет ВЕСЬ .jsx (2026-07-27).** Расширение обычное, AE формат знает —
  но на `importFile` выдаёт «Unsupported video bit depth in source file» и обрывает
  скрипт на первом же импорте: не пропадает один слой, не собирается весь проект
  (случай `09_ng18.jsx` — фото со стока в базе вставок). Смотреть надо ВНУТРЬ файла:
  `insertlib.to_ae_image()` теперь зовётся на каждой картинке, а не по списку
  расширений, и всё, чей режим не из `AE_OK_MODES`, кладёт рядом `<имя>-rgb.png`.
  `core/verify_jsx.py` ловит это же до AE.
- **AV1-видео роняет ВЕСЬ .jsx (2026-08-01).** Та же болезнь, что у CMYK-JPEG, только у
  видео: контейнер `.mp4` знакомый, а поток внутри — нет, и `importFile` обрывает скрипт
  диалогом «The source compression type is not supported» (случай `AutoCut_all.jsx` —
  `videoplayback (12).mp4`, скачанное с YouTube, AV1). Кодек виден только `ffprobe`,
  поэтому `insertlib.to_ae_video()` смотрит поток у каждого видео и всё из
  `AE_BAD_VCODEC` (av1/vp8/vp9/theora) перекодирует рядом в `<имя>-h264.mp4`. Общий вход
  для сборки — `to_ae_media()`, он же стоит в `api._adopt_inserts` вместо `to_ae_image`.
  H.264 многословнее AV1 в 3 раза — отсюда `crf 20`, а не 18. `core/verify_jsx.py` ловит до AE.
- **Масштаб клипа из Премьера ВРЁТ на пережатых файлах (2026-08-01).** `_clip_scale`
  читает Motion>Scale из XML, а он описывает тот файл, что лежал в Премьере. Снято в 4K,
  отдано в AE перекодированным в 1080p — из XML едет `scale=50.4`, и в композиции 1080×1920
  человек встаёт вполовину кадра. Реальный случай (спикер C): юзер полдня чинил
  это руками, прибавляя +98 к КАЖДОМУ ключу зум-нула, а следом ужимая нул «интро» до
  55–60%, потому что интро висит на нуле и росло вместе с ним. Поэтому масштаб Камеры 1
  считается в .jsx от РЕАЛЬНОГО размера исходника (`src.width/height` — AE его знает):
  `CAM1_FIT` = % заполнения кадра, 100 = кадр заполнен ровно, независимо от разрешения
  файла. Рото-копия и её маска считаются от того же числа. Перебивки Камеры 2 по-прежнему
  берут масштаб из Премьера — там он обычно осмысленная рамка кадра.
- **Зум нула множится на заполнение.** Видимый кадр = `CAM1_FIT × CAM1_SCALE`, поэтому
  врезка усиливает и размах зума: на `fit=200` дрейф 100–160 даёт 200–320%. Хочешь прежнюю
  амплитуду — во столько же раз ужми `cam1_zoom_big` / `cam1_drift_hi`. Не пытаться
  сделать `cam1_fit` аддитивной правкой нула: на нуле висят интро и вставки кам1, и любая
  правка нула тащит их за собой. Масштаб на СЛОЕ ничего лишнего не двигает.
- **Верификатор смотрел только ПЕРВЫЙ таймлайн склейки (2026-08-01).** В «одном .jsx на
  всё» структуры повторяются N раз, а `extract_structs` брал первое вхождение `var CAM=` —
  остальные таймлайны ехали в AE непроверенными (та же AV1-вставка сидела во втором, и
  проверка молчала). Теперь `verify()` режет файл по `// ===== следующий таймлайн =====`
  и гоняет проверки по каждому куску, помечая сообщения `таймлайн k/N:`.
- **Windows / регистр путей:** `find_cam_dirs` сортирует папки камер по ЧИСЛУ в имени
  (`камера1` < `Камера2`), иначе регистр мог поменять камеры местами.
- **Жёлтые слова:** авто-подхват цветных слов из Премьера + фолбэк `<stem>.yellow.json`;
  разделитель стопки — по зазору ровно в 1 кадр; палочка `|` между подряд жёлтыми рвёт стопку.
- **Краш arrow.dll при связке torch и детектора вздохов (2026-09-05).**
  В Windows-процессе `arrow.dll` падает с access violation `c0000005`, если `pyarrow`
  загружается после `torch` через цепочку `sklearn → pandas → pyarrow` (её тянет
  классификатор вздохов в `core/breath.py`). Краш оставляет процесс с кодом 0, но калечит
  WinAPI: `subprocess` и чтение файлов выдают мусор. Инвариант: **в любом процессе,
  где рядом живут `torch` и детектор вздохов, `pyarrow` обязан быть загружен до `torch` —
  это делает `import arrowfix` первым проектным импортом точки входа.** Защищены три точки:
  `core/omni_cut.py`, `core/gigaam_cut/__main__.py` и `tools/train_breath.py`. Подробности и замеры — в `core/arrowfix.py`.
- **Геометрия интро-текста: привязка к baseline, строчные буквы и асимметрия шага строк (2026-09-07).**
  В After Effects текстовые слои с центральной выключкой имеют `Anchor Point = [0, 0, 0]`, где
  по вертикали $Y=0$ — это базовая линия шрифта (`baseline`).
  Заглавные буквы (кегль 140 pt при 100% масштабе) растут от baseline вверх на ~100 px (cap-height).
  Строчные буквы при масштабе 69% (`Scale = [69, 69, 100]`) растут от baseline вверх всего на ~48 px
  (x-height $\approx 70 \times 0.69$).
  Поэтому визуальный зазор при одинаковом шаге координат базовой линии резко асимметричен:
  * мелкий текст СВЕРХУ большого: `stp = LINE_STEP * 0.75 = 120 px`. Верх заглавных букв большой строки
    поднимается к $Y_1 - 100$, визуальный зазор равен $120 - 100 = 20\text{ px}$ (плотно и аккуратно).
  * мелкий текст СНИЗУ большого или две мелких строки подряд: при `stp = 120 px` визуальный зазор
    составлял бы $120 - 48 = 72\text{ px}$ (в 3.5 раза больше — огромная дыра).
  Прямой замер эталона `MKnew10.aep` показал, что реальный шаг вниз к мелкой строке составляет ~72 px,
  что в точности равно `BACK_STEP = 0.45` (`LINE_STEP * 0.45 = 72 px`). При шаге 72 px визуальный зазор
  снизу равен $72 - 48 = 24\text{ px}$ (полная визуальная симметрия с 20 px сверху).
  Формула в `core/xml2ae/build.py`: `var stp = LINE_STEP * (GRP[si].back ? BACK_STEP : (GRP[si-1].back ? 0.75 : 1.0));`.
- **Пресеты стиля и защита от устаревшего кэша back_step (2026-09-07).**
  В файле пресета `styles/Спикер M 2 камеры.json` исторически зафиксировалось значение `back_step: 0.75`
  (от первого чернового варианта до замеров эталона). При сборках 1522/1523 стиль спикера перебивал
  дефолт бэкенда и снова генерировал `BACK_STEP=0.75`. Решение:
  1. В `styles/Спикер M 2 камеры.json` выставлено эталонное `back_step: 0.45`.
  2. В `core/styles.py` в функцию `migrate_style_dict` добавлена автомиграция: любое значение `0.75`
     в любом сохранённом JSON стиля на лету переводится в `0.45`.
  3. В `core/xml2ae/build.py` при формировании плана сцены добавлена страховка от legacy-значения `0.75`.
- **Анимация появления интро «reveal» (раскрытие): изоляция аниматора (2026-09-07).**
  Анимация раскрытия в After Effects реализуется исключительно через встроенный текстовый аниматор
  (`Text Animator`: `Scale 3D [11, 11, 91.67]`, `Percent Offset -100 → 100`, форма `Ramp`),
  `Gaussian Blur 26.8 → 0` и `Opacity 0 → 100`.
  Свойство `Transform Group > Scale` самого слоя должно оставаться статичным (`[69, 69, 100]` для `back`,
  `[100, 100, 100]` для базовых строк): анимация ключей на самом `Scale` слоя приводила к нахлысту слов
  друг на друга из-за рассинхронизации между шириной абзаца `lineW` и экранным размером букв.
- **Синхронизация звука глитча интро и параметры Glow (2026-09-07).**
  При `anim == "glitch"` звуковой файл `gltchgltch_24.wav` укладывается на таймлайн строго под каждое слово
  с глитчем с упреждением 17 кадров и хвостом 56 кадров (на 60 fps). Прекомп интро с глитчем получает
  эффект свечения `ADBE Glo2` со значениями Threshold 211, Radius 93, Intensity 0.42 (в точности по `MKnew10.aep`).

## Как запускать / проверять

- Веб: `python reelsi/webui.py` → http://127.0.0.1:5001 (единственный интерфейс).
- CLI ИИ-нарезки (основной движок): `python reelsi/omni_cut.py --cam1 A.MP4 --cam2 B.MP4 --out cut.xml --mode gigaam`
  (режимы `old`/`gigaam`, профиль спикера — `--speaker`).
- CLI классика: `python reelsi/reelsi.py --cams 2|1` (или `--single`, `--no-cut`, `--aggressive`).
- Тесты контрактов: `python -m pytest reelsi/tests -q` (parse_full, set_highlights/
  edit_word + .bak, /api/status, /api/ui_state). Гонять после правок xml2ae/api.
- Правки XML на месте (`set_highlights`/`edit_word`) оставляют `<файл>.xml.bak`
  (оригинал из Премьера, один раз при первой правке).
- **Проверка `.jsx` без AE — `core/verify_jsx.py`** (прежний ручной рецепт «скопировать в
  `.js` и прогнать `node --check`» внутри неё, плюс всё остальное):
  `python -m core.verify_jsx Reelsi_out` — синтаксис, разбор структур
  `CAM/SUBS/ROTO/INTRO_GROUPS/INSERTS/CAM1_SCALE`, пропавшие с диска файлы,
  `.webp`/`.avif` и CMYK-картинки во вставках, несовпадение `t` с расширением файла, перехлёсты клипов
  камеры, `ci` вне диапазона, перенос строки в слове. С `--xml source.xml` дополнительно
  сверяет число камер/слов/вставок с `parse_full`. Гонять после правок `core/xml2ae/`.
- **Сверка того, что реально собралось в AE, — `tools/verify_ae.py`.** В AE:
  `File > Scripts > Run Script File...` > `tools/ae_inspect.jsx` (кладёт `<проект>.inspect.json`
  рядом с .aep, без диалога), затем
  `python tools/verify_ae.py <проект>.inspect.json --jsx <файл>.jsx` — число слов,
  интро-прекомпов, вставок, кусков рото, клипов камер, наличие нулов. Сборка «один
  .jsx на всё» даёт несколько главных компов — тогда нужен `--comp <имя>`. Если .jsx
  от ДРУГОГО клипа (не совпадают файлы камер), это сообщается одной строкой, а не
  десятком расхождений. Порядок слоёв — ПРЕДУПРЕЖДЕНИЕ, не ошибка: канонический
  порядок ниже, но проект правят руками, и перестановка бывает осознанной.
- **Единственная настоящая проверка jsx-анимаций — рендер/импорт в After Effects.** Всё,
  что трогает раскладку/ключи/рото, проверяется только там; проверялки выше ловят лишь
  то, что видно по структуре. После правок кода **старые `.jsx` надо пересобрать** — на
  диске они остаются прежними.

## ИИ-провайдеры: профили (LM Studio / Claude / OpenRouter / OpenAI-совм.)

`aicut` с 2026-08-06 — пакет, а не файл на 2721 строку. Снаружи это по-прежнему одно
пространство имён (`aicut.gen_video`, `aicut.begin_call` — семь десятков имён
переэкспортированы фасадом), внутри:

| модуль | что там |
|---|---|
| `core/aicut/config.py` | профили провайдеров, ключи, таблицы reasoning и кэша промпта |
| `core/aicut/prompts.py` | system-промпты и JSON-схемы ответов |
| `core/aicut/llm.py` | вызов модели: стрим, отмена, поколения вызовов, выгрузка LM Studio |
| `core/aicut/images.py` | генерация картинок для вставок |
| `core/aicut/video.py` | каталог видео-моделей, их возможности, проверка запроса, генерация |
| `core/aicut/commands.py` | сами команды: жёлтые, вставки, интро, план |

Одно следствие, на которое легко наступить: **живые каталоги провайдера обновляются
присваиванием ИЗВНЕ** (`/api/ai_models` после кнопки «Обновить список»), и адресатом
должен быть модуль-владелец — `aicut.video.VIDEO_MODEL_CAPS`, а не
`aicut.VIDEO_MODEL_CAPS`. Присваивание в фасад ложится на пакет, а `video_caps`
читает свои globals: кнопка тихо перестаёт работать.

**Возможности провайдера — из каталога и ответа API, а не из его имени (2026-08-26).**
Имя провайдера в профиле решает ровно две вещи: диалект API (`anthropic` → SDK,
остальные → OpenAI-совместимый `/chat/completions`) и атрибуцию (`HTTP-Referer`/
`X-Title` у OpenRouter). Всё остальное — что модель умеет, есть ли у провайдера
Image/Video API, какие уровни «Ума» показывать — берётся из каталога models.dev
(`aicut/catalog.py::caps`) и из ответов `{base}/models`, `{base}/images/models`,
`{base}/videos/models`. Новая проверка вида `provider == "openrouter"` — почти всегда
ошибка: она чинит один провайдер и ломает всех остальных. До 2026-08-26 так и было:
у профиля со своим URL пустовали возможности моделей, не спрашивались каталоги
картинок и видео, а генерация картинки уходила в `/chat/completions`, где FLUX
отвечает 404.

Две ловушки этого правила:

- `caps(provider, model)` ищет модель по ВСЕМУ каталогу, если под своим ключом не
  нашёл (вендор из префикса id → openrouter → любой провайдер с точным совпадением).
  При таком совпадении **цена гасится** (`cost: None`): у разных хостеров одной модели
  она разная, и показать чужую значит соврать. Точная цена бывает только при
  совпадении под собственным ключом провайдера.
- **Наш слуг `openai` означает «OpenAI-совместимый, свой URL», а НЕ вендора OpenAI.**
  В models.dev провайдер с таким же именем есть, и без отдельной таблицы совпадение
  считалось точным — наружу уходил прайс OpenAI (поймано живым прогоном на
  CommandCode: `gpt-5.6-luna` отдавал 0.2/1.2). Поэтому ключ каталога берётся из
  `CATALOG_KEY`, где перечислены только настоящие вендоры.

**User-Agent обязателен во всех исходящих запросах (2026-08-26).** Дефолтный
`Python-urllib/3.x` режется Cloudflare: у `api.commandcode.ai` и `/models`, и
`/chat/completions` отвечали `403` с телом `error code: 1010`, из-за чего кнопка
«Обновить список» ничего не находила и профиль такого провайдера был нерабочим
целиком. Запросы строит `app_meta.http_req()` — он подставляет `Reelsi/<версия>`,
если вызывающий не задал свой UA (браузерный `_PROBE_UA` для проб чужих CDN в
`core/aicut/video.py` остаётся своим). Голых `urllib.request.Request(` в `core/aicut/`, `api/`,
`core/omni_asr.py`, `core/insertlib.py`, `webui.py` быть не должно — за этим следит
`tests/test_ga_user_agent.py`.

Все LLM-вызовы идут через `aicut._ask_json()` — он резолвит АКТИВНЫЙ профиль из
`reelsi/ai_config.json` (в .gitignore — там API-ключи; нет файла → дефолт LM Studio
из env `LMSTUDIO_URL`/`LMSTUDIO_MODEL`) и диспетчит: `anthropic` → `_ask_anthropic()`
(SDK `anthropic`, streaming + structured outputs через `output_config.format`,
temperature/thinking не передаются); остальные → `_ask_openai()` (OpenAI-совместимый
`/chat/completions`; Bearer-ключ; для OpenRouter — атрибуция HTTP-Referer/X-Title;
400 на `response_format` → один повтор со схемой в system-промпте;
`ensure_loaded`/`unload_ours` — только при `provider=="lmstudio"`).

**Отмена ИИ-вызова = поколение (`aicut.llm.EPOCH`), а не один флаг.** «Стоп» рвёт fetch у
КЛИЕНТА; поток сервера остаётся сидеть в стриме провайдера. Пока была одна глобальная
`CANCEL`, повторный запуск (типовой сценарий: отменил medium-reasoning, поставил off,
запустил заново) ставил `CANCEL=False` — старый поток терял признак отмены, продолжал
жечь провайдера и по завершении дёргал `unload_ours()`, убивая генерацию НОВОГО вызова:
UI «залипал», в логе шёл прогресс старого процесса. Теперь: `begin_call()` (каждый
одиночный ИИ-эндпоинт) и `cancel_call()` (`/api/ai_stop`, `/api/cancel`) увеличивают
`EPOCH` и кладут номер в thread-local; поток проверяет `cancelled()` и умирает сам, если
его номер устарел; `is_current(ep)` гейтит выгрузку модели (устаревший поток и отложенный
unload из `ai_stop` НЕ трогают LM Studio, если поверх уже стартовал новый вызов);
`clear_cancel()` — для вызовов без номера (джоб, `ai_test`, `ai_genimage`: идут пачками,
менять им поколение нельзя). В `api/_core.py` счётчик `AI_ACTIVE`: новый одиночный вызов ждёт
смерти предыдущего до 25с (в логе «⏳ жду завершения предыдущего ИИ-вызова…»).

API (`api/ai.py`): `GET/POST /api/ai_config` (профили, ключи наружу МАСКОЙ `•••xxxx`;
маска при save = «не менял» → ключ сохраняется), `POST /api/ai_test` (мини-вызов
`{ok:true}` → `{ok,ms}`), `POST /api/ai_models` (список моделей провайдера).
UI (webui.py): МОДЕЛЬ выбирается ОТДЕЛЬНО на каждый шаг — селекты
`<select data-prof="cut|yellow|inserts|intro">` («Модель нарезки» на стр.1;
«Модель · жёлтые/вставки/интро» на стр.2, рядом со своим «Ум ·»). Общих
`#aiprofile`/`#aiprofile2` больше нет. Модалка ⚙ `mbAISettings` (CRUD профилей,
автозаполнение Base URL, datalist подсказок моделей, «Проверить», «Обновить список»)
задаёт `active` — теперь это ФОЛБЭК-профиль (шаг без своей привязки берёт его).
Поле `model` из JS-fetch'ей УБРАНО — сервер резолвит профиль ШАГА сам; параметр
`model` в эндпоинтах остался как необязательное переопределение (CLI/совместимость).
По умолчанию в облако уходит только текст (слова+тайминги).

**Модель — тоже НА КАЖДЫЙ ШАГ отдельно** (как «ум», 2026-07-23). Хранится в
`ai_config.step_profiles` (`{cut,yellow,inserts,intro}` → имя профиля), пусто/нет =
общий `active`. Читает `aicut.step_profile(step)`, кладётся в `_ask_json(..., profile=)`
и через `resolve_profile(name=)` перекрывает `active`. Все ИИ-вызовы шага передают
свой профиль: нарезка (`omni_cut`/`gigaam_cut` decide) → `step_profile("cut")`,
жёлтые/вставки/интро → свои. Действие `/api/ai_config {action:"set_step_profile",
step,name}` (пустое `name` = сброс на `active`); переименование/удаление профиля
чинит `step_profiles` (переезд на новое имя / откат на `active`).

**Omni (слух) — тоже профилем**: ключ `active_omni` в ai_config.json (`"__local__"` =
локальная Qwen2.5-Omni-7B, дефолт; имя профиля = облачная аудио-модель). Селект
`#omniprofile` на шаге 1, действие `set_active_omni` в /api/ai_config (anthropic
отклоняется — Claude не принимает аудио; удаление профиля-слуха сбрасывает на local).
`core/omni_asr.py`: тяжёлые импорты (torch/transformers) только в локальном пути;
облачный путь `transcribe_clip_cloud` шлёт чанки ~24с как `input_audio` (base64 wav,
temperature 0) на OpenAI-совместимый `/chat/completions` — работает с аудио-моделями
(Gemini на OpenRouter и т.п.). ВНИМАНИЕ: облачный Omni отправляет ЗВУК провайдеру.
`core/omni_cut.py` при облачном Omni НЕ выгружает LM Studio (VRAM-своп не нужен).

**Фильтр галлюцинаций Omni (omni_cut.py)**: на кашлях/вздохах Qwen2.5-Omni галлюцинирует
связный текст («Это что за шум?», боилерплейт отказа «Извините, но я не могу…») — decide-LLM
видела «речь» и оставляла кашель в нарезке. Три слоя ДО LLM (`halluc_drop`, только
интервалы <2.2с): (1) акустика `voiced_ratio` — нет голосового тона (автокорреляция F0
60–350 Гц, порог <0.12) = кашель; вздох С ТОНОМ даёт 0.3–0.55 и акустикой не ловится —
его ловят (2) повтор одинакового текста на ≥2 коротких интервалах (шаблон чат-приоров;
самообучение в `halluc_phrases.json`, .gitignore) и (3) словарик известных фраз
(HALLUC_SEED + выученные). Плюс в `is_nonspeech`: плотность >25 букв/с (невозможно
физически) и <5 букв на ≥0.8с («Это.» на 1с = вздох). Кэш .omni.json переиспользуется —
перезапуск нарезки применяет фильтр без повторной транскрипции.

**Генерация картинок-вставок (Nano Banana)**: ключ `active_image` в ai_config.json
(`"__off__"` = выкл, дефолт; селект «Картинки (генерация)» внизу модалки ⚙; провайдер
anthropic/lmstudio отклоняется). `aicut.gen_image()` — OpenAI-совместимый
`/chat/completions` c `modalities:["image","text"]`, base64 из
`choices[0].message.images[0].image_url.url`. `/api/ai_genimage {query,dest}` →
`insertlib.add_generated()`: PNG в `<база>/generated/` + запись в индекс БЕЗ рескана
(desc=query, эмбеддинг сразу) → следующие ролики находят автоподбором бесплатно.
UI: кнопка ✨ на карточке фото-вставки + «✨ Недостающие» в модалке вставок (цена и счёт
в confirm ДО запуска, генерация последовательная). Приоритет всегда: база → генерация.
Рекомендуемая модель: google/gemini-3.1-flash-lite-image (~$0.04/шт).

**Генерация видео**: вкладка «Видео» остаётся отдельным raw-инструментом, а карточки
видео-вставок запускают тот же `aicut.video.gen_video` через тот же `VJOB`. Профиль
(`active_video` в ai_config) = провайдер + ключ, а единственные модель и разрешение —
`ai_config.video_model` (`set_video_model`) и `ai_config.video_resolution`
(`set_video_resolution`); все селекторы живут в ⚙ → «Генерация».
Вкладка показывает сводку этого общего выбора и ссылку в настройки, поэтому модель и
разрешение не могут разъехаться между ручной генерацией и вставками. Разрешение —
НЕОБЯЗАТЕЛЬНОЕ поле (пусто/нет = провайдер решает сам); резолвится
`aicut.video_resolution_cfg(model)`: для известной модели с непустыми caps отдаётся
только поддерживаемое (без учёта регистра, наружу канон из caps), устаревшее НЕ
отправляется; неизвестную модель пропускаем. `set_video_model` атомарно сбрасывает
разрешение, несовместимое с новыми известными caps; `set_video_resolution` на известной
модели с неподдерживаемым значением отвечает structured error без записи.
`/api/video_gen` raw и insert берут model+resolution ТОЛЬКО из config/resolver и
игнорируют body `model/resolution/duration/aspect`; `/api/video_models` переоценивает и
сбрасывает устаревшее серверное разрешение (`video_resolution_sync`), возвращая итог.
На вкладке «Видео» `vid_res` — readonly-отображение глобального значения; разрешение не
сохраняется/не восстанавливается/не посылается во фронте.

Карточка отправляет в `/api/video_gen` только `query`, слот `a|b`, ключ спикера и
исходный `insert_duration`. Python добавляет `speakers/*.json -> video_prompts`, выбирает
длительность `ceil(duration_sec)` с зажимом 3…4 с и минимальную допустимую длину модели
не короче цели. Если известная модель не принимает ни одну длину до четырёх секунд,
запрос останавливается до `VJOB` и оплаты; тайминг карточки не меняется. Готовый
`result.path` ставится через `insSetMedia`, а файл позже переносит в библиотеку обычная
сборка. У вкладки и карточки один start/poll: контекст результата показывает плеер либо
обновляет карточку, не создавая спорящий второй poller. Перед стартом карточка сохраняет
opaque-token; VJOB хранит его рядом с ключом и отдаёт в status, поэтому F5 доставляет
`result.path` исходной карточке (не текущему индексу). Transport-ошибка снимает только
локальный busy, а готовый result всегда важнее локального флага отмены.

Контракт OpenRouter Video API АСИНХРОННЫЙ: `POST {base}/videos` → `GET polling_url` до
`completed` → скачать `unsigned_urls[0]` (нужен `Authorization`, несмотря на «unsigned»).
Свой поток и состояние `VJOB` — нарезку не лочит.

- **История задач живёт на СЕРВЕРЕ** (`_videogen/history.json`, `REELSI_VIDEO_DIR` /
  `REELSI_VIDEO_HISTORY` — как `REELSI_UI_STATE`; `/api/video_history`). Генерация
  идёт минутами в облаке, а страницу за это время закрывают и жмут F5 — до 2026-08-05
  переживал только последний результат, остальные ролики оставались на диске
  безымянными, а оборванная задача — незаметной. Запись пишется на КАЖДОМ переходе
  статуса (`running` → `done` \ `error` \ `cancelled`), поэтому убитый сервер оставляет
  след; `vhist_boot()` на старте метит зависшие `running` как `lost`, а id задачи у
  провайдера снимается с лога (`vemit`) — по нему ищут оплаченный ролик, он лежит у
  провайдера ~48 ч. `vhist_scan_files()` подбирает mp4 из `out/`, о которых истории
  нет (сделаны до неё). Удаление записи забирает и файл: иначе он вернулся бы
  следующим же обходом папки. Поля самой вкладки (запрос, референсы, длина,
  разрешение, пропорции, seed, звук) — в общем состоянии UI, ключ `VID`.
- **Каталог моделей двухслойный.** `aicut.VIDEO_MODELS` — встроенные факты о главных
  восьми (снято с живого `/videos/models` 2026-08-05): длины, разрешения, пропорции,
  кадры, звук, seed **плюс то, чего в каталоге провайдера НЕТ ВООБЩЕ** — референсы r2v
  и их лимиты. `video_caps()` кладёт поверх живой каталог (он главнее: по нему
  OpenRouter и валидирует), `video_model_list()` отдаёт объединённый список в выпадашку.
  Поэтому поля страницы перестраиваются под модель СРАЗУ, без сети. Живой каталог
  тянется САМ, в фоне при открытии вкладки (`vidSyncCaps`, бесплатный GET): он
  уточняет ограничения и добавляет в выпадашку остальные модели (Sora, Wan, Runway…).
  Кнопки «проверить возможности» и простыни фактов на странице НЕТ (убраны 2026-08-05
  по требованию пользователя): ограничения не показывают, а применяют — в списках
  только допустимое, неподдерживаемое (seed, звук, роли референсов) выключено.
- **Границы, на которых ловились отказы:** Veo — только 4/6/8 с и 16:9 / 9:16;
  Hailuo 3 — единственное разрешение 2K; Kling 3 — 720p и без seed; Seedance 2.0 —
  4–15 с и ЕДИНСТВЕННАЯ, кто принимает ВИДЕО-референс (до 3 шт, **суммарно ≤15 с**).
- **i2v и r2v — разные режимы.** Кадр (`frame_images`) и референсы
  (`input_references`) вместе не отправляются: OpenRouter молча берёт кадр, ByteDance
  отвечает «first_frame + reference_images conflict». Последний кадр без первого не
  принимается. **Кадр — это КАРТИНКА** (`image_url`): видео, поставленное первым
  кадром, отвергается — в UI у видео-референса роль вообще одна.
- **`video_check()` — предполёт**, полный список того, что до провайдера не долетит:
  длина/разрешение/пропорции по спискам модели, оба правила режимов, по одному
  первому и последнему кадру, счётчики и бюджет референсов, **пустой промпт** (нужен
  всем моделям), **не-https ссылка** (раньше молча выбрасывалась — и юзер платил за
  ролик без своего референса), **ссылка на страницу вместо файла**, **модель не из
  видео-каталога** (в профиле лежала несуществующая). Быстрый прогон (без сети) — в
  `/api/video_gen`, ответом на нажатие; полный (с досмотром ссылок) — в `gen_video`.
- **`probe_media()` / `/api/video_probe`**: HEAD (Content-Type) + ffprobe по ссылке →
  `kind` (image/video/audio/**page**), длина, размер кадра, вес. Тип НЕЛЬЗЯ брать из
  расширения (у ссылок его часто нет, а фото и видео уходят в разные поля), длина
  видео нужна заранее (иначе 400 «video total duration … 15.2 … in r2v» уже после
  отправки), а `page` — самая частая ошибка: адрес страницы вместо прямой ссылки.
  Не открылось — пусто, гадаем по расширению. `resolve_refs()` досматривает КАЖДУЮ
  ссылку в `gen_video` перед сборкой payload: тип от клиента — только подсказка.
  Аудио (`kind=audio`) отклоняем честно — схемой OpenRouter не передаётся.
- **Ошибки провайдера разворачиваются** (`_video_error_text`): OpenRouter кладёт ответ
  апстрима СТРОКОЙ в свой JSON («message»: «HTTP 400: {…}»), и в UI летела каша из
  скобок; теперь до сути + подсказка по-русски (`_VIDEO_ERR_HINTS`).
- **Форматы картинок** (`image_formats`, схемой OpenRouter не описаны): Veo НЕ берёт
  `.webp` — поймано пользователем 2026-08-05, поэтому у Veo список `strict` и такое
  блокируется; у Kling/Hailuo данных меньше — только предупреждение на карточке
  (`video_warnings`): ложный запрет хуже. Формат берётся от ffprobe/Content-Type,
  а не из расширения.
- **«Стоп» после отправки** пробует отменить задачу и У ПРОВАЙДЕРА (`POST
  /videos/{id}/cancel`, затем `DELETE /videos/{id}` — публичной схемой не описаны, но
  статус `cancelled` и вебхук `video.generation.cancelled` есть). Не принял — так и
  пишем в ошибке: задача досчитается и спишется, вот ссылка на результат. Прекращения
  опроса мало — на этом уже потеряли деньги (2026-08-05).
- Референсы — ГОТОВЫЕ https-ссылки: провайдер качает файл по URL, локальные/data-URI
  отвергает («Only HTTPS URLs are allowed»). Подпись к референсу схемой не описана —
  что с него взять, модель читает из ПРОМПТА по @-тегу (`@image1`/`@video1`,
  `_video_prompt` вплетает сам, синонимы юзера нормализуются).

**Снятие фона** (`insertlib.remove_bg`, пакет `rembg`/u2net, onnx на CPU ~1–2 с/шт,
модель ~176 МБ качается сама в `~/.u2net` при первом вызове): image-модели отдают
предмет на белом фоне, а вставки в базе — с альфой. Ключ `image_rembg` в ai_config.json
(дефолт ВКЛ, галка «убирать фон» рядом с селектом в ⚙) — фон снимается сразу после
генерации, ДО записи в базу, плюс обрезка полностью прозрачных полей (генератор оставляет
широкие пустые рамки). Пустая альфа (модель съела всё) → отдаём исходник. Для уже
лежащего файла — `insertlib.strip_bg_file()` / `/api/rembg {path,query,dest}` (кнопка
«Фон долой» на карточке): прозрачный `<имя>-nobg.png` кладётся сразу в `<база>/photos` и
вносится в индекс с описанием=запрос, исходник в «Скаченном» цел (мусор в Downloads не
плодим, чистая картинка нужна в базе). rembg не
установлен → генерация не падает, картинка сохраняется с фоном + `warn` в ответе.

**Файлы вставок сами уезжают в базу** (`insertlib.adopt`, вызов из `api._adopt_inserts`):
скачал картинку в Downloads → выбрал в карточке → **на сборке .jsx** файл переезжает
(`shutil.move`) в `<база>/photos|videos`, а `media` в самих вставках подменяется ДО
`to_ae_full`, поэтому .jsx ссылается уже на новое место. Момент выбран так, что уехало =
точно пригодилось: пока перебираешь варианты, Downloads не трогается. Описание в индексе
= **запрос вставки** (`desc_src="adopted"`) → в следующих роликах файл находится
автоподбором без прогона «Описать через ИИ». Уже лежащее в базе не двигаем (но в индекс
дописываем), коллизия имён → `имя_2.ext`, пропавший файл молча пропускаем, ошибка
переноса НЕ роняет сборку. Переносы пишутся в `<база>/_import_log.json` (как у
`import_media`). Путь сборки один — фоновый `/api/build_run` (маппинг кладётся в
`JOB["insmoved"]` и отдаётся в `/api/status`); синхронные `tojsx` и
`tojsx_multi` удалены 2026-07-28 как мёртвые дубликаты, фронт их не звал.
Тем же аудитом убраны `xml2srt` (`.srt` и так пишется при генерации субтитров —
`core/subtitle_xml.py`, и в CLI `reelsi.py --srt`) и `pickfile` (диалог выбора одного
XML; фронт зовёт `pickfiles`). Фронт по маппингу чинит пути в СВОИХ трёх местах — `c.inserts`,
`c.job.ins` и живом `INS` (`applyInsMoved`, сравнение путей без учёта регистра/слешей),
иначе следующая сборка искала бы файл по старому адресу.

**Форма маски запоминается за файлом** (2026-08-04). Вместе с описанием `adopt` кладёт в
запись индекса `mw`/`mh` — ширину/высоту кропа фото-вставки в % (та самая «Маска Ш/В» в
карточке). `match_many` отдаёт их рядом с путём, фронт применяет в `insApplyCrop` —
и при автоподборе, и при ручном выборе через 📚. Смысл: одна и та же картинка из базы
раньше приезжала с кропом 100/100 и подгонялась скрабберами заново в каждом ролике.
Сборка — единственный момент, когда форма точно известна (юзер её только что видел в
предпросмотре), поэтому пишем именно там и **поверх** прошлой. 100/100 не пишем (это и
есть «как считает JSX сам»), значения вне диапазона скраббера 20..300 отбрасываем
(`insertlib._crop_of`). `build_index` сохраняет `mw`/`mh` при полном рескане — как
`rej`/`added`. У видео маски нет, `insApplyCrop` их не трогает.

**Почему автоподбор возвращал старую картинку** (найдено 2026-07-18, исправлено):
у сгенерённого файла `desc` == запрос, поэтому при перегенерации того же запроса в базе
оказывались ДВА файла с идентичным desc → идентичные эмбеддинги (cos=1.0 между собой) →
одинаковый score на любой запрос. Ничья по score, ничья по `used` (у свежих 0) →
стабильная сортировка отдавала добавленный ПЕРВЫМ, то есть ровно тот, который юзер
забраковал перегенерацией. Плюс `insAfterAI` берёт базу ДО генерации, так что новая
генерация даже не запускалась. Лечение: (1) ключ сортировки `match_many` дополнен
свежестью — `(-score, -used, -added, -позиция)`, новые записи получают `added`
(таймштамп), у старых фолбэк на позицию в индексе; (2) `insertlib.reject(path, query)` —
брак пары **файл+запрос** (`rej: [запрос,...]` на записи), автоподбор такие пропускает,
руками через 📚 файл по-прежнему доступен, под другие темы тоже. Брак ставится сам,
когда юзер жмёт ✨ или ✕ поверх АВТОМАТИЧЕСКИ подставленной картинки (выбранное руками
не бракуется). `build_index` сохраняет `rej`/`added` при полном рескане.

**Почему автоподбор тащил свежие генерации вместо базы** (найдено 2026-07-21, исправлено).
Два независимых перекоса, оба про то, ЧТО едет в эмбеддер:
1. **Стиль забивал предмет.** Запросы у нас почти все вида «broken eyeglasses 3d icon», и
   «3d icon» — это треть короткого вектора. У сгенерённых/`adopted` записей `desc` = сам
   запрос, то есть тот же стиль → они кучковались между собой поверх смысла: замер на
   боевой базе давал `fried egg 3d icon` → **broken mirror 3d icon (0.67)**, а
   `empty hourglass` → broken eyeglasses (0.77). Старый порог косинуса такой мусор пропускал,
   поэтому автоподбор выглядел «в основном свежие генерации»: 1004 нормально описанных файла
   базы не могли перебить 51 запросо-подобную запись. Лечение — `_STYLE`-стоплист
   (`3d|icon|render|stock|photo|footage|illustration|closeup|graphic|style|image`)
   вырезается **только из запроса**: ищем предмет. В описаниях стиль остаётся.
2. **nomic-embed без префиксов.** Модель обучена на асимметричной паре
   `search_query:` / `search_document:`; без них «короткий запрос → длинное описание» плывёт.
   Теперь `_emb_queries` / `_emb_docs` (префикс только для моделей с `nomic` в id).

Схема эмбеддинга версионируется: `EMB_TAG` (сейчас `q5`) пишется в индекс, `_ensure_emb_tag()`
в начале `match_many` молча пересчитывает описания одним батчем при несовпадении (~40 с на
1000 файлов, один раз, полного рескана диска не нужно — тексты уже в индексе). Без
эмбеддера тег не трогаем: работает токенный фолбэк, пересчёт случится когда LM Studio
поднимут.

**Запись базы вставок — три текстовых поля** (2026-08-22). Раньше у записи было одно
описание `desc`, и прогон «описать всё» затирал метафоры вроде `money bills flushed down
toilet`, а восстановить их с картинки нельзя. Теперь полей три:
- `desc` — что ЗАДУМАНО: исходная фраза сценариста. Пишут `adopt` (`desc_src="adopted"`),
  `add_generated` (`desc_src="generated"`) и ручная правка (`desc_src="user"`); vision
  (`auto_describe`) `desc` не трогает никогда.
- `vis` — что ВИДНО на картинке: пишет только `auto_describe` (vision).
- `ru` — русская подпись вставки.

В эмбеддер едет склейка всех трёх через `_doc_text(desc, ru, vis)`, очищенная от слов
стиля и цвета `_subject_text` — предмет, без «3d icon / photo / white». Пригодность текста
записи для поиска — `needs_text(it)`: непригодны ОБА поля (`desc` и `vis`); у
`desc_src="user"` всегда пригодно — человек правил руками, не переписывать.

**Миграция.** `build_index` переносит vision-описания прежних прогонов: у записей
`desc_src="ai"` описание переезжает в `vis` (если `vis` пуст), а `desc` очищается и
`desc_src` становится `"name"`. Идемпотентна: после первого же прохода `desc_src == "name"`,
повторный скан ничего не меняет.

**Отказы vision** — `_is_refusal()`. Ответ, начинающийся с «None of the objects...»,
«i cannot», «there is no» и т.п., описанием не считается: запись попадает в `needs_vis`
и переописывается обычным «Обновить базу», а в эмбеддинг отказ не идёт — он хуже пустого,
тянет к себе чужие запросы. На боевом прогоне таких ответов было 155 из 1373.

**Пропавшие файлы** — поле `gone` (таймштамп). Ставит и снимает только скан; записи не
удаляются — в них `used` и `rej` (история). Подбор фильтрует по `gone`, а диск проверяется
только у победителей по мере набора `k`.

**Сопоставление путей — через `os.path.normcase`** (Windows ФС регистронезависима). Без
этого скан пометил 58 живых записей как пропавшие и завёл им дубли; `build_index`
схлопывает такие дубли (`_merge_prev_records`), беря максимум полезного: пригодный `desc`
(`_field_unfit`), максимум `used`, объединение `rej`, непустые `ru`/`vis`/`mw`/`mh`, а
эмбеддинг — только если итоговый текст совпал с текстом победившей записи.

**Ранжирование** — `rank = score + lex`. `score` — косинус по предметной части
(`_subject_text`), `lex` — лексический бонус `LEX_W = 0.35` с весом по редкости слова (idf),
считаемый по имени файла + `desc` + `ru` + `vis`. В выдаче `score` остаётся чистым косинусом,
`lex` отдаётся отдельным полем. Матрица векторов кэшируется (numpy, `_matrix`) и сбрасывается
вместе с индексом.

**Пороги автоподбора живут в `insertlib`, а не во фронте**: `AUTO_COS = 0.30` (для токенного
фолбэка `AUTO_COS_TOK = 0.5`), `AUTO_LEX = 0.20` — самостоятельный порог лексического
совпадения, поле `auto` в выдаче. `AUTO_COS` подобран замером на 194 реальных запросах
(проходит 73%, мусор `chicken breast 3d icon` → бургер остаётся под 0.28). Второй порог
появился потому, что на 1317 запросах у 39 был top-1 с косинусом ниже 0.30 при `lex >= 0.20`
(буквальное совпадение имени файла вроде «revolver cylinder» → `revolver_cylinder.mp4`),
и такие запросы не подставлялись.

**Стиль спикера** — поле `look`: сама приписка `image_prompts[slot].extra` из профиля
спикера, нормализованная `_norm_look`; пишется только у сгенерённых. Поправка ранга, а не
фильтр: свой стиль `+0.05`, пустой `0` (общая картинка со стока годится всем), чужой
`−0.15`; кандидат с чужим стилем обязан остаться в выдаче. Профиль спикера резолвится только
в `api/inserts.py`, в `match_many` приходит уже нормализованный `look`.

**Промпт vision** сменён под `qwen3-vl-8b` и требует называть предмет без стиля и цветов
(запрет отказа обязателен: на боевой базе вышло 11 % отказов вида «None of the objects...»).
Замер (стенд `tools/bench_vision.py`, 40 файлов с известным ответом): `gemma-4-e2b` 16 %
при любом промпте, `qwen2.5-omni-7b` 18 %, `gemma4-e4b-sft` 0 % (не отвечает),
`qwen3-vl-8b` 26 % и читает названия с упаковок.

Осталось на будущее: гонять `describe_file` по сгенерённым/`adopted` картинкам, чтобы у них
появился `vis` — тогда база станет однородной, а `desc` останется исходной фразой.

**Тип вставки — по файлу, а не по заявке** (найдено 2026-07-21, исправлено). `type` в
`INSERTS` решает в AE всё: фото = стоп-кадр с наездом и стилем по активной камере, видео =
футаж с `Quick 2.mov` + whoosh и `sin`. А файл может приехать любой (руками через «Выбрать
файл…», из вкладки AE), поэтому `insSetMedia()` в UI проставляет `type` по расширению везде,
где садится файл, а `xml2ae.to_ae_full` перед раскладкой стилей ещё раз чинит тип по
`_is_image(media)` — последний рубеж, он же лечит старые сохранённые проекты.

**`type_hint` остаётся мягким — жёсткий фильтр откатан** (2026-07-30). Пробовали отсекать
пул по типу (просили фото — видео не отдаём). Откатили в тот же день: (1) автоподбор в
среднем и так попадает, а более подходящее видео лучше «ничего»; (2) фильтр резал и ручную
выдачу 📚 — в вариантах не оставалось ничего, кроме одного типа, и выбрать было не из чего.
Сейчас: автоподбор (`insLibFill`) шлёт тип как пожелание — `insWant(x)`, отсутствующий тип
= фото (как в `insGenBatch`); ручная выдача 📚 (`insLibFor`) тип НЕ шлёт вовсе и берёт k=8 —
там юзер смотрит глазами. Мешало на самом деле другое, см. следующий пункт.

**Снятая крестиком картинка не возвращается** (`noAuto`, 2026-07-30). В базе при снятии
файл сознательно НЕ бракуется (см. выше — брак портил базу другим роликам), значит на
следующем проходе он снова первый по score: юзер убирал картинку, добирал вставки ИИ или
правил описание — и получал ровно её обратно. Теперь `insClearMedia` ставит вставке
`noAuto`, а оба АВТОматических пути его смотрят: `insLibFill` (файл не ставит, но `libOpts`
для 📚 всё равно заполняет) и `insGenBatch` (иначе молча генерил новую за деньги). Любой
осознанный выбор файла флаг снимает — `insSetMedia` (📚-вариант, «Выбрать файл…», вкладка
AE) и `insGenCore` (✨). Флаг живёт в состоянии клипа, т.е. переживает перезагрузку страницы;
стережёт это `test_cleared_insert_is_not_refilled_by_itself`.

**Описание вставки правится в карточке** (`.qedit` вместо прежнего read-only `<code>`):
это одно и то же описание идёт и в подбор из базы, и в генерацию. `insQuery()` по
Enter/уходу фокуса: сбрасывает `libOpts` (старые варианты не про этот запрос) и сразу
перематчивает из базы через `insLibFill([x])`. Файл, выбранный РУКАМИ или сгенерённый
(за него плачено), правка описания НЕ затирает — только автоподобранный (`libAuto`);
чтобы заменить такой файл, сперва убери его крестиком. `insLibFill(arr)` — общий подбор
по списку (один batch-запрос), ставит файл только тем, у кого его нет; `insLibAuto(clip)`
= обёртка над ним для всех вставок клипа без файла.

**Крестик у имени файла** (`insClearMedia`) убирает ТОЛЬКО картинку — вставка (тайминг,
описание, mosaic) остаётся; сбрасываются `libAuto`/`genAuto`, `libOpts` сохраняются.
Заново из базы не подставляем: раз убрал — значит не то. Не путать с ✕ в шапке карточки
(`insDel`) — тот удаляет вставку целиком.

**Убрать картинку ≠ «картинка не подходит» (2026-07-22).** `insClearMedia` больше НЕ
бракует файл в базе. Раньше снятие автоподбора само писало записи `rej: [запрос]`, и
юзер, который просто чистил вставку (или сносил её целиком), молча портил базу — брак
всплывал потом, в других роликах, и выглядел как «оно записало, что картинка не подходит,
а я её не трогал». Теперь пара файл+запрос бракуется только там, где это сказано явно:
✨ перегенерация ПОВЕРХ автоподбора (`insGenOne`). Удаление вставки целиком (`insDel`) в
базу не лезет вообще — оно пишет лишь `ins_rejected` («эта вставка тут не нужна», уходит
в промпт следующей разметки), и это другая память.

**Генерация прямо при разметке**: галка «и сразу генерить недостающие» в модалке 📚
(localStorage `autocut2_inslib.gen`, видна только когда генерация включена в ⚙, дефолт
ВЫКЛ — это платно). Общий хвост `insAfterAI(clip)` = автоподбор из базы → (по галке)
генерация остатка; дёргается из всех четырёх путей: «Подобрать вставки», «Добрать»,
«Разметить всё» (фаза 3) и разметки одного клипа. В пачке при первой же ошибке
(402/429/нет ключа) генерация останавливается — не молотить N раз в один отвал.

## Генерация картинок и видео

**КАРТИНКИ** — `core/aicut/images.py`:
- профили генерации (из `images_profiles.json`),
- `build_image_prompt` — сборка промпта (без «технического хвоста»),
- `gen_image` → API-вызов (облачная модель, например Nano Banana),
- подпись добавляется через пробел (не запятую) — «broken eyeglasses 3d icon»,
- rembg (вырезание фона) — `image_rembg_on`.

**ВИДЕО** — `core/aicut/video.py`:
- каталог видеомоделей (`video_catalog.json`),
- валидация запроса (промпт, длительность, запрещённые теги),
- `gen_video` → API-вызов облачной модели,
- `normalize_video_tags`, `resolve_refs` (ссылки в видео), `video_warnings`.

**СЛОТЫ** — слоты "1"/"2" — ДВЕ ГЕНЕРАЦИИ ОДНОГО предмета, слот `a` — пакет.

## API endpoints (сводка)

**ОБЩЕЕ** — все `/api/*` — JSON, джобы-сабпроцессы стримят лог через `emit`.

**ДЖОБЫ** (`api/jobs.py`):
- `POST /api/omnicut_run` — ИИ-нарезка (сабпроцесс).
- `POST /api/run` — нарезка (кастомная панель / классика, параметры из `cutstages`).
- `GET /api/cutstages` — список доступных ступеней нарезки, дефолты и пороги.
- `POST /api/draft_render` — черновой рендер.
- `POST /api/status` — инкрементальный опрос лога (`since=N`).
- `POST /api/cancel` — отмена джоба.
- `GET /api/clean_tmp`, `GET /api/tmp_info` — чистка/инфо `_tmp`.

**ФАЙЛЫ** (`api/files.py`):
- `POST /api/files` — списки камер/файлов.
- `POST /api/pickmedia` / `pickfiles` / `pickone` / `pickaudio` / `pickdir` —
  нативные диалоги файлов (разовые, на сервере не хранятся).
- `GET /api/media` — отдаёт любой медиафайл (Range для стриминга).
- `GET /api/waveform` — кэш пиков для редактора нарезки.
- `POST /api/cams`, `/api/cammatch` — раскладка камер, подбор кам 2..N по звуку.
- `POST /api/cams_make` — создание 1..4 папок `cameraN`/`камераN` по явной кнопке на чистой установке (молча не создаются), возвращает состав камер.
- `POST /api/newtakes` — фильтр «уже нарезано» для очереди.
- `POST /api/clip_delete` — dry-run или удаление XML и файлов `<stem>.*` плюс отдельного `<stem>.jsx` в `jsxdir` без трогания исходников камер и системных файлов (`files`, `bytes`, `skipped`, `cams`).
- `GET /api/fonts` — реестр установленных шрифтов (PostScript-имя + семья), при ошибке деградирует до пустого списка.
- `GET /api/fontfile/<path:ps_name>` — отдача файла шрифта только из реестра `fonts` для точного предпросмотра в браузере (защита от чтения произвольных файлов).
- `GET /api/music_random` — случайный трек из папки музыки.
- `GET/POST /api/ui_state` — серверное зеркало состояния UI.

**ИИ** (`api/ai.py`):
- `GET/POST /api/ai_config` — профили/ключи провайдера (маской).
- `POST /api/ai_models` — список моделей провайдера.
- `POST /api/ai_test` — мини-вызов LLM (проверка).
- `POST /api/ai_yellow` / `ai_inserts` / `ai_intro` — разметка; `ai_stop` отменяет.
- `POST /api/ai_genimage` — генерация картинок; `POST /api/rembg` — вырезание фона.
- `GET /api/ai_stats` — сводка вызовов из `ai_calls.jsonl` по `(model, step, reasoning)`: медианы токенов input/output/reasoning и времени, доля размышлений `rt%`, число успешных вызовов и ошибок (для окна настроек).

**РЕДАКТОР** (`api/editor.py`):
- `POST /api/editor_load` / `editor_save` — состояние редактора нарезки, память
  правок (возвращено/удалено).
- `POST /api/edit_word` — правка текста слова; `set_yellow` / `clear_subs` — теги
  субтитров.
- `POST /api/caption` — чтение (без `text`) или атомарная запись (`text`) одиночной подписи ролика в `<stem>.caption.json` (включается стилем `caption`, входит в `scene_plan` и сборку AE).
- `GET /api/words`, `POST /api/xml_state`, `GET /api/omnicut_cuts` — список слов/состояние.
- `POST /api/breaths` — нарезка вздохов из `.breaths.json`.
- `POST /api/asr_engines` — реестр движков речи.
- `POST /api/gen_subs`, `POST /api/aicut_preview`, `POST /api/scanxml` — субтитры
  с нуля, виртуальный EDL для предпросмотра, скан папки.

**ВСТАВКИ** (`api/inserts.py`):
- `POST /api/insertlib_info` / `scan` / `reject` / `match` / `import` / `describe`
  / `desc` / `items` — индекс базы вставок, подбор и описание.
- `GET /api/insertlib_describe_status` — статус фонового vision-описания базы: `running`, `done`, `total`, `error` и инкрементальный `log`/`log_total` по `since=N`.

**СТИЛЬ / СПИКЕРЫ** (`api/presets.py`):
- `POST /api/styles` / `savestyle` / `delstyle` — пресеты стиля клипа.
- `POST /api/style_patch` — точечное обновление полей пользовательского `styles/<name>.json` с сохранением остальных настроек (встроенные `base`/`geologica` не меняет; автосохранение настроек строк/слов субтитров в UI).
- `POST /api/speakers` / `savespeaker` / `delspeaker` — профили спикеров.
- `POST /api/terms` — словарь терминов ASR; `POST /api/censor_words` — списки цензуры.

**СБОРКА** (`api/build.py`, `api/render.py`, `api/previewproxy.py`):
- `POST /api/build_run` — сборка AE (`.jsx`).
- `POST /api/scene` — план сцены для предпросмотра шага 3 (вся математика сборки без
  рото/`.jsx`); предпросмотр рисует его и не досчитывает.
- `POST /api/cams_load` / `cams_save` / `swap_cam` — раскладка камер на шаге 2.
- `POST /api/export_xml` / `export_drp` — скачать таймлайн как XML / `.drp`.
- `POST /api/render_run`, `GET /api/render_status` — безголовый рендер AE (только
  Windows, `aerender`), свой джоб.
- `POST /api/preview_proxy`, `GET /api/preview_proxy_status` — прокси 720p 4:2:0 для
  4:2:2 10-битных исходников, которые браузер не декодирует, свой `PXJOB`.

**GDRIVE** (`api/gdrive.py`):
- `POST /api/gdrive_download`, `GET /api/gdrive_status` — материал по ссылке
  гугл-диска через `rclone`, свой джоб (не занимает JOB нарезки).

**ВИДЕО** (`api/videogen.py`):
- `POST /api/video_gen` — запуск генерации; `POST /api/video_cancel` — отмена.
- `GET /api/video_status` / `video_history` — статус / история.
- `POST /api/video_models`, `POST /api/video_probe` — список моделей, проба файла.

**СИСТЕМА**:
- `POST /api/cancel` — отмена джоба.
- `GET /api/status` — инкрементальный опрос (`since=N`).
- `GET /api/clean_tmp` — чистка `_tmp`.
