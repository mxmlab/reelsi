# Жёлтые выделения субтитров — спецификация

English version: [docs/HIGHLIGHT_SPEC.en.md](HIGHLIGHT_SPEC.en.md).

Восстановлено из реального проекта (дамп `tools/ae_inspect.jsx` → `1.json`),
эпизоды сопоставлены по транскриптам (`Reelsi_out/*.words.json`).

## Базовый стиль (все слова)
- Шрифт: `SFPro-CondensedSemibold`, по центру.
- Размер: **140** (в проекте это 97 с масштабом ~140 % — эквивалент; мы печём 140 напрямую).
- Цвет: белый `[1, 1, 1]`.
- Появление: хард-кат (без анимации), без звука.
- Якорь позиции (одиночное слово): X = W/2, Y ≈ **0.5964·H** (=1145 при 1920).

## Выделенное слово
- Всё то же (размер 140, шрифт, центр), но:
- Цвет: жёлтый **`[1, 0.9176, 0]`** (RGB 255/234/0).
- Анимация «slide-up»: Position выезжает снизу вверх на ≈0.064·H (~123 px при 1920)
  за **~0.35 с**. Scale не трогаем.
- Анимация Opacity **0 → 100** на том же окне ~0.35 с.
- Ease обеих анимаций: **cubic-bezier(0.35, 0.01, 0.10, 0.99)** —
  в терминах AE: key1 out-influence 35, key2 in-influence 90, speed 0
  (тот же безье, что у зума камеры; `1−0.10 = 0.90`).
- Звук: поп `assets → highlight_pop` (`4 type & delete.wav`) в момент появления (startTime = start слова).

## Стопка (подряд идущие выделенные слова)
«Подряд» = соседние слова в порядке субтитров, оба выделены.
- Ряд r (0-based): Y = ROW1 + r · STEP, где ROW1 ≈ 0.5964·H, STEP ≈ 0.06224·H (~119.5 px).
- Каждое слово выезжает в свой ряд со своим start; **общий out** = конец последнего слова связки
  → вся стопка держится вместе и исчезает разом.
- Пример из C1221: «ФИЗРАСТВОР»(ряд0)+«С САХАРОМ»(ряд1); «ОТЕК»+«ЛИЦА»; «не»+«досыпали».

## Красный акцент (на будущее, не реализуем сейчас)
Тёмно-красный `[0.6863, 0.1216, 0.1216]` — негативный смысл («ПОД БЕШЕНЫЕ ПРОЦЕНТЫ»).

## Частица «не»/«ни» перед выделенным словом
- Частица «не»/«ни», стоящая непосредственно перед словом, которое выделил ИИ, красится
  ВМЕСТЕ с ним (замер по 236 клипам: 135 жёлтых слов с белым «НЕ» перед ними).
- Предлоги и прочие служебные слова не присоединяются: правило только про «не»/«ни».
- Правило дословно уходит и в подсказку ИИ-разметке жёлтых (`core/aicut/commands.py`).

## Сила жёлтых и наезд камеры (`cam1_yellow_zoom_strong`)
Жёлтых слов ИИ ставит десятки, и наезд на КАЖДОЕ превращал ролик в непрерывный зум
(решение владельца 02.10.2026). Поэтому у камеры есть галка **«Только сильные жёлтые»**
(`cam1_yellow_zoom_strong`, у камеры 2 — `cam2_yellow_zoom_strong`, обе включены по
умолчанию). Включена — на кусок ставится наезд только на самые сильные жёлтые; выключена —
прежнее правило «наезд на каждую фразу».

Силу считает `core/emphasis.py` и кладёт в сайдкар `<стем>.emph.json` рядом с XML. Две
составляющие по каждому слову:

- **эмоция фразы** — модель GigaAM с головой `emo` (`emo = 1 − p(neutral)` в окне 2.5 с с
  центром на слове; замер владельца: 65 мс на слово на GPU, нейтральное 0.98–1.0,
  эмоциональное 0.77);
- **ударение по звуку** — громкость (RMS, дБ), высота тона (`librosa.yin`) и растянутость
  слога, каждое в z-оценке по СОСЕДНИМ словам (±5 слов, медиана и MAD). В тон идут только
  озвученные кадры: на паузах `yin` выдаёт случайную частоту, и без порога тон слова уезжал
  бы на шум паузы.

Звук — голос Камеры 1 в ИСХОДНОМ времени под словом (сопоставление «слово монтажа → кусок
исходника» то же, что у дорожки голоса). Читается ОКНАМИ вокруг нужных слов, а не исходником
целиком: окно эмоции — 2.5 с с центром на слове, окно ударения — сам блок слов ±5 соседей;
пересекающиеся окна склеиваются (`_merge_windows`), так что соседние слова не дают десятков
чтений ffmpeg по одному куску. Тон и RMS считаются ОДИН раз на объединённое окно
(`tone_track` → `librosa.yin` без Витерби), а слово берёт срез готовых массивов: пословный
`pyin` (с Витерби) на клипе с полусотней жёлтых съедал 141 с из 145.

Обе составляющие лежат в сайдкаре рядом, поэтому способ оценки переключается БЕЗ пересчёта
(ключ стиля `hl_zoom_strength`; «по голосу» модель эмоций не грузит вовсе и пишет в сайдкар
только `stress`). Компоненты, которой в сайдкаре нет, слово честно числится непосчитанным, и
правило возвращается к прежнему, а не считает слово «слабым». Версия формулы — в ключе
сайдкара: `EMPH_VERSION` поднимается при смене весов и окон, иначе старый сайдкар переживёт
правку.

Правило наезда (`core/xml2ae/layout.py`, `_yellow_strong_phrases`; ручки читает
`core/xml2ae/plan_camera.py`):

- порог силы **`hl_zoom_min_pct`** («Порог силы, %», дефолт 70) — процентиль сил жёлтых САМОГО
  клипа: фраза ниже p70-го процентиля не наезжает вовсе. 0 — наезжают все фразы с жёлтыми,
  100 — только самое сильное слово клипа. Сила фразы — максимум сил её слов;
- **`hl_zoom_max_per_piece`** («Наездов на кусок, макс.», дефолт 2) — сколько наездов максимум
  в одном куске;
- **`hl_zoom_second_min_s`** («Второй наезд — кусок от, с», дефолт 8) — кусок короче наезжает
  один раз, даже если сильных слов несколько: второй цикл в него не помещается;
- порог считается по всем жёлтым КЛИПА (а не куска): «жёлтых много» — свойство ролика, и цикл
  по силе не выбирается — наезды стоят в порядке времени, иначе состояние «камера уже на пике»
  считалось бы неверно. Текст жёлтым при этом остаётся: порог про камеру, не про цвет.

Гейт один: не посчиталось (нет звука, нет модели, слово добавлено руками после расчёта,
версия формулы разошлась) — правило работает как раньше, наезд на каждую фразу, и в лог идёт
строка «сила жёлтых не посчитана». Сайдкар пересчитывается в конце шага ИИ-жёлтых
(`aicut.cmd_yellow`) и лениво при сборке (`core/xml2ae/precompute.py`,
`emphasis_precompute`); план сцены сайдкар только ЧИТАЕТ (`read_emphasis`) — эта дверь
быстрая, её зовут на каждую правку вставок.

## Где реализовано
- `core/xml2ae/build.py` — `to_ae_full(..., highlights=set_of_indices)` строит слои с учётом стиля/стека/попа.
- `core/emphasis.py` — сила жёлтых (эмоция GigaAM-Emo и ударение по звуку) и сайдкар `<стем>.emph.json`.
- `core/xml2ae/precompute.py` — `emphasis_precompute`: одна дверь расчёта для сборки и кнопки превью.
- `core/xml2ae/layout.py` — `_yellow_strong_phrases` (порог, предел наездов, длина куска) и `_hl_phrase_groups` (фраза из подряд идущих слов).
- UI — панель «Слова» в предпросмотре: клик по слову = жёлтое; индексы уходят в `/api/set_yellow`.
- Индексы — 0-based позиции слов в отсортированном по времени списке субтитров (как их видит `parse_full`).
