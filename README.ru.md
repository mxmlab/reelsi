# Reelsi

[![CI](https://github.com/mxmlab/reelsi/actions/workflows/ci.yml/badge.svg)](https://github.com/mxmlab/reelsi/actions/workflows/ci.yml)

Локальный помощник монтажа говорящей головы. ИИ режет видео по содержанию и собирает готовые проекты для Adobe Premiere Pro и After Effects — или рендерит готовый ролик сам, без After Effects. Все вычисления происходят на вашей машине, наружу уходит только то, что нужно выбранному облачному провайдеру: текст транскрипта, а если включены облачные функции — звук для распознавания и картинки для описания и генерации вставок; с локальными моделями ничего не уходит.

> Русская версия. English: [README.md](README.md).

![Reelsi в работе](docs/img/demo.webp)

## Что делает

### Нарезка

- **Синхронизация камер по звуку**: автоматическое сведение нескольких камер по аудиодорожкам. Рассчитан на несколько камер (до четырёх), проверен на двух.
- **ИИ-нарезка по смыслу**: нарезка речи по транскрипту через локальную модель (LM Studio, Ollama) или облачного провайдера. Нарезка — это набор ступеней на выбор: паузы, смысловая нарезка, правка повторов и оговорок кодом, подгон резов по тишине, вздохи, черновик mp4.
- **Пословное распознавание**: сменные движки распознавания речи (Whisper, whisper.cpp, GigaAM), каждый со своими таймингами слов.
- **Второй проход текста (необязательный)**: настройка **«Движок нарезки (текст)»** (⚙ → «Нарезка», по умолчанию выключена) позволяет Whisper поправить написание слов, которые распознал GigaAM; тайминги остаются за GigaAM. При включённой настройке субтитры попадают в XML уже при нарезке.
- **Вырезание вздохов**: находит вздохи перед фразами и вырезает их; спорные показаны оранжевой полоской в редакторе и убираются одним кликом.
- **Редактор нарезки**: правка результата руками — курсор, края блоков, возврат вырезанного двойным кликом, прослушивание вырезанного звука и сохранение обратно в XML. При включённом втором проходе текста вернувшийся кусок получает субтитры обратно из слов исходника.
- **Очередь клипов**: много роликов одной очередью, подбор камер по имени или по звуку и пропуск роликов, у которых нарезка уже есть.
- **Черновик mp4**: быстрый черновик каждой нарезки, чтобы посмотреть результат до разметки.

### Предпросмотр и правка

- **Предпросмотр сцены в браузере**: вся собранная сцена — нарезка, субтитры, вставки, интро — до экспорта, с правкой перетаскиванием: положение вставки, положение интро, тайминг.
- **Раскладка камер**: какая камера в кадре на каждом куске, сохранение раскладки и возврат к авто; плеер даёт послушать другую камеру и проверить синхронизацию.
- **Пакетная разметка**: субтитры идут ролик за роликом на видеокарте, а облачные ступени (жёлтые слова, вставки) стартуют для ролика сразу, как только готовы его субтитры, — весь набор размечается за один проход.
- **Редактор вставок**: тайминг, положение и масштаб каждой вставки; карточка сохраняет свою личность, даже когда один файл стоит в нескольких вставках, а любую правку можно отменить и вернуть.
- **Работа по клипу хранится на диске**: спикер, раскладка камер, вставки, стиль и интро клипа возвращаются после перезагрузки и пересканирования, а удалённый клип уезжает в корзину, откуда его можно вернуть.
- **Ротоскоп и слежение за головой в предпросмотре**: одна кнопка считает вырезанную фигуру спикера и трек головы на видеокарте, с прогрессом и «Стоп», и показывает то и другое в предпросмотре.

### Звук

- **Обработка голоса для каждого спикера**: ИИ-шумодав и цепочка VST3-плагинов («сначала шумодав, потом плагины»), живое прослушивание через окно плагина и ползунки громкости; обработанный голос запекается в одну дорожку, общую для предпросмотра и проекта, и нарезка идёт уже по очищенному голосу.
- **Музыка**: живёт в стиле с переопределением на клип; выбранный случайный трек виден по имени, «Другой трек» выбирает заново, а ссылку можно скачать заранее, а не во время сборки.

### Оформление

- **Пословные субтитры**: анимированная графика субтитров с подсветкой активных слов, умной разбивкой на строки и подложкой, плюс обычный `.srt`.
- **Подсветка слов**: ИИ выбирает ключевые слова; жёлтые слова появляются на речи (подъём, проявление, блюр), складываются в строке по одному, а наезд камеры случается только на самых сильных.
- **Интро**: хук и анимированные титры, собранные из транскрипта, с accent-строками, свечением, тенью, положением, масштабом и отступами от края для каждой камеры. Длина строки заголовка — ручка стиля (по умолчанию 20 символов), а слово-призыв в кавычках в конце ролика становится последним акцентом.
- **Работа с камерой**: анимация зума (плавно, скачками, дрейф), наезды внутри длинных тейков и на подсвеченных словах, ручная кадрировка (заполнение, точка наезда, сдвиг кадра, горизонт) и слежение за головой — у двух камер свои зум, кадр, цвет и интро.
- **Вставки**: фото и видео подбираются из локальной базы по смыслу или генерируются у ИИ-провайдера, либо берутся из стоков Pexels, Unsplash, Pixabay и Openverse в этом порядке (Coverr — за флагом); режим подложки вырезает фон у фото, а цензура закрывает область мозаикой. Слово из личного словаря `named_inserts.json` (корень репозитория; общий пример — `data/named_inserts.example.json`) ставит на себя картинку из базы.
- **Модель вырезания фона**: u2net (быстрая, по умолчанию, ~0.7 с на картинку) или BiRefNet (чище края, ~8 с на картинку на процессоре); выбор в ⚙ → Генерация, BiRefNet при первом выборе скачивает модель ~1 ГБ.
- **Ротоскоп**: вырезание фона спикера на видеокарте ставит его фигуру над интро и вставками.
- **Стиль спикера и проекта**: панель стиля со всеми ручками, пресеты, стиль, привязанный к спикеру, и порядок слоёв собранной сцены.
- **Текстовые мелочи**: словарь терминов для распознавания, списки цензуры с режимом «только целое слово», подпись под роликом и дисклеймер, масштаб и положение которого правятся в предпросмотре.

### Экспорт и рендер

- **Экспорт в несколько форматов**: смонтированная последовательность уезжает в Premiere Pro (XML), After Effects (скрипты `.jsx`) и DaVinci Resolve (проекты `.drp`).
- **Безголовый рендер After Effects**: набор собирается и рендерится без открытия интерфейса AE; несколько копий After Effects собирают клипы параллельно, ещё одна сводит их в один проект, с прогрессом, ETA и «Стоп».
- **Встроенный рендер без After Effects**: второй движок рисует кадры тем же предпросмотром сцены в браузере без окна и сводит звук по плану сцены, поэтому After Effects не нужен вовсе. Этот путь повторяет предпросмотр приблизительно — свечение, Lumetri и мозаика цензуры близко, motion blur нет.
- **Прогресс, очередь и логи**: у каждой долгой работы видно клип, очередь и ступень, есть кнопка «Стоп».

### Дополнительно

- **Язык интерфейса**: русский и английский, переключается в шапке.
- **Командная строка**: нарезка, подсветка и сборка скрипта After Effects доступны и из консоли, без веб-интерфейса.
- **Материал с Google Drive**: загрузка исходников по ссылке (`rclone`) с раскладкой по папкам камер.

## Как идёт обработка

1. **Исходники**: от одной до четырёх камер в папках рядом с репозиторием; дорожки камер сводятся между собой по звуку.
2. **Распознавание**: речь распознаётся с таймингами каждого слова (Whisper, whisper.cpp или GigaAM). При включённом втором проходе текста Whisper дополнительно правит написание; слова исходника сохраняются рядом с XML (`<stem>.srcwords.json`), и субтитры вернувшихся в редакторе кусков можно пересобрать.
3. **Нарезка**: транскрипт уходит языковой модели, которая решает, что убрать, — локально или через выбранного провайдера; код возвращает паузы, повторы и вздохи и собирает таймлайн.
4. **Правка**: нарезка и раскладка камер правятся руками в редакторе.
5. **Разметка и оформление**: субтитры, подсветка, вставки, интро и работа с камерой считаются по каждому клипу; материалы берутся из локальной базы или у ИИ-провайдера.
6. **Сборка и рендер**: план сцены становится Premiere XML, скриптом AE, проектом Resolve или готовым роликом из встроенного движка.

Модели — распознавание, вздохи, эмоции, шумодав — считает один локальный сервис моделей: он держит веса в памяти вместо загрузки на каждый клип и считает несколько клипов разом, до своего потолка. Где считать — машинная настройка: по умолчанию видеокарта, а на машине без карты или чтобы освободить карту под локальную LLM (LM Studio, Ollama) — процессор. Перед рендером сервис просят освободить видеопамять.

## Системные требования

Проверено только на Windows 11 с видеокартой NVIDIA и Adobe After Effects / Premiere Pro. Другие платформы не проверялись; заметки о переносе — [docs/PLATFORMS.md](docs/PLATFORMS.md).

- Python 3.10 и ffmpeg в переменной PATH.
- PyTorch, поставленный отдельно и первым, в сборке под своё железо: сборка под процессор тоже работает, но привязанные к видеокарте шаги пойдут в десятки раз медленнее (`install.ps1 -Cpu`).
- Браузер на Chromium (Chrome, Edge, Brave и подобные). Он рекомендуется для предпросмотра: в Firefox звук исходников камер с дорожками PCM не декодируется вовсе — превью молчит, пока не переедет на прокси превью. Встроенному рендеру браузер на Chromium нужен безусловно: кадры он снимает в своём браузере без окна.
- Видеокарта NVIDIA с поддержкой CUDA — то, на чём проект проверен; модели можно считать и на процессоре (⚙ → «Нарезка» → «Где считать модели»). На карте параллельных распознаваний больше и быстрее, на процессоре видеопамять не занимается вовсе.
- Языковая модель для смысловых шагов — LM Studio или Ollama локально, либо API-ключ облачного провайдера. Классическая нарезка по паузам с Whisper работает и без неё.
- Adobe After Effects необязателен: он нужен для безголового рендера AE и для ручной правки собранного `.jsx`, а встроенный движок рендерит без него. Adobe Premiere Pro тоже необязателен — он нужен только чтобы открыть экспортированный XML, сам Reelsi его не зовёт.
- Опциональные утилиты: `rclone` (скачивание с Google Drive), `yt-dlp` (музыка).
- Необязательные Python-пакеты из `requirements-optional.txt` ставятся по одному: каждый включает ровно одну возможность, остальное продолжает работать (`pedalboard` — живое прослушивание через VST3-плагины и список устройств вывода; `gigaam` — пословная нарезка; `silero-vad`, `rembg`, `anthropic`, `yt-dlp`). `python doctor.py` называет, чего нет и что без этого отключится.
- ИИ-шумодав приезжает по требованию: движок RoFormer — отдельное окружение со своими моделями, качается кнопкой в панели голоса; без него работает прежний бинарник deep-filter.
- Шаблоны субтитров используют шрифт SF Pro; пересборка под другой шрифт: `python tools/harvest_good.py "path/to/reference.xml"`.

## Установка

Все команды — из папки клона `reelsi/`.

Обычная установка (`pip install .` или `pipx`) не поддерживается: шаблоны, статика и личные файлы пользователя живут в папке клона.

Автоматическая установка: `install.ps1` для Windows, `install.sh` для macOS и Linux:

```bash
powershell -ExecutionPolicy Bypass -File install.ps1   # Windows
bash install.sh                                        # macOS и Linux
```

Оба установщика ставят только зависимости: команды `reelsi`, `reelsi-webui` и `reelsi-doctor` появляются после `pip install -e .`. Python и ffmpeg они не ставят — `install.sh` для этого нужен системный `python3`, и оба останавливаются и говорят, чего не хватает, вместо того чтобы ставить это самим.

Ручная установка:

```bash
pip install torch==2.8.0 torchaudio==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cu126
pip install -r requirements.txt
pip install -r requirements-optional.txt
```

Установка из клона в режиме editable (регистрирует команды `reelsi`, `reelsi-webui`, `reelsi-doctor`):

```bash
pip install -e .
# с опциональными зависимостями:
pip install -e ".[optional]"
```

У версий зависимостей в `requirements.txt` стоит верхняя граница. Убирать её не надо: свежий мажорный релиз ломает шаг субтитров на чистой установке — librosa 1.0 выбросил запасной путь через `audioread`, а PyAV 19 убрал аргумент, который faster-whisper 1.2 ещё передаёт, поэтому PyAV прижат ниже 19. Если `pip check` или шаг субтитров сообщает о конфликте версий, переставьте зависимости с прижатыми версиями, а не снимайте границу.

Проверка окружения выполняется командой `python doctor.py` (или `reelsi-doctor`): скрипт проверяет установленные компоненты, GPU-ускорение и выводит, чего не хватает.

## Быстрый старт

Клонируйте репозиторий внутрь рабочей папки, рядом с папками материала:

```
my_workspace/
├── reelsi/            ← этот репозиторий
├── camera1/           ← видео с камер
├── camera2/
└── music/
```

Запустите веб-интерфейс:

```bash
python webui.py          # или: reelsi-webui
```

Откройте адрес http://127.0.0.1:5001: мастер из трёх шагов провёдет нарезку, разметку и экспорт в After Effects. При первом запуске `webui.py` автоматически создаёт файлы `insertlib.json`, `styles/` и `speakers/` из `examples/*.example.json`. Ключи ИИ задаются через ⚙ в интерфейсе и хранятся в `ai_config.json` вне git.

Команды консоли:

```bash
python reelsi.py --cams 2     # две камеры (после pip install -e .: reelsi --cams 2)
python reelsi.py --single     # одна камера
python reelsi.py --no-cut     # только субтитры
```

## Ограничения

- Проверено только на Windows 11 с видеокартой NVIDIA и приложениями Adobe.
- До конца проверен только путь After Effects; экспорт в Premiere XML и `.drp` работает, но проверен меньше.
- Экспорт в Premiere XML и DaVinci `.drp` содержит известные дефекты: [docs/KNOWN_ISSUES.md](docs/KNOWN_ISSUES.md).
- Встроенный рендер повторяет предпросмотр приблизительно: свечение, Lumetri и мозаика цензуры близки к результату After Effects, а motion blur не переносится.
- Цвет Lumetri в предпросмотре в браузере — приближение: настоящие кривые Lumetri закрыты, поэтому предпросмотр показывает направление правки, а не точный результат.
- Статус бета-версии: структуры настроек и проектов могут меняться между релизами.

## Разработка

Установите зависимости разработки и настройте git-хуки:

```bash
pip install -r requirements-dev.txt
pre-commit install
```

Запуск тестов и линтеров локально (CI выполняет те же проверки):

```bash
python -m pytest tests -q
python -m pytest tests -q -n auto --dist loadgroup -m "not perf"   # как в CI
ruff check .
mypy
```

Вторая форма — ровно то, что гоняет CI: `-n auto` (pytest-xdist) раздаёт набор по
воркерам, `--dist loadgroup` держит тесты, поднимающие настоящий Chrome
(`xdist_group("chrome")`), в одном воркере — несколько браузеров разом мерят
геометрию нестабильно, — а `-m "not perf"` не пускает тесты бюджета времени: они
меряют скорость раннера, а не код (локально идут). Два флага неразрывны: без
группы тесты с Chrome расходятся по воркерам.
