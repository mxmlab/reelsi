# Подкаст → рилсы

Длинный горизонтальный подкаст режется на N рилсов. Дальше рилс живёт как обычный
клип: встаёт в очередь шага 1, ИИ-нарезку запускает человек.

```
источник (файл | YouTube + выбор дорожки) → скачать → расшифровка (слова + тайминги)
 → ИИ: «N кусков, начало/конец» → карточка подкаста → окно правки (16:9)
 → [Перевести в рилсы] → склейки → ракурсы → лица → кто говорит → центр спикера
 → вертикальный файл рилса → запись в очередь шага 1 (одна камера, абсолютный путь)
```

## Решения владельца (2026-10-10)

| Вопрос | Решение |
|---|---|
| Где в UI | обычная карточка на шаге 1 сразу после гугл-диска; скрывается в ⚙ → «Нарезка» → «Страница нарезки», как гугл-диск |
| Источник | файл на диске ИЛИ ссылка YouTube; качать в высшем качестве; дорожка — оригинал по умолчанию, но можно выбрать автодубляж |
| Папка | у подкаста своя папка; рилсы идут в папку камеры 1 спикера, как клипы его студии; без неё — `reels/` в папке подкаста |
| «Ум» выбора кусков | шаг `podcast` в ⚙: ИИ-профиль + уровень размышлений, как у остальных шагов |
| Язык | движок расшифровки выбирается в ⚙ → «Подкаст», как движок нарезки |
| Общий план, в кадре 2+ человека | центр на ГОВОРЯЩЕГО (по голосу) |
| После перевода | рилсы встают в очередь шага 1; нарезку не запускаем |

**Рефрейм запекается в файл рилса** (по склейкам), а не через `frame` профиля
спикера: рамка профиля одна на камеру и общая для всех выпусков, а ракурсы у каждого
подкаста свои. Нарезка и сборка AE не меняются — для них рилс = клип на одну камеру.

## Данные

Папка подкаста: `<папка подкастов>/<slug>/`, где `slug` — безопасное имя из названия
(латиница/кириллица, цифры, `_`; без `\/:*?"<>|`; не длиннее 60 символов).

| Файл | Что |
|---|---|
| `podcast.json` | проект подкаста (схема ниже), пишется только `fileio.atomic_json_dump` |
| `source.<ext>` | скачанное видео (YouTube). Локальный файл НЕ копируется — путь в `source` |
| `audio16k.wav` | звук для расшифровки (16 кГц моно), пересоздаётся, если источник новее |
| `words.json` | слова расшифровки `[{"w","start","end"}]` (формат `asr_backends`), секунды от начала источника |
| `cams.json` | разбор камер источника (`core/podcast_cams.py`): склейки всего источника, ракурс каждой, уверенность и головы ракурсов (`angle_info`), головы непонятных склеек (`shot_heads`). Годен, пока не сменился источник (путь, размер, mtime) |
| `reels/<slug>_<NN>.mp4` | вертикальный рилс после перевода, `NN` = порядковый номер куска с 01 |
| `reels/<slug>_<NN>.reframe.json` | склейки, ракурсы, лица и рамка по склейкам — для отладки и повтора |

```json
{
  "v": 1,
  "title": "Название выпуска",
  "slug": "nazvanie_vypuska",
  "url": "https://youtu.be/…",          // пусто для локального файла
  "source": "C:/…/source.mkv",           // абсолютный путь видео
  "audio_track": {"format_id": "251-1", "lang": "en", "original": true},  // null у файла
  "duration": 5321.4,
  "reels_wanted": 5,
  "status": "new|downloading|downloaded|transcribing|transcribed|choosing|ready|converting|converted|error",
  "error": "",
  "asr_engine": "whisper",
  "lang": "ru",                           // язык расшифровки (определён или задан)
  "segments": [
    {"id": "a1b2c3", "start": 812.40, "end": 871.05, "title": "Про деньги",
     "why": "законченная мысль с выводом", "reel": ""}   // reel — путь mp4 после перевода
  ]
}
```

Инварианты: `0 <= start < end <= duration`; куски не пересекаются; `id` устойчив
к правке границ (правка в окне не меняет `id`); после перевода `reel` не пустой.

## Настройки (`ai_config.json`)

- шаг `podcast` в `STEP_REASONING_DEFAULT` (`"medium"`) и `STEP_TITLES` (`"Подкаст"`) —
  отсюда сами собой работают `step_profile("podcast")` / `step_reasoning("podcast")`;
- `active_podcast_asr` — движок расшифровки из каталога `asr_backends.engines()`,
  дефолт `"whisper"` (любой движок, не обязательно `cut: true`);
- `podcast_lang` — `"auto"` (дефолт) или код языка; при `auto` whisper определяет сам.

## Скачивание (YouTube)

- проверка дорожек: `python -m yt_dlp -J --no-playlist <url>` → список звуковых
  форматов: `format_id`, `language`, `abr`, признак оригинала/дубляжа. У YouTube это
  слово в `format_note` (`original` / `dubbed` / `dubbed-auto`) и `language_preference`
  (у оригинала выше). Дорожки без языка — одна группа «по умолчанию».
- видео — лучшее по высоте, затем битрейт: `-f "bv*+ba[format_id=<id>]/bv*+ba/b"`;
  склейка в `mkv` (`--merge-output-format mkv`): 4K на YouTube бывает только VP9/AV1,
  в mp4 это ломкий ремукс. Превью в браузере — через готовую дверь
  `/api/preview_proxy` (720p H.264), не исходник.
- прогресс — `--newline`, строки `[download]  12.3% of …`; таймаут простоя как у
  rclone (10 мин без вывода → снять процесс деревом).

## Выбор кусков (ИИ)

Вход модели — расшифровка фразами с метками времени `[mm:ss] текст` (фраза = слова до
паузы ≥ 0.6 с или до конца предложения). Ответ — JSON
`{"segments":[{"start":сек,"end":сек,"title":"…","why":"…"}]}`, ровно N кусков
(больше — берём первые N по порядку ответа, меньше — сколько есть + предупреждение).
Длина куска по умолчанию 30–90 с (в промпте). Код после ответа:
1. границы прилипают к словам: `start` → начало ближайшего слова, `end` → конец слова,
   за которым пауза (не режем посреди фразы), окно поиска ±3 с;
2. пересечения — второй кусок начинается после первого; вырожденные (< 5 с) — выкидываются;
3. сортировка по `start`.

Длинный подкаст, не влезающий в контекст модели шага (оценка: символы / 3 больше
`ctx_limit` из каталога): v1 честно отказывает с подсказкой выбрать модель с большим
контекстом. Окна с нахлёстом — только если упрёмся на деле.

## Перевод в рилсы (на кусок)

Владелец 2026-10-10: «у нас есть трекинг и рото — трекинг отслеживает, где человек в
камере, а код ставит его по центру». Лица ищет НАШ трекинг (`core/headtrack.py`, маска
RVM), отдельный детектор лиц не нужен.

1. **Склейки** — `ffmpeg -i src -vf "select='gt(scene,0.1)',showinfo" -f null -` по ВСЕМУ
   источнику, один раз (в разборе камер): времена `pts_time`; склейка короче 0.4 с сливается
   с соседней. Кусок берёт склейки, обрезанные по своим границам.
2. **Разбор камер** — `cams.json` (см. «Данные»): один раз на источник, под общим локом сразу
   после расшифровки. «Продолжить» и перевод досчитывают его, если файла нет или он не годен
   (сменился путь, размер или mtime источника). Миниатюры середин склеек 64×36 серым → ракурсы
   (средний модуль разности < 18 — один ракурс) → переназначение: каждая склейка уходит к ракурсу
   с БЛИЖАЙШЕЙ опорой (опора — медоид ракурса), два круга. Замер владельца 2026-10-11: общий план
   прилипал к ракурсу гостя (17.7 при пороге 18, к своему ракурсу — 7.7); ближайшая опора это лечит.
3. **Уверенные и непонятные ракурсы** — ракурс уверенный, если в нём 3 склейки и 20 с и больше.
   Выборка — три его склейки: первая, средняя и последняя по порядку; участок 1 с вокруг середины
   склейки, обрезанный внутрь на 0.05 с. Головы участка — модальное число голов по его точкам
   (точки без голов не считаются), позиции — медианы `hx` и `top` по точкам с этим числом.
   Выборки согласны, если число голов одинаково и разброс `hx` каждой головы ≤ 0.05: тогда ракурс
   уверенный, его головы — медианы выборок (`angle_info`). Непонятные — мелкий ракурс или выборки
   разошлись: для них RVM идёт по каждой их склейке (`shot_heads`).
   RVM — не больше двух вызовов `headtrack.track` (5 к/с, `heads=True`) на весь источник: первый —
   на выборки уверенных ракурсов (три уверенных ракурса — девять участков), второй — на непонятные
   склейки. Непонятных нет — второго вызова нет.
   Головы склейки для рамки: `shot_heads[i]`, если склейка непонятная, иначе головы её ракурса.
   Перевод кусков RVM не вызывает.
   Головы в точках (`[[hx, top], …]`) — из профиля верхней кромки маски: для каждого столбца самая
   верхняя строка маски, сглаживание, локальные вершины («макушки») с разносом ≥ 8 % ширины и
   выступом ≥ 4 % высоты. Две сидящие рядом фигуры часто сливаются в одно пятно маски — поэтому
   вершины профиля, а не компоненты связности.
4. **Кто говорит** (ракурс с 2+ головами) — по движению рта: кадры 10 к/с, на голову
   окно ниже макушки (высота ≈ ширина головы), считаем разность кадров в нижней половине
   окна минус в верхней; говорит голова с максимумом в окне 1 с. Без речи в окне (по
   словам) или перевес < 15 % — прежний говорящий; смена не чаще раза в 1.5 с.
5. **Рамка** — кусочно-постоянная: окно 9:16 во всю высоту, центр X = голова
   (одна голова — её медиана; несколько — говорящего), упор в края кадра. Смена
   говорящего внутри общего плана — жёсткий переход (как монтажная склейка), без
   панорамы.
6. **Файл** — один проход ffmpeg: `-ss a -to b -i src`, `crop=w=CW:h=ih:x=X0` +
   `sendcmd` (файл команд `t crop x X;` на каждой смене), `scale=1080:1920:flags=lanczos`,
   видеокодек `encoders.pick("master")` + `codec_args`, звук — AAC 320k (opus из mkv
   Premiere не берёт). Выход `reels/<slug>_<NN>.mp4`, рядом `.reframe.json`
   (склейки, ракурсы, головы, говорящие, рамки).
7. **Очередь** — запись в очередь шага 1 как одна камера с АБСОЛЮТНЫМ путём;
   `build_pairs` склеивает `os.path.join(camdir, abs)` в сам `abs`, так что запись
   живёт при любом переключателе камер. Очередь из двухкамерных пар и однокамерного
   рилса обязана резаться одним прогоном. Нарезку НЕ запускаем.

## Задания и блокировки

- скачивание — свой джоб (как `GDJOB`), JOB нарезки не занимает;
- расшифровка, разбор камер и перевод в рилсы — GPU/тяжёлое: под общим межпроцессным локом
  (`_cross_lock_acquire`), как предпросмотр рото;
- ИИ-выбор — без GPU-лока (облако), но с отменой через `aicut.cancel_call`.

## Что сделано

- **Проект и скачивание.** Проект подкаста, дорожки YouTube (оригинал или автодубляж), скачивание
  с прогрессом и сторожем простоя; локальный файл берётся по пути, без копии.
- **Расшифровка и выбор кусков.** Расшифровка через `asr_backends`, фразы с метками, ИИ выбирает N
  кусков, границы прилипают к словам, пересечения и вырожденные куски убираются.
- **Джоб и отмена.** Роуты и джоб `PDJOB`, статус в `podcast.json` (продолжение после перезапуска),
  отмена, общий лок для тяжёлых шагов.
- **Блок на шаге 1.** Обычная карточка под гугл-диском, скрывается в ⚙ → «Нарезка» → «Страница
  нарезки». Строки подкастов: правка (карандаш), повтор, мусорка. «Все рилсы в очередь» — один джоб
  по всем подкастам папки. «Подкаст» в ⚙: профиль ИИ, уровень размышлений, движок, язык.
- **Окно правки кусков (16:9).** Видео (прокси 720p в общей строке прогресса), список кусков и
  таймлайн «Вся запись» — волна, слова баблами, зум, протяжка. Правка: C/S режут, D/Delete/Backspace
  удаляют, I/O ставят края на плейхед, двойной клик — новый кусок. Отмена и повтор, автосохранение,
  выбор нескольких кусков. Таймлайн — тот же, что у шага 1 и вставок (см. `docs/ARCHITECTURE.md`).
- **Разбор камер один раз на источник.** Склейки по всему источнику, ракурсы по миниатюрам, `cams.json`.
  RVM вызывается по выборке уверенных ракурсов и по непонятным склейкам, перевод кусков RVM не трогает.
  Головы берутся из верхних макушек профиля маски, допуск по ширине окна.
- **Говорящий.** По движению рта на каждом ракурсе с двумя и более головами; на общем плане — лицо
  в полном разрешении и окно по ширине головы из маски.
- **Перевод в рилсы.** Файл 1080×1920 (H.264 мастер-профиль, AAC 320k), `.reframe.json` рядом для
  отладки. Рилс встаёт в очередь шага 1 одной камерой с абсолютным путём; нарезку ИИ не запускаем.
- **Папка рилсов.** Папка камеры 1 спикера; без неё — `reels/` в папке подкаста, в ответе
  `fallback: true`.
- **Корзина.** Удаление подкаста — в `<папка подкастов>/_reelsi_trash/` с `trash.json` (`kind:
  "podcast"`), возврат на место, очистка насовсем в ⚙ → «Нарезка». Внешний исходник уходит с галкой
  «И исходники», если его не держит другой подкаст этой папки. Рилсы в очереди из папки подкаста
  уходят из очереди вместе с ним, с предупреждением.

Замеры, на которые опирается решение (живые прогоны владельца): весь выпуск — 4 уверенных ракурса,
RVM 169 кадров вместо 1374 при разборе по выборке; говорящий по рту и запекание — 62 с → 27 с;
два рилса из выпуска — 45 с, смена ракурса гость/ведущий; общий план длиной 2:18 распознан верно.

## Что открыто

- Общий план, где говорят двое сразу (смех): говорящий выбирается неоднозначно.
- Общий исходник ищется только среди клипов той же папки XML (см. `docs/KNOWN_ISSUES.md`).
- Старые записи корзины подкастов без `trash.json` не показываются.
- Перевод длинного подкаста, не влезающего в контекст модели, отказывается с подсказкой; окон с
  нахлёстом нет, пока на деле не упрёмся.
- ИИ-нарезка рилсов не запускается сама: это решение владельца, а не недоделка.
