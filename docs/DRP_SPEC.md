# Экспорт в DaVinci Resolve — формат `.drp`

Статус: генерация `.drp` с нуля работает — камеры, нарезка, синхрон, вставки,
титры, UI. Разобрано на DaVinci Resolve Studio 21.0.3.

## Зачем вообще `.drp`

Графику (титры) **невозможно** передать ни одним обменным форматом. Это не пробел
реализации, а устройство форматов: они стандартизируют монтаж, а не отрисовку.

| формат | текст титров |
|---|---|
| FCP7 XML (`xmeml`) — то, что мы отдаём | **нет** |
| FCPXML (Final Cut X) | нет — «титры в проприетарном формате Final Cut» |
| AAF, EDL, ADL, OTIO | нет |
| `.srt` / `.vtt` / `.ttml` | да, но это дорожка субтитров, не графика |
| `.drp` / `.drt` — родной формат Resolve | **да** |

Проверено экспериментально, а не вычитано: пользователь сделал титр Fusion в
Resolve и экспортировал в FCP7 XML — на месте титра оказался пустой `Slug`,
во всём файле ноль вхождений `Text`, `font`, `color` и ни одной кириллической
буквы. Resolve не переносит через этот формат даже собственный титр.

У Premiere текст титра лежит в проприетарном FlatBuffer-блобе (668 символов
base64 на слово, см. `data/sub_template.xml`) — читать его умеет только Premiere.
Оба редактора спрятали текст в своё, потому что общего места для него нет.

## Формат `.drp` — разобран полностью

Снято с экспорта **DaVinci Resolve Studio 21.0.3.0007**. Формат приватный и
недокументированный: при смене версии Resolve сверять заново.

```
.drp                                ZIP
 ├ project.xml
 ├ MediaPool/Master/MpFolder.xml    записи медиапула
 ├ SeqContainer/<uuid>.xml          таймлайн: треки, клипы, тайминги
 └ Gallery.xml
```

### Таймлайн

Обычный XML. Дорожка = `<Sm2TiTrack>`, клип = `<Sm2TiVideoClip DbId="…">`.
Значимые поля клипа: `Name`, `Start`, `Duration`, `In`, `MediaFilePath`,
`MediaRef` (→ `DbId` записи медиапула), `MediaTimemapBA`.

`MediaTimemapBA` = `02` + 8 байт big-endian double = **длительность в секундах**
(кадры / 60). Перекодировка сверена байт в байт.

### Титр Fusion — самодостаточен

У клипа-титра `PrettyType` = `Fusion Composition`, нет `MediaFilePath` и нет
`MediaRef`. Всё содержимое — в `<CompositionBA>`:

```
<CompositionBA>  hex
 └ uint32 BE (длина распакованного) + zlib
    └ бинарный контейнер: ключи UTF-16BE с 4-байтовым префиксом длины
       ключ "0_data": [4 байта тип][1 байт][4 байта BE ДЛИНА ДАННЫХ][данные]
       данные = текст композиции … "Compressed = true, }\0"
                + uint32 LE (длина) + zlib(граф нодов)
```

**Поле «длина данных» — главная ловушка.** Первая попытка правки дала чёрный
слой именно потому, что размер данных изменился, а поле осталось старым. Проверять
себя тождественной перепаковкой: разобрать и собрать без правок → распакованные
байты обязаны совпасть побайтово. Без этой проверки ошибка не видна.

Граф нодов — обычный текст Fusion:

```lua
{ Text1 = TextPlus { Inputs = {
     Width = Input { Value = 1080 }, Height = Input { Value = 1920 },
     StyledText = Input { Value = "СЛОВО" },
     Font = Input { Value = "Open Sans" }, Style = Input { Value = "Bold" },
     Size = Input { Value = 0.0729 },
     Red1 = …, Green1 = …, Blue1 = …,
     Center = Input { Value = { 0.5, 0.4036 } },
     VerticalJustificationNew = Input { Value = 3 },
     HorizontalJustificationNew = Input { Value = 3 } } },
  MediaOut1 = MediaOut { Inputs = { Input = Input { SourceOp = "Text1", Source = "Output" } } } }
```

Fusion **не сериализует значения по умолчанию** — если ставим цвет или кегль,
входы нужно добавлять, а не только заменять. Отсчёт Y снизу вверх: якорь строки
из `docs/HIGHLIGHT_SPEC.md` (`Y = 0.5964·H` сверху) даёт `Center.y = 1 − 0.5964`.

### Медиапул — разобран и пишется

Запись = `<Sm2MpVideoClip DbId="…">`, на её `DbId` ссылается `MediaRef` клипа
таймлайна. Её `FieldsBlob`:

```
[4 байта][4 байта = длина − 8][1 байт маркера] + zstd   (магия zstd с 9-го байта)
 └ protobuf-обёртка (поле 1 → поле 1 → поле 5)
    └ контейнер ключей UTF-16BE, как в композиции:
       [4 длина имени][имя][4 тип][1 флаг][4 длина][данные]

       Type          тип 3   int32
       MediaExtents  тип 12  16 байт = два double LE
       CodecName     тип 10  строка
       ChannelVecBA  тип 12  вложенный контейнер (каналы звука)
       MediaRef      тип 10  GUID
       BitDepth      тип 3
```

**`MediaExtents` = [стартовый таймкод в секундах, длительность в секундах].**
У `C1412.MP4` там 7051.344 — это ровно drop-frame таймкод `01;57;31;11`.
То есть та же величина, из-за которой ехали тайминги в XML: источник данных для
обоих форматов один, `xmlbuild.probe()`.

Проверено на живом Resolve:

- **Блоб обязателен.** Стереть `FieldsBlob` — проект не импортируется вовсе,
  таймлайна нет. Надежда, что Resolve переспросит файлы сам, не оправдалась.
- **Перепаковка zstd безопасна.** Разжать и сжать заново (уровень 19) — проект
  открывается, медиа онлайн, титры целы. Значит поток zstd обычный, без словаря.
- **Resolve читает длительность из блоба, а не из файла.** Проект,
  перенацеленный с `C1412.MP4` (163 с) на `C1413.MP4` (204 с), показывает 204 с —
  значит `MediaExtents` надо считать честно.
- **Патчить прицельно.** `MediaExtents` есть и у второй камеры, и у самого
  таймлайна: правка «всех блобов разом» ломает соседей. Искать нужную запись по
  `DbId` / `Name`.

Нужен `zstd`: в stdlib он с Python 3.14, у нас 3.10 → пакет `zstandard`.

### Запись медиапула — это ПОЛНЫЙ ДЕСКРИПТОР, а не ссылка

Самое дорогое открытие. Кроме `FieldsBlob` в записи ещё пять вложенных блобов, и
все описывают конкретный файл:

| блоб | что несёт | как править |
|---|---|---|
| `<Clip>` ×2 | путь, имя, mtime, кодек — отдельно видео и звук | protobuf, длины пересчитываются |
| `<Time>` | `Timecode`, `NumFrames`, `FrameRate` | на месте |
| `<Geometry>` | `Resolution` | на месте |
| `<TracksBA>` | `StartTime`, `Duration` (в сэмплах), `SampleRate`, `NumChannels` | на месте |
| `FieldsBlob` | `MediaExtents`, `CodecName`, `MediaRef` | на месте |

Клонировать запись и поправить только `MediaExtents` НЕДОСТАТОЧНО: внутри
останется файл шаблона, и Resolve сочтёт две камеры одним медиа — первая уходит
в офлайн, вторая показывает застывший кадр.

Почти всё фиксированного размера, потому что таймкод всегда `HH:MM:SS:FF` (11
символов), а числа — 4 или 8 байт. Переменная длина только у путей в `<Clip>`.

Контейнер ключей: `[4 длина имени][имя UTF-16BE][4 тип][1 флаг][значение]`.
У типов 10 (строка) и 12 (блок) перед значением ещё 4 байта длины. **Байт-флаг
после типа легко проглядеть** — без него все скаляры читаются со сдвигом на байт.

### Идентификаторы: одна таблица на всю запись

Блобы ССЫЛАЮТСЯ на элементы XML. Ключ `MediaRef` в `FieldsBlob` — это `DbId`
элемента `<BtAudioInfo>`, то есть звук записи. Поэтому при клонировании нельзя
генерировать идентификаторы порознь в XML и в блобах: нужна ОДНА таблица
старый → новый, применяемая везде. Иначе ссылка рвётся.

Симптомы, которые это давало (ловилось в три захода, каждый раз чинилось только
то место, куда смотрели):

- `DbId` совпал → первая камера офлайн, вторая с застывшим кадром;
- `UniqueMediaPoolItemId` совпал → то же самое;
- `MediaRef` разошёлся с `BtAudioInfo` → клипы зелёные, но **без волны и без звука**.

### Клип таймлайна: две ловушки

**`MediaTimemapBA` у медиаклипа — не длительность клипа.** Это карта ИСХОДНИКА,
пять doubles `[L, 0, L+1/60, 0, L]`, где `L = (кадров−1)/30`, одинаковая у всех
клипов одной камеры. Длительность клипа (один double) — только у титров Fusion.
Перепутать = застывшая картинка. Третий double считать как `(2·кадров−1)/60`:
`L + 1/60` даёт другой последний бит мантиссы.

**`MediaStartTime` и `MediaExtents[0]` — одна величина в разных единицах.**
У клипа кадры делятся на номинальные 30, у медиапула — на реальные 29.97.
Для `01;57;31;11` это 7044.3 против 7051.3443, расхождение семь секунд.

**`Flags=2` — клип выключен.** Так хранится раскладка мультикама: камера 1 всегда
видна, камера k>0 — только на своих кусках. Аналог `<enabled>` из XML.

## Что сделано

Пословные титры собираются и работают: 195 штук на реальном ролике, тайминги и
жёлтые взяты из нашего XML (`parse_full` + `auto_highlights`), жёлтый
`[1, 0.9176, 0]` и ужатие длинных слов (порог 14 символов) — как в Premiere.
Проверено пользователем в Resolve.

Не перенесено, требует уточнения по эталону:

- **шрифт** — в AE это PostScript-имя `SFPro-CondensedSemibold`, Fusion хочет
  семейство + начертание отдельно. Оставлен `Open Sans Bold` из шаблона;
- **кегль** `0.0729` (140 px ÷ 1920) и **позиция** `{0.5, 0.4036}` — пересчёт, а
  не перенос: у Fusion `Size` относительный и его связь с высотой кадра не
  проверена.

Способ уточнить любой из них — тот же, что решил всю эту задачу: попросить
поправить один титр в Resolve, экспортировать `.drp` и снять точные числа.

## Раскладка треков в экспорте

Совпадает с конвенцией, которую уже ждёт `parse_full` (`core/xml2ae/parse.py`), — снизу вверх:

```
V1..Vn   камеры 1..N
V(n+1)   вставки ФОТО
V(n+2)   вставки ВИДЕО
         дорожка субтитров — ищется по содержимому, где угодно
```

Одинаково для XML и для `.drp`.

**Вставки в XML не попадают** — это ловушка. Список вставок живёт в localStorage
фронта (`c.inserts`: `start_sec`, `duration_sec`, `type`, `media`) и уходит на
бэкенд только при сборке `.jsx`. Ни в одном рабочем XML вставок нет. Для экспорта
брать их оттуда же, откуда их берёт сборка AE, а не из XML.

## Что где скачивается

| страница | XML | `.drp` |
|---|---|---|
| 1 — нарезка | да, **только он** | нет |
| 2 — разметка | да | да, со вставками и субтитрами |

На первой странице выбора формата нет намеренно: там ещё нет ни вставок, ни
титров, а XML открывается и в Premiere, и в Resolve.

## Риск, который надо держать в голове

Формат приватный. Blackmagic может поменять его в любом обновлении и предупреждать
не станет. Всё, что здесь описано, снято с 21.0.3 и подлежит перепроверке при
смене версии. Это цена за единственный формат, который несёт графику.
